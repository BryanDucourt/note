# 本周计划
## BEHAVIOR-1K 披萨场景：长程上下文分析

### 研究问题

**在有限上下文预算下，哪些历史信息能够支持当前及后续任务决策？如何围绕这些用途组织、检索和压缩历史？**

这里的历史上下文包括当前任务内已经获得的观测、动作及其反馈。任务指令与当前观测始终保留，信息价值通过决策质量和重新获取信息的成本衡量。

1. **必要性：没有历史，会损失什么？**
   - 哪些节点仅凭当前观测即可正确决策？
   - 哪些节点需要重新观察、搜索或尝试？
   - 哪些关键信息在后续环境中难以再次获得？
2. **作用机制：历史补上了什么判断依据？**
   - 当前还有哪些条件待确定？这些条件影响哪些行动分支？
   - 单条事实是否足够，还是需要组合实例、数量、加工状态和转移结果等证据？
3. **保留范围：这些信息后续还会在哪里使用？**
   - 哪些细节需要继续保留，哪些可以合并为状态摘要？
   - 什么事件会改变信息的有效性？什么时候可以退出活跃上下文？

### 核心 insight（工作假设）

> **历史信息的价值取决于它支持什么任务判断、需要与哪些证据组合、未来还会在哪里使用，以及之后能否重新获得。**

据此，将研究重点放在两个相互衔接的机制上：
- **证据组合：**围绕当前待决条件，选择能够共同支持判断的历史片段。
- **信息生命周期：**围绕剩余任务用途，调整信息的保留时间和表示粒度。

下面的情境用于提出假设，实际决策点以示范中的可见证据为依据。

### 四个可检验的研究设想

#### 1. 待决条件驱动的证据组检索【优先主线】

**假设：**涉及多个实例、数量、加工和转移的判断，存在证据互补性。在相同上下文预算下，按整组证据对待决条件的支持程度进行选择，可以降低条件遗漏和任务判断错误。

例如，“蘑菇是否准备齐”可能同时需要：两个不同实例均已加工、加工结果符合要求、材料已完成转移，以及后续数量或位置变化的证据。

**机制：**当前子目标 → 待决条件 → 候选召回 → 证据组选择 → 判断与行动。
- 待决条件从任务指令、当前子目标和当时可见信息中生成。
- 召回层可沿用 BM25、BGE-M3；重排层评价证据组的条件覆盖、互补性、时效性和成本。
- 以“预计减少的决策错误 − 获取与使用成本”为选择目标；待决条件得到充分支持时停止扩展。

**关键观察：**组合证据问题上的收益应高于单条位置事实即可解决的问题。对照独立片段 Top-K、依赖扩展检索与证据组选择，固定候选库和 token 预算，分别记录条件判断与后续任务推进。

**研究切口：**估计多条证据的联合价值，在预算内选择足以区分行动分支的证据组合。

#### 2. 面向剩余任务的信息生命周期与压缩【第二主线】

**假设：**信息的保留价值随剩余任务变化。依据后续用途调整表示粒度，可以兼顾上下文成本与后续决策质量。

例如，取奶酪时暂时用不到蘑菇处理记录，后续判断配料齐备时可能再次需要这些记录。

| 阶段 | 可能需要保留的信息 |
| --- | --- |
| 两个蘑菇处理进度不同 | 各自的实例、加工状态和位置 |
| 加工完成，转移尚待确认 | 来源数量、加工结果和待确认的转移关系 |
| 已确认进入同一容器，剩余目标允许互换使用 | 批次级数量、状态、容器及来源证据索引 |
| 后续装配完成 | 装配结果，以及剩余目标和恢复分支需要的信息 |

**机制：**维护信息与未完成目标、可预见恢复分支的关系，据此执行展开、合并、归档和重新取证。剩余用途依据当时任务进度估计。

**关键观察：**压缩效果需要覆盖后续多个决策点，关注提前删除引起的遗漏、重复与恢复成本，以及适时合并节省的上下文。分别记录活跃上下文、归档存储和再次检索成本。

**研究切口：**在什么条件下，实例级历史可以合并为更粗粒度的任务状态，同时保留剩余任务需要的区分能力？

#### 3. 动作影响驱动的上下文失效与局部修订【可靠性机制】

**假设：**依据相关事件局部修订事实及其派生判断，可以减少旧状态引起的决策错误，并保留仍然有效的信息。

例如，观察到部分配料被倒出后，需要更新容器内数量，并重新判断“配料齐备”；已经确认的加工状态可以继续保留。

**机制：**新事件 → 受影响属性和关系 → 依赖判断的局部修订。动作结果待确认时，相关状态标为待确认。

**关键观察：**在相近时间间隔下，分别分析相关状态变化和无关操作，记录旧状态错误、误撤销比例与更新成本。优先作为前两条主线的可靠性机制。

#### 4. 面向未来信息丢失的主动取证【后续扩展】

**假设：**在混合、转移等可能降低信息可恢复性的动作前，进行针对性观察并保存证据，可以减少后续状态歧义和重复检查。

**机制：**结合后续用途、动作后的信息可恢复性及当前观察成本，选择直接执行或先取证再执行。动作前确认与动作后结果分别记录。

**关键观察：**在相同观察预算或总执行成本下，比较后续状态歧义、重新检查次数、恢复成本和任务完成情况。

### 本周工作：先建立证据组合与后续用途的案例

**本周目标：形成一条可分析的披萨任务过程，识别组合证据是否带来收益，以及相关信息在后续何时再次被使用。**

#### 1. 获取并整理一条官方示范
- 使用官方任务描述、分段标注、episode 索引和对应视频；对象状态疑问按需借助原始 HDF5 回放。
- 对齐观测、动作、反馈、实例及帧段，明确每个决策点之前已经可获得的信息。
- 数据入口：[官方数据说明](https://behavior.stanford.edu/challenge/dataset.html)、[披萨示范标注示例](https://huggingface.co/datasets/behavior-1k/2026-challenge-demos/blob/main/annotations/task-0049/episode_00490010.json)。

#### 2. 围绕三类候选节点制作证据卡
- 工具位置：寻找单条事实即可支持判断的参照节点。
- 多次加工与转移：寻找需要组合实例、状态和结果的节点。
- 混合后来源或数量：寻找信息后续用途及可恢复性变化的节点。

每张证据卡记录：**当前决策与待决条件、当前可见信息、历史证据及出处、证据之间的关系、后续用途、更新或失效事件。**

#### 3. 形成最小诊断材料
- 比较当前观测、独立片段检索结果和人工精选证据组，统一任务指令与观测范围。
- 独立片段与证据组使用相同 token 预算；通过缺失某个条件的证据组合观察互补性。
- 人工精选证据作为信息供给的诊断参照，算法选择能力通过后续检索对照评价。
- 模型输入限定为决策前可获得的信息；隐藏状态用于分析与评分。
- 记录条件判断正确性、证据成本和后续任务推进；后续推进证据通过可运行环境中的执行获得。

**本周产出：**一条对齐的任务过程、三类候选节点的证据卡，以及关于“哪些判断需要证据组合、哪些区分需要继续保留”的初步结论与待解决问题。
