## 二、加四个工具

| 工具 | 参数 | 做什么 |
|---|---|---|
| open | evidence_ref, point_xy | 打开图上这个点指到的柜门、抽屉、冰箱等 |
| close | evidence_ref, point_xy | 关上图上这个点指到的东西 |
| pick_up | evidence_ref, point_xy | 拿起图上这个点指到的物体，手里一次只能拿一个 |
| put | evidence_ref, point_xy | 把手里的物体放进或放到图上这个点指到的容器或台面 |

- evidence_ref 必须是最新一次观测的头部图，point_xy 是图上的归一化坐标，和 move_to_point 的用法一样。
- 程序负责把图上的点换成物体，再用 THOR 自带的交互动作去执行。物体 ID、类别、距离这类仿真信息只能在程序内部用、写进评估档案，不能进规划器的输入，返回的文字里也不能出现仿真里的物体名或 ID。
- 返回的内容：成功还是失败；失败的原因，按 THOR 的报错归类（够不着、点上没有能操作的物体、手里已经有东西、手里没有东西、容器是关着的等）；动作之后新拍的头部图。
- 新工具只在一个新的 THOR 平台配置里打开，现有配置保持不变。工具表照 v2 的格式写（arguments、limits、effect、returns）。新配置的本体段里，"You have no arms in this task." 要换成一句说明语义操作的话，你拟好写进报告。

## 三、验证（不调用规划器）

- 写脚本，在 2～3 个 iTHOR 厨房里各做一遍：打开冰箱或抽屉，拿起一个物体，放进容器或放到台面上，再关上。另外故意做几次会失败的操作：离得太远、点在墙上、手里有东西还去拿。
- 每次都记下：动作前后的图、程序换出来的物体、THOR 返回的成功或报错、返回给规划器的文字。
- 用 THOR 的元数据离线核对两件事：按图上的点指到的物体是不是想指的那个，统计准确率；动作之后物体的状态对不对（开没开、在不在手里、在哪个容器里）。元数据只用于这份核对。
