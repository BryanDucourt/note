# 具身上下文文献整理（1022）

**依据**：Zotero“研究方向 → 具身智能与机器人”分类，共 102 篇。分类依据是摘要；11 篇没有摘要的看了首页，其中 GEN-1.5 和 S1 只有博客网页。没有精读全文。

**范围**：去掉与上下文无关的 15 篇（名单见文末），余下 87 篇与上下文、记忆、历史直接相关。

## 一句话

绝大多数论文的出发点是同一个：机器人策略只看当前画面，而任务需要过去的信息，比如物体被手挡住、要数做了几遍、要知道做到哪一步。所以大家都在“加记忆”，分歧在于各自认为卡在哪里。最近半年有一个明显转向：从“记得更多”，转到“当前决策需要什么，就记什么、取什么”；同时出现了专门检验“记忆有没有真正影响决策”的审计研究。

## 一、五类出发点

| 出发点 | 篇数 | 典型说法 |
|---|---|---|
| ① 当前画面不够，要给底层策略加历史 | 29 | “VLA 是马尔可夫的，任务不是” |
| ② 长期运行的智能体没有持久记忆 | 22 | “部署几天几周，上下文窗口装不下” |
| ③ 记了也没用对 | 11 | “记忆和当前决策对不上” |

| ⑤ 从自己的经验里改进 | 10 | “不改权重，靠积累的交互现场适应” |

### ① 给底层策略加历史（29 篇）

都在 VLA、扩散策略或世界动作模型（WAM）上加历史，分歧在于认为瓶颈在哪：

| 认为的瓶颈 | 做法 | 论文 |
|---|---|---|
| 太贵：历史一长，计算和延迟扛不住 | 压缩，例如每帧压成一个 token | ContextVLA、NativeMEM、DySta、AEM、MemoryWAM、Memo、Compressing History into Memory、MaP-WAM |
| 学偏：训练时抓住历史里的偶然特征 | 只给关键帧、辅助任务、稀疏注意力 | BPP、PTP、HALO、MemER |
| 挑不准：只有少数时刻要紧 | 关键帧、事件检测 | KEMO、EventVLA、KC-VLA、TTC-Memory、CycleManip |
| 一种记忆不够 | 短期视频加长期文字，多层多类 | MEM、MemoryVLA、MemoryVLA++、HiMe、DIM-WAM、SAM2Act、Embodied-SlotSSM |
| 最小结构够不够 | 可学习的循环记忆 token | μVLA、ReMem-VLA、HAMLET |
| 世界模型生成时前后不一致 | 带记忆的世界模型 | WorldMem、Mem-World |

- 这一类最拥挤，2026 年 6 月一个月就有约 10 篇。
- 几乎都要训练模型。
- 关于“学偏”有反方证据：MXQ9Z49E（Training and Evaluating Diffusion Policies with Long Context Lengths）实测直接加长上下文没有文献说的那么脆弱。

### ② 长期运行的智能体（22 篇）

在大模型规划、具身问答（EQA）、导航层面，用外部结构化记忆，例如场景图、3D 快照、知识图谱。常用“仿脑”的说法。

| 子问题 | 论文 |
|---|---|
| 时间一长，检索要快、要准 | ReMEmbR、STaR、3DLLM-Mem、LTE |
| 世界会变，旧记忆过时 | HitMem、WorldLines |
| 存进去的描述本身不可靠 | UQ-DAAAM |
| 记忆要指导探索，不只用来答题 | MemoryEQA、Mind Palace、3D-Mem、HIMM |
| 记什么：只记意外 | Worth Remembering |
| 分层、多类记忆的智能体系统 | KARMA、RoboMemory、LongAct（HoloMind）、ABot-AgentOS、OmniAct |
| 导航和视频流的上下文压缩 | StreamVLN、VLN 历史 token 剪枝、AstraNav-Memory、StreamMeCo |
| 多机器人共享记忆 | ECI（When Multi-Robot Systems Meet Agentic AI） |

### ③ 记了也没用对（11 篇）

共同论点：有用的不是原样保留的画面，而是从交互中提炼、和当前决策相关的状态。

| 论文 | 说的问题 |
|---|---|
| MemCompiler | 开局一次性注入记忆，很快和智能体的状态脱节，甚至不如不给 |
| MemPrism | 信息在，但没按当前决策需要的结构组织 |
| Mimir | 平铺的历史不告诉你哪些事实支撑当前目标；把世界记忆和任务记忆分开，行动前再绑定 |
| SimpleARM | 按任务指定要监控的几类状态（关系、指代、进度、路线），只在子目标依赖历史时取用 |
| AGM | 把“尝试过”记成“完成了”，执行错误会变成持久的状态错误；只在有物理证据时推进进度 |
| DSSR | 损失几乎全来自“写的时候没留下”，事实要带得越久，损失越大；提示词写出的摘要远不如带命名字段的状态 |
| COMPACT-VA | 压缩要和规划意图对齐（自动驾驶） |
| MeMento | 按用户偏好压缩长历史 |
| HiAgent | 按子目标管理工作记忆 |
| Value-Directed Compression of POMDPs（2002）、Bounded Finite State Controllers（2003） | 经典理论：压缩信念状态时保住决策价值 |

8 篇发表于 2026 年 5–9 月，是最新的一类。

### ⑤ 从自己的经验里改进（10 篇）

| 做法 | 论文 |
|---|---|
| 不改权重，把交互经验当上下文 | Zeva、WAM-TTT、Harness VLA、EmbodiSkill、REFLECT、BrainMem |
| 大规模预训练后的上下文学习（公司） | GEN-1.5、S1 |

## 二、两条横向线索

和“把信息当资源调度”的总故事最相关，散在各类里：

- **上下文有成本**
  - BRACE：重规划的上下文越积越长，平均延迟看不出问题，尾部延迟会超时；它给每次重规划分配 token 和延迟预算。
  - HiMe：慢思考和实时控制之间的冲突。
  - OmniAct：上下文增长要压到亚线性。
  - MemCompiler：每步延迟降低 60%。
- **回忆还是重新去看**
  - Mind Palace：用信息价值决定何时停止探索、何时查记忆。
  - UQ-DAAAM：固定查询预算下，重看不确定的物体。
  - InfoSeeker：先主动收集信息，验证对环境的理解，再规划。
  - 3D-Mem：把未探索区域的“前沿快照”和已知记忆放在一起决策。

从摘要看，还没有哪篇把“物理动作的先后顺序”和“存储、检索、重看这些信息操作”放进同一个预算里一起安排。

## 三、对我们现有实验的启示

| 启示 | 来源 | 状态 |
|---|---|---|
| 错误按“信息空窗”分档：关键事实已经多久确实没出现在画面里。空窗为 0 时判错是感知或判断问题，空窗越长越可能是记忆问题 | MIKASA-Robo-VLA、DSSR | 已并入 1020 任务说明 D1 |
| 取证加“独有性”指标：选出的旧图有没有当前画面看不到的东西；空窗为 0 的题当对照 | Present but Not Remembered | 已并入 1020 任务说明 D4 |
| G2（任务状态表）应胜过 G1（通用递归摘要），空窗越长差距越大 | DSSR | 预测，待 10-19 实验检验 |
| SimpleARM 的形态接近 G2、G3，必须引用并写清差异；它的“按机制消融”可借给 D3 | SimpleARM | 待精读 |
| “按当前判断取证”作为方法已很挤，贡献要落在测量上 | MemCompiler、MemPrism、STaR、MemoryEQA、HALO | 与 1020 笔记一致 |
| 做“必须靠记忆”的变体时，先跑不给记忆的对照 | NoSense | 以后做变体时用 |
| grouped-assembly 补“看证据再行动”的候选：信息够了就停、不确定才重看、意外才记、核实后才推进 | Mind Palace、UQ-DAAAM、Worth Remembering、AGM | 未采纳 |
| 用“预算损失 + 写入遗憾”拆解记忆预算的影响 | DSSR | 未采纳 |
| 汇总时报尾部延迟（p95）和单轮内上下文增长曲线 | BRACE | 未采纳 |
