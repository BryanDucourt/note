# 上下文骨架会审：GPT 第一轮原文（1028）

---

最大问题是：**任务状态、规划意图、感知判定和几何换算混在同一接口里，产生的错误又靠追加提示纠正。** 优先明确各字段的含义和责任，再压缩长度。现有结果不支持一次删掉八成输入。

1. 系统提示保留四段，按以下顺序组织。

- **职责与权限**：每次选一个工具；当前目标和阶段由程序指定；G2 触发程序换阶段；finish 不可用。
- **证据规则**：当前观察、历史记录、执行反馈、规划假设分开；未评估与未发现分开；同一原图的多份描述算同源证据；不引入仿真真值。
- **决策原则**：目标已定位时优先恢复目标视图；未定位时结合任务相关性、历史目击、未解决区域和行动成本；重复观察没有新增证据时调整策略。
- **输出契约**：字段、顺序及工具参数约束。

保留 G1/G2 定义、scan 的采样与最终视图区别、历史路线需要重新观察确认。工具详情只在工具表出现一次。

删除机械臂/VLA说明、刀任务残留、硬编码阶段预算、逐字段填表教程。把“门洞”“前景家具变大”等补丁收敛成一条：**位置、房间类型和行动进展必须有对应证据，规划预期不得写成观察结果。** 删除强制“先选房间”的流程；目标已经出现在环视图时，这层规划没有必要。

2. 输入采用五块，顺序固定。

① **Task**：当前目标、阶段、剩余决策数、阶段转换记录；G1/G2 各带目标ID、阶段ID、观察ID和判定状态。上一规划意图明确命名为 `previous_intent`，不再叫 `current_subgoal`。预算和能力从运行配置生成，作为唯一来源。

② **工具表**：仅列实际启用工具及参数、限制、停止反馈。

③ **近期执行**：最近三次动作的请求、实际执行量、停止原因及相关观察ID；只保留一份上一意图。累计路程、完整理由和重复朝向不再铺开。

④ **独立记忆**：Object、Spatial、Experience 分块；Task 已在首块。每条保留库内ID、内容、观察/推断类型、最后证据时间、原图引用及未解决冲突。完整调用来历和版本链留在日志。Experience 关闭时明确标记关闭。

Spatial 的模型记录与程序视点索引分别标明来源，去掉重复位姿。各库独立检索，不合并语义；共享的只是原始证据ID。先保留当前选中的记录，只缩减重复字段，再单独研究检索和条数。

⑤ **图像证据**：历史/动作前图在前，最新环视图随后，最终实际朝向图最后。每图仅标ID、采样时刻、历史/当前身份及可选转向引用。完整矩阵留给程序。

检索必须显式使用当前目标与阶段。[现有检索](/Volumes/2T/Code/Others/LHC/lhc_demo/context.py:511)使用“总目标＋上一步自写 subgoal”，存在被旧意图带偏的路径。

3. 输出建议五字段：

`reason → subgoal → tool → arguments → expected_outcome`

`reason` 限一句关键依据，引用图或记忆ID；`subgoal` 表示可撤销的跨步意图；`expected_outcome` 写可观察变化。仅工具和参数承担动作硬校验。

默认停用 `search_plan` 的房间候选大结构。跨步方向由简短 subgoal 保留；若另外研究显式搜索计划，其格式错误应单独记录，避免连带拒收可执行动作。

`check_conditions` 退出默认输出。八成集中于“可见度变好”，区分行动价值的能力有限。删除时必须同步停用依赖它的“确认进展”计数，否则缺少检查会被持续计为无进展；保留执行反馈和独立 G1/G2。把这项迁移单列版本。

理由前置也单列比较：THOR 的收益明确，BEHAVIOR 已出现退化，不能直接推广为通用收益。

4. 转向的首选接口是“选择视图”，由程序算角度。

例如 `rotate_base({"view_id":"E17"})`。程序结合采样时与当前的实测朝向、相机外参，生成旋转命令。统一坐标系后：

`Δ = ((h目标 − h当前 + 180) % 360) − 180`

当前朝向为0°、目标为215.5°时，得到−144.5°，即右转。180°由程序固定约定。

模型不再同时读取绝对角、弧度、计划角和多个相对角。自由探索转向才输出 `direction:left|right` 加非负角度，由适配器转换符号。

视图引用只适用于最新原地环视；发生平移后，旧视图先用于寻找和重观察。相对转角文字已经出现仍然转反，继续增加说明不是优先方向。

5. 验证围绕决策质量，按单项改动推进。

先修正预算、能力等矛盾，每项单列；随后依次比较转向接口、逐块去重、提示重组、输出顺序、辅助字段退出。每版对照直接前版，最终再与冻结原版同批比较。

每个平台取六类点、每类约三点：环视后对准、当前图可辨但判定不确定、未发现目标的探索、受阻或重复搜索、A→B切换、B→A回访。纳入0010及跨180°案例，预留未参与改提示的点。

每点每版至少五次，批内随机交错；固定图像、记忆和判定器输出，记录最终实际发送的请求。首答拒收计失败，修复成本另计。

主指标是**正确且可执行的首答比例**；分别报告目标视图选择、转向误差、阶段/回访动作、token和时延。预先标注可接受动作集合，避免只认原动作。按决策点配对、分平台报告差值与区间；五次回答不算五个独立场景。

最大风险是离线点来自旧策略。回放支持冻结状态下的决策结论，长期收益仍需闭环轨迹评估。

6. 还有两个容易漏掉的问题。

**判定器和程序索引可能遮住记忆贡献。** 删除 G1/G2 同时移除了额外模型提供的感知信号。记忆比较应固定当前任务状态与 G1/G2，并分别控制记忆文本、派生空间索引和历史图片通道。后续可按库比较无该库、系统记忆、仅由当时原始证据整理的参考记忆，区分记录质量、检索命中与动作收益。

**G2 的最终图需要核实。** [取图代码](/Volumes/2T/Code/Others/LHC/lhc_demo/check_conditions.py:75)允许回退到 `head_000`，工具说明又允许 scan 受阻中断。应绑定结束时实际朝向的图；还需核实正常返回后是否重新采样。若这里错位，完成信号会直接污染规划和评估。
