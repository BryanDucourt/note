## 一、翻成大白话

同样的信息，换一种给法：按机器人自己的身体来整理，动了以后及时更新。这样，小模型能不能少犯"够不着还去拿"这类错，最后把任务做完？

路线分三步：
1. 先用成对的题找出小模型稳定出错的地方；
2. 再试一个最小的改法；
3. 最后看这个改法在连续几步、完整任务、新厨房里还管不管用。

## 三、核对 GPT 引的最近的一篇：PhysVLM

查的是 arXiv 2503.08481v1 的全文。

- **S-P Map 是什么**：
  - 先在各关节的活动范围里采样，用正运动学算出手能到达的空间；
  - 再把深度点云里落在这个空间内的部分，在深度图上标出来，够不着的地方涂灰。
  - 也就是说，程序先把"够不够得着"算好，再交给模型。
- **任务规划分两组**："目标都在范围内"和"部分目标要先靠近"。

| 模型 | 目标都在范围内 | 部分目标要先靠近 |
|---|---:|---:|
| GPT-4o | 75.9 | 35.8 |
| Claude-3.5 | 73.6 | 32.1 |
| GPT-4o-mini | 70.5 | 23.2 |
| PhysVLM-3B（它自己训练的） | 69.2 | 48.4 |

- **给 API 模型加 S-P Map**：只在问答题上测过，GPT-4o-mini 从 52.8 升到 59.8；任务规划上没测。
- **对我们的意义**：
  1. 问题确实存在：大模型一碰到要先靠近的任务，分数就掉一半以上；
  2. 审稿人一定会问"为什么不直接把够不够得着算好给模型"，所以需要这样一个对照组。

GPT 对这篇的转述基本准确，只是没说明加图那一项只测了问答。

## 四、要先想清楚的三处

### 1. B 和 C 差得太少，方法的分量可能要放在"更新"上

- 单步静态题里，我们这一轮发出去的 B（d430fc6），已经给了以底盘为原点的前、左、高三个数，身体参数里也补了肩膀的位置。
- C 再多做的，主要是两件：减去肩膀的坐标；把同一个物体的东西放在一起。效果可能不大；就算有效果，审稿人也可能说"只是替模型做了减法"。
- 再加上 PhysVLM 这个先例，"直接给算好的够不够得着"很可能比 C 强。
- 真正有分量的"组织"，在于动了以后怎么更新：移动以后把旧观测换算到新的身体位置上，并标明哪些是现在看到的、哪些是推算的。这正是我们这条线（上下文、记忆）本来的强项，也是 PhysVLM 这类静态方法覆盖不到的地方。
- **Claude 的看法**：方法的核心放在实验三的"随动作更新"上，静态的 C 只当地基。要用户定。

### 2. "自然发生率"要提前量

- GPT 把"自然任务组"放在实验四。如果官方任务里很少出现身体受限的状态，完整任务上的收益就会很小。
- 我们已有的数：48 个点里，12 个官方开局全部"现在就够得着"。身体问题出在任务中段：脚本关口里，放杯的路径被咖啡机挡住、放置点净空不够、菜在站位上看不见。
- 所以可以先跑几回合闭环（用现有的脚本或规划器），数一数任务中段有多少次落进"够不着、被挡、躯干不对"的状态。
- 这也是我们定过的规矩：先看自然发生率，再定主机制。

### 3. 我们自己的旧结果是一个反例，路线里没提

- BEHAVIOR 卡住那组：事实认得准、整理好了、也送到了，不开推理的规划器还是不用，往空地走最好只有 6/25；开推理加指引是 11/25。
- 所以"C 让关系答对了，动作却没跟上"很可能会出现。GPT 这份路线假设每一步都成功，没写到时候怎么办。它上一份评审里写过结果的分支，这一份要补上。
- 推理开不开也没写。1031 定的是规划器不开推理，GPT-6 用最低档，这里要写明。

## 五、小一些的问题

- **请求方式**：GPT 这次分三种：只问关系、只选动作、先答关系再选。我们这一轮发出去的是后两种。按 1021 定的"一轮的说明发出后不再加项"，"只问关系"放到下一轮再加。
- **"手里有东西"那一对**：要靠 put 先放下手里的东西，而脚本关口里 put 还有失败。放到扩展的时候再加。
- **时间表偏乐观**：
  - 完整任务之前，要先修好关口里放杯、按键的问题，还有在设施之间走动；
  - 我们一轮通常要一两天；
  - 所以"1–2 周出 MVP、4–6 周出完整证据"要打折扣。
- **GPT-6 的花费**：完整任务每回合几十次决策，24 个任务 × 两个条件，可能要上百美元。到时候先试跑，再估算。
- **四个库**：这一篇只用按请求生成的输入视图，不引入共享的语义库，所以不违反 `AGENTS.md`。以后要合成共享的关系记录，再按规矩讨论。
- **研究问题的说法**：GPT 这次比上次好懂，但还是长。怎么说，等用户来写。

## 六、要用户定的

1. 第一篇是不是采用这条主线（顶层的事，用户定）。
2. 方法的核心放在静态的"怎么整理"，还是动了以后的"怎么更新"。
3. 下一轮要不要加两组：一组"只问关系"；一组"直接给算好的够不够得着"，作为 PhysVLM 式的对照。
4. 要不要先量自然发生率。
5. 按惯例，顶层方案定稿之前，先让 Gemini 唱反调、GPT 再审一遍。要不要现在做（会消耗额度）。
