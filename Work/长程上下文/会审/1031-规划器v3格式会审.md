## 一、GPT 的方案（摘要）

- **主线**：v3 围绕"推进任务状态"。G1/G2 留作可见性信息，不再当通用的完成标准。
- **输出**，顺序固定：`subgoal → reason → tool → arguments → expected_change`。
  - subgoal：这一步要改变什么，包括清掉后续动作的障碍；
  - reason：一句话，引用证据编号；
  - expected_change：能观察到的移动、手里拿着什么、容器开合或信息变化。
  - 输入里先列出没满足的条件和已有证据；挑记忆的提示改成"哪些记录影响这些条件和它们的前提"；删掉"理由首句先报 G1/G2"。
- **完成判据**：任务写成有名字的条件，状态是满足、没满足、未知。判断模块给带证据的判断，程序负责组合和推进，规划器没有判完成的权力。
  - 找到 A：判断模块确认 A 出现在这次观测的任一张图里；要正对的话，另列一个朝向条件。
  - 拿起 A：看图确认对象是 A，程序结合拿取成功的回执维护"手里拿着什么"。
  - 把 A 放到 B：程序确认放下，判断模块确认 A 和 B 的放置关系。
  - 打开或关上 C：先确认是 C，再看图或工具回执。
  - 走到某处：事先约定看图能认出的到达区域。
  - "搬出并关门"要同时满足放好、手空、原来那扇门关上。再搬一次，旧条件作废；认不清或被挡住记未知；新阶段先评估当前观测；超出预算记失败，依赖它的阶段记阻塞。仿真真值只在离线核对。
- **计划**：默认只留当前子目标。两三步的滚动计划作为可选变量另测：每步写开始条件、动作意图、预期变化，当作未确认的意图保存，成本要算进去。
- **试点**：
  - 冻结 24 个决策点：深浅受阻、拿取、拿着待放、放好待关、搬后回访，加正常成功的点；留出一半，不用来调提示。
  - 对照："v2 原样""只删掉围着找东西的措辞""完整 v3"，每种再配"真实记忆""删掉关键记忆""等长无关文字"；计划另做消融。
  - 计分：事先标好每个点可以接受的动作，记正确动作、重复失败的动作、参数是否合法；记录记忆的写入、送达和引用。上下文的价值，按删掉记忆前后正确动作率的差来算。
  - 门槛：24 个点净多至少 4 个正确动作，留出的点也改善，误判完成不增加。真实记忆带来的增益没有变大，就否定"新接口让上下文更好用"。
  - 在线放 THOR：原来三类任务各 10 个配对种子，判据和总预算一样，拆条件不加预算。之后再到 BEHAVIOR 验物理绕行。
- **风险**：字段可能诱发事后编理由；计划可能让它更固执；点偏和执行能力还会限制收益。主要读数必须是实际动作和任务结果。v2 结果原样保留；旧录像按新旧两套判据各判一遍，单独列出判据变化带来的差。
- **只做一件事**：冻结"已经放好、只差关门"的决策点，给出剩下的条件和证据，比较三种接口。

## 二、Gemini 的方案（摘要）

- **先挑两处毛病**（Claude 已核对代码，都属实）：
  - **废掉顶层的 G1/G2**：不是环视的步骤，G2 就是 G1 的别名（`check_conditions.py` 第 79–80 行写着 `alias_of: G1`）；G2 一满足阶段就结束（`task_sequence.py` 第 63–66 行），所以规划器被叫来时 G2 总是没满足。强制理由第一句报 G1/G2，既浪费开头的输出，又把注意力锁在"朝目标看"。
  - **顺序不能是"干什么→为什么→预期"**：不开推理时，写在 tool 后面的内容影响不了这一步选什么。另外 `build_context` 只带了上一步的子目标，没带上一步的预期结果（`context_v2.py` 第 144–150 行），"对比预期"现在悬空。
- **输出**，顺序就是它的工作记忆：
  1. `state_check`：一句，核对上一步的预期和实际结果；没达到就写明是被挡、点偏还是状态没变；阶段第一步写 stage_start。需要把上一步的 `expected_outcome` 带回输入。
  2. `evidence_used`：0–2 个图或记忆的编号。
  3. `subgoal`：`{now, next_after}`。
  4. `why`：一两句，不准写"没看到目标"，只写这一步怎么解决 state_check 里的阻碍或当前阶段的前提。
  5. `tool`、`arguments`。
  6. `expected_outcome`：一句，能观察到的物理或状态变化，下一步原样带回。
  - 系统提示和挑空间记忆的提示，都改成"推进当前阶段的物理前提（绕开障碍、打开容器、对准、交互）"。
- **阶段判据**：不要把"开、拿、放、关"捆成一个 7 步的阶段。THOR 里"放好了只差关门就用完 7 步"是捆绑预算造出来的假失败。拆成 5 类原子阶段：
  - find：判断模块看正对方向的图；
  - reach：历史视点由程序按测量的位姿差判，语义区域由判断模块看图判；
  - open/close：程序看工具完成，判断模块看前后两张图和点击点，确认是那个容器开了或关了；
  - pick_up：程序看工具完成且 holding，判断模块看点击点落在目标上、执行后原位消失；
  - put：程序看工具完成且 holding 变回空，判断模块看落点在容器上。
  - 离线一律用仿真真值核对得分，和在线推进分开。
- **计划**：不要长序列，只用两拍 `{now, next_after}`。不开推理时写三步以上容易编造未来坐标、变得僵硬；纯单步又会把"去台面"压成"朝台面硬撞"。要不要留，离线消融定。
- **试点**：
  - 离线三片：A 几何受阻（BEHAVIOR 108）；B 操作前提和纠错（THOR 关着的柜子里找东西、点偏后重拿、放好待关门）；C 常规找东西（防退步，v2 已经 10/10 的点）。
  - 对照：C0 v2；C1 去掉 G1/G2、改输出顺序；C2 再带回上一步预期；C3 再加两拍；C3-drop 删掉关键的障碍或容器记忆，作反事实对照。
  - 读法线：A 往受阻扇区外的空地移动（它写的是 >30°）≥50%；B 选对前提工具且点在目标上 ≥60%；C 保持率 ≥95%；C3 比 C3-drop 高 25 个百分点以上，才算真的用上了记忆。
  - 否定条件：C2、C3 在 A 上仍 <30%（光靠输出结构解决不了深的几何绕行，要程序给可达候选，或者给一点推理预算）；C3 和 C3-drop 差 <10 个百分点；C 跌破 85%。
  - 在线放 THOR：快，没有打滑噪声，五类阶段都有，还有 3×10 轮的 v2 基线。跑通后回 BEHAVIOR 跑 108 加两个正常起点。
- **风险**：近处遮挡让判断模块判"不确定"卡关（允许退一步或 observe 复核一次）；evidence_used 可能乱引用（只认 C3 减 C3-drop 的净增益）。
- **衔接**：BEHAVIOR 只有 find，判据和 G2 等价，可以直接比；THOR 拆了阶段，按同样总步数上限（比如 28 步）下、离线真值的里程碑完成率和 v2 对齐。
- **只做一件事**：用已存的 v2 状态（108 带路线的状态、THOR 关着的柜子、被动找东西）先离线跑 C0、C2、C3、C3-drop。

## 七、第二轮：Gemini 唱反调、GPT 审稿（草稿第一稿）

两边各自续用第一轮的对话，拿到的是同一份草稿。

**Gemini 的攻击**（按它排的严重程度）：
1. **操作片泄题**：v2 的运行里"开、拿、放、关"捆成一个阶段，规划器得自己判断当前该做哪一步；草稿却直接告诉 v3 阶段类型（open、pick_up……）和涉及的物体，等于用真值告诉它该调哪个工具、开哪个容器。"操作片比 v2 高 20 个百分点"就成了同义反复，a 类连记忆都不用查。
2. **删上下文没删干净**：HISTORICAL 图本身就拍到了目标，只删文字记忆，图还在；按名字删，漏了不含目标名、但带着回去路线的程序视点；`previous_*` 在 v3－ 里会漏出删之前的意图；v2 原来的 expected_outcome 写的是"会看到目标"，喂给 v3 会让它的核对乱判失败。
3. **计分能钻空子**：餐桌底下、餐桌后面露出来的地面在分割里也算地面，偏 16° 点到那里就拿分，直线走照样撞桌；合法的 move_base 侧移、后退和 go_to_viewpoint 又全判 0。f 类"原地转向记忆的方向 ≤30° 就得分"，和 108 的病根（隔着障碍朝目标转）方向相反。
4. **样本和留出是假的**：5 个受阻点都来自起点 108；同一起点按单双号分调试、留出，只是隔两步的同一张餐桌；温度 0 同一点问 5 次几乎没有方差，460 次实际只有 23 个点。
5. **因果顺序**：subgoal 在 why 前面，等于先拍板意图、再找证据背书；它和 expected_change 重复。在线时阶段满足就结束，status 永远不会是 met，留着只是噪音。
6. **更简单的做法**：每点只问 1 次，换成跨起点、跨房间的大约 80 个独立点，按起点或轮次分留出；比格式时不给 v3 喂 open、close，保持和 v2 一样的阶段粒度，把"拆阶段"留到下一轮；删掉 subgoal 和 status；顺序改成核对上一步 → 证据编号 → 为什么 → 工具 → 预期；受阻计分加"连线不穿过障碍"。

**GPT 的审稿**（按它排的严重程度）：
1. **阶段信息可能提前给出答案**：v3 拿到原子阶段，评分又要求同名工具，v2 拿的却是原任务。要么规定原子阶段怎么由决策前的合法证据确定，再加一组"阶段信息相同、输出保留 v2"的对照；否则收益里混着任务拆分，不能叫"只改格式"。
2. **主分会奖励错的动作**：落在地面、偏 15° 也可能穿过餐桌；目标看得见、点也点中，可能距离太远；朝历史地点直走可能撞障碍。反过来，后退、转身、走近可能是对的却不得分。应该逐点预标可接受的动作集合，把工具的前提算进去；离线分数叫"动作选择合格率"，执行收益留给在线试点。
3. **找片 e 和完成定义冲突**：如果 find 是"这次任一张图里看到"就完成，e 应该由程序直接结束阶段；如果要求转到正面，就明确保留 G2 的意思。`seen_in` 必须限定在这一次观测里。
4. **机械删除不一定删掉关键证据**：关键词会漏掉路线、别名，也会误删；历史图、最近动作、`previous_*` 里可能还留着同样的信息。要逐点冻结删除清单和残留，补等长替换的对照。差值只能解释为被删记录的增量价值。
5. **留出和重复的单位不对**：同一条轨迹相邻的点按单双号拆开会互相泄露；108 那几个点参与过方案设计，只能当诊断集。按整条轨迹划分，调试完、提示冻结后再看留出结果。统计按点和轨迹归组。
6. **"上下文更有用"能被退化触发**：v3 完整输入不变、删掉的那组变差，差值也会扩大。应事先指定主片，要求主片的完整输入收益和交互收益同时到线。没到线写"未达门槛"，不要断言没有改善。
7. **执行口径还缺三项**：上一步的预期只能照原回答转录，不能补成更合理的 v3 预期；last_step_check 加 unknown；第一次回答格式不合格计入主分失败，修复和重答另报，不替换。

## 八、在线试点草稿的第二轮（1031）

两次离线试点之后，用户选了复盘里的第 1 种："可以按1做一下"。Claude 写了 THOR 在线 v2 对 v3 试点的草稿（[[1031-THOR在线v2对v3试点说明]] 第一稿），Gemini 唱反调、GPT 审稿，都续用 v3 的对话。

**Gemini 的攻击**：
1. **天花板加噪声**：写清柜子、给 12 次决策以后，v2 可能已经完成 7–8/10，"多 3 个"撞天花板；就算 7 对 4，也落在同样输入两批之间的波动里。
2. **阶段之间互相影响**：第 1 关没关门，后面找东西反而更容易，50 个找东西的阶段混在一起算，惩罚了把门关好的那组。每关都传完整任务文字的话，第 3 关看字面就知道开哪个柜子，测不到记忆。
3. **读法线没绑离线真值**：在线只看工具反馈，拿错放错也算过关；"差不多位置"没有阈值，点偏以后合理的微调也会被算成重复失败。
4. **新补丁没验证就上线**：判断写法的新改法没在那 18 个 e 点上测过；写"看过放大图"会让它在误报时也盲信。
5. **更简单的做法**：先离线测新写法（不到 17/18 不上线）；不跑 v2 已经满分的被动观察，32 轮都给两类搬运任务；第 3 关不写"同一柜子"在哪；读法线绑离线真值和小里程碑；重复失败定死为底盘移动 <0.1 m、点击差 <0.03。

**GPT 的审稿**：
1. **主分要按离线核实**：搬运在阶段结束时核实目标、放置位置、手空、容器关上；写明超出预算后怎么办；搬运失败后的找东西单列；另报四个阶段全对的轮数。
2. **预期带回有接线风险**：共享解析器读 `expected_outcome`，v3 输出的是 `expected_change`，直接复用会丢字段；只带回实际执行了的动作的预期，没执行的坏回答不能变成下一步的预期；跨阶段怎么处理要固定。
3. **配对和重置**：列出 15 对和种子，每对相邻执行，平衡先后；重置物体、门、手里的东西、机器人和全部记忆；报告逐对差异。
4. **"完全一样、逐字节不变"要限定范围**：记忆内容随轨迹不同；逐字节比较只在同一个输入快照上做；判断信息保留 yes、no、unknown 和当前图编号，措辞要和实际流程一致。
5. **重复失败的定义要能执行**：固定目标、失败原因、参数容差和"中间没有进展"；一长串只算一次；报次数和比率；失败阶段耗掉的预算也要报。
6. **读法线有歧义**：70% 是门槛还是次要指标要写明；v2 已经 8/10 时线不可达，要事先标成天花板；结论只限整套 v3。
7. **冒烟和重试要隔开**：冒烟不进正式样本，之后冻结版本；JSON 修复和参数重答分开；基础设施故障怎么补跑事先定，模型失败不挑着重跑。

**Claude 的处理**（第二稿）：
- 加第一步：离线预检新判断写法，6 个 e 点 × 3 次，和 v2 交错，至少 16/18 才上线；不写"看过放大图"。
