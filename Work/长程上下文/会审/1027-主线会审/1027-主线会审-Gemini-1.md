以下按第六节的六个问题逐条回答。先说核心判断：**换掉原问法是对的，但新问法太宽、像工程体检而不像科学问题；更严重的是，第二周的数据里藏着三个程序级漏洞，导致你们其实还没有真正测到“生成的记忆对决策有没有用”。**

### 1. 问法：适不适合？优缺点是什么？有哪些已有工作？

**判断：方向比原来对，但不能直接拿“上下文对决策值多少”当现阶段的研究问题；应该收窄到你们长期问题的后半句——“当早期感知不可靠或视野受限时，上下文什么时候能帮规划器少走弯路、什么时候反而误导规划器提前停止？”**

- **比原问法好在哪**：
  原问法（“观测范围丢失造成多少损失”）建立在一个未经证实的前提上：上下文整体已经在起正面作用，只是被“范围丢失”拖了后腿。第二周数据直接证伪了这个前提（自然发生率 0/1877 和 0/669；THOR 人工丢掉范围后 1–2 步就被覆盖，中位步数 5 步甚至比保留组 6 步还少）。及时止损是对的。
- **新问法最大的三个弱点**：
  1. **“上下文值多少”没有脱离任务结构的普适答案，不算科学问题**：在单房间、转头 1–3 次就能看到目标的任务里，记忆本来就值 0（无历史也是 2/2）；在跨区域回访或高代价搜索里，有效记忆当然值省下的步数。不绑定任务的可观测性结构，问“值多少”测出来的是任务难度，不是记忆机制。
  2. **把“程序管道漏洞”错当成了“大模型生成记忆没价值”**：用户怀疑“提示词生成的记忆到底有多少价值”，但第二周有历史没跑赢无历史，主因根本不是 DeepSeek 写坏了记录，而是**挑选规则把记录删了**（W2）和**把判断模块的误报直接喂给了规划器**（W3）（详下第 6 题）。
  3. **漏掉了第二周唯一真正跑出来的强信号——上下文的“负价值”与“不确定性校验”**：在 W3（条件变化）里，有历史（3/6）比无历史（2/2）差，唯一做对的 0040、0042 全靠 Object 写了“不确定”，挡住了 Task 里的误报判定。这恰好对应你们的长期问题（**什么时候值得重新去看，而不是相信记忆**），比宽泛地问“上下文值多少”尖锐得多，也更容易发文章。
- **已有类似工作**：
  - *记忆何时有价值*：MultiON（Wani et al., CVPR 2020）、Goat-Bench（Khanna et al., 2024）已证明：单房间短视距搜索中反应式策略与带记忆策略差距极小，记忆价值集中在顺序多目标回访与跨遮挡区重定位。
  - *结构化记忆 vs 滚动摘要/原始历史*：ConceptGraphs（2024）、ReMEmbR（2024）等做过空间/实体记忆与纯文本摘要的对照。
  - *早期感知错误写进记忆后误导后续决策*：KnowNo（Ren et al., 2023）讨论了感知不确定性下何时向环境求证；智能体记忆中的错误固化（hallucination propagation in agent memory）也是近期热点。

### 2. 怎么量：比什么？单步还是整轮？怎么守住信息边界？

要拆开“总潜力（值多少）、哪一层起作用（从哪来）、生成与挑选损耗（兑现多少）”，不能只比“有历史 vs 无历史”，必须搭**三级对照梯子**：

1. **比什么（三组主对照 + 消融）**：
   - **下界 $M_0$（无历史）**：规划器只看当前图、上一张图和目标。
   - **当前系统 $M_{\text{sys}}$（生成记忆）**：拆成两个子版本——**$M_{\text{sys-raw}}$（现行带挑选上限版）** 与 **$M_{\text{sys-full}}$（去掉“只挑当前可见/最近 4 条”过滤，把库里已有记录全给规划器）**；再做单库消融（去掉 Task 判定、只留 Object、只留 Spatial）。
   - **上界 $M^*$（人工清洗的视野内真值记忆）**：
     - **如何保证不泄露仿真真值？** 严格按**“历史已见画面边界”**构造 $M^*$：由人工（或离线看图）只根据第 $1..t$ 步已经拍到的 RGB 图，用完全相同的字段格式改写记录——没入画的物体绝不写；远处只有 87 像素、肉眼看不清的板子，必须标为“疑似/不确定”，绝不写死为真砧板。这不引入任何深度、分割、位姿真值，只消除模型写记忆时的漏写和误判。
   - **三问的对应算式**：
     - **上下文最多值多少** = $M^* - M_0$
     - **生成记忆兑现了多少** = $M_{\text{sys-full}} - M_0$（对比 $M^* - M_0$）
     - **挑选/截断丢了多少** = $M_{\text{sys-full}} - M_{\text{sys-raw}}$
2. **在单个决策点量，还是整轮量？看什么指标？**
   - **先在单个关键决策点（离线探针）量，再在整轮验证**。单房间里瞎转也能撞上目标，整轮成功率噪声太大、样本量又小（每组 2–6 轮）。
   - **单步指标（主指标）**：
     - 延迟回访交接点：**首次自由决策的朝向正确率**（第 1 步是否直接选 `move_to_point` / 转向历史见过 X 的方向，而不是原地盲目 `scan`）。
     - 条件变化交接点：**核实动作率**（第 1 步是走近核实，还是原地 `observe` 触发结束）。
   - **整轮指标（辅指标）**：不要只看二值对错，看**自由阶段多余决策步数**（实际步数减去从交接点走过去的最少步数）和**误报完成率**。

### 3. 用什么任务：怎样让上下文价值显出来？控制什么变量？

第二周 W2（延迟回访）之所以看不出记忆价值，是因为**任务几何太简单**：“X 在自由阶段第 1–3 次决策就重新入画”，无历史转两下头就能看见，$M^* - M_0$ 的天花板只有 1–2 步，根本拉不开差距。

**任务筛选硬标准**：在交接点跑无历史 $M_0$，**中位寻获步数必须 $\ge 5$ 步**，否则该起点配置直接作废。建议主跑 **AI2-THOR**（10 秒一步，样本量能上到 20–30 个决策点），BEHAVIOR 只做小样本复核：

1. **任务 A（测正价值：跨视角/遮挡回访）**：
   - 脚本前缀在区域 A 看清目标 X，随后走到被岛台/拐角遮挡或背对 A 的区域 B 看 Y，并在 B 产生 $N$ 条干扰记录。从 B 找回 X 需要从 3 个以上候选方向/导航点中选对 A，盲搜平均要 5–8 步，有记忆一步到位。
2. **任务 B（测负价值与核实：远距疑似物/易混物）**：
   - 直接规范化 W3 和 THOR 厨房 7/9（咖啡机/锅像水壶、远处浅色板子像砧板）：脚本前缀在远处拍到疑似物，交接给规划器，测试上下文是帮规划器“走近核实”还是害它“原地报错完成/漏检”。
3. **控制变量**：
   - 固定脚本前缀、交接位姿和图像序列（感知绝对固定）；
   - 只干预交接时刻送入规划器的上下文内容（1. 是否把 Task 的 G1/G2 满足状态暴露给规划器；2. Object 是否做可见性/条数截断；3. Object 对远距目标标“支持”还是“不确定”）。

### 4. 怎样推广：怎么让结论不局限于这套提示词和四个库？

1. **把“四个库”映射成所有具身智能体通用的三类信息通道**：
   写论文和设计消融时，不要停留在你们自定义的模块名上，直接对应到通用功能：
   - `Task` = **进度与终止信念（Progress State）**
   - `Object` = **带不确定性的实体记忆（Entity Memory with Uncertainty）**
   - `Spatial` = **已探索/未探索拓扑（Exploration Frontier）**
   同时在离线探针上补一个**单段滚动摘要（Rolling Summary）**对照（把 1023 拿掉的对照只在离线探针上加回来，几分钟就能跑完），直接检验“把实体不确定性独立建库”是否比“混成一段摘要”更能防止误报完成。
2. **用解码约束救活 Qwen3-VL，低成本补齐第二个模型**：
   Qwen3-VL（8B 82%、32B 71%）合法输出率不达标，通常是 JSON 格式或枚举字段拼写越界，不是视觉或推理不能用。在**不改提示词**的前提下，用 vLLM/SGLang 的结构化输出约束（`guided_json` / schema grammar）或外层字段修复器，只在**离线重放的冻结请求**上跑通 Qwen3-VL，就能堵住审稿人“只在 DeepSeek 一个模型上成立”的质疑。

### 5. 第一步：一周内能做完的最小一步？什么结果放弃这个问法？

**一周内的最小一步（不需要跑漫长的 BEHAVIOR 在线仿真，3 天离线探针 + 2 天 THOR）**：

1. **第 1–2 天（正在做的离线探针扩展到 W2 + W3 共 12 个交接点，耗时 <1 小时）**：
   - **W2 探针（0034–0039 的首次自由规划点）**：把当时**已经在库里、但被挑选逻辑拦住的砧板记录**塞回规划器输入，对比“现行漏掉版”和“无历史版”，看规划器第 1 步会不会立刻转向砧板。
   - **W3 探针（0040–0045 的首次自由规划点）**：做 $2 \times 3$ 离线替换——Task 的 G1/G2（显示“满足” vs 改为“不满足/隐藏”）$\times$ Object 的板子记录（无记录 vs 标“支持” vs 标“不确定”），每格重放 6 个请求，看规划器选 `observe`（误报完成）还是走近核实。
2. **第 3–5 天（THOR 10 个厨房在线验证）**：
   - 修掉 Object“只挑当前可见物体”的过滤后，在 THOR 挑 10 个无历史需 $\ge 5$ 步的回访起点，跑 $M_0$、$M_{\text{sys-full}}$、$M^*$ 各 10 轮。

**放弃当前问法的硬标准（Kill Criterion）**：
- 如果在 W2 离线探针和 THOR $\ge 5$ 步的任务里，**连人工清洗的完美记忆 $M^*$ 塞给规划器，都没法比无历史 $M_0$ 显著改变第 1 步动作或减少 $\ge 2$ 步搜索步数**——说明瓶颈根本不在上下文/记忆生成，而在**规划器压根不会利用文本坐标/方向记录来选动作**。立刻放弃“记忆值多少/兑现多少”的问法，转去查规划器的动作空间和空间对齐。

### 6. 最该先核实什么：上面数据和推断里最可疑的 5 个地方

1. **【最致命】W2（延迟回访）根本没测到 Object 记忆，因为挑选逻辑把目标记录全拦住了**：
   第三节写得很清楚：0034–0039 共 6 轮延迟回访里，“离开砧板以后，Object 挑选输入时只挑当前看得见的碗。砧板的记录还在库里，但没有进入首次自由规划的 Object 输入”。
   这意味着**在全部 6 轮延迟回访交接给规划器的那一刻，规划器看到的 Object 摘录里根本没有砧板！** 一个记忆系统在挑选输入时“只挑当前看得见的物体”，那要记忆干什么？当前看不见的时候才需要记忆！你们据此怀疑“大模型生成的记忆有没有价值”，其实连生成的砧板记录都没让规划器看见。
2. **W3（条件变化）“有历史（3/6）不如无历史（2/2）”，是因为把判断模块的误报通过 Task 库直接喂给了规划器**：
   判断模块在远图上有 16/18 的误报率。在 BEHAVIOR 里，脚本前缀阶段不触发结束，但判断模块算出的 `G1/G2 = 满足` 被写进了 Task 库。
   - 到了自由阶段第 1 步，**有历史组**（0041、0043、0045）看到 Task 写着 `G1/G2 = 满足`，规划器直接说*“程序判定 G1 与 G2 均已满足……无需再搜索”*，选 `observe` 原地不动，触发自由阶段完成判定而误报结束！
   - 而**无历史组**（0048、0049）因为**看不见 Task 库**，不知道程序已经误判完成了，所以老老实实 `scan` 并走近，反而做对了！
   **必须核实**：既然 G2 是用来判任务结束的裁判信号，为什么要在任务还没结束时把 `G1/G2 = 满足` 当上下文喂给规划器？这等于直接命令规划器原地停下。
3. **判断模块的极高误报率（16/18）和 THOR“首帧直接结束”规则污染了主指标**：
   THOR 厨房 7 的 8 轮全在第 1 张图把咖啡机当水壶直接结束；厨房 9 把锅当水壶；W3 远图 16/18 认错。当裁判模块有近 90% 的远距误报率时，整轮对错主要取决于“机器人走位有没碰巧避开裁判的误报视角”，而不是记忆好坏。即便判断模块提示词冻结，**不在首帧/远距单帧上直接判停**、或者**不把 Task 的满足判定透传给规划器**，也是必须先核实的系统边界问题。
4. **THOR T1（保留 vs 丢掉范围）的干预只维持了 1–2 步就被覆盖，整轮步数对比无效**：
   数据明确提到“丢掉组 9/9 在自由决策 1–2 次以后，Object 自己又写回了带局部限定的记录”。也就是说从第 2 步起两组已经没有区别了，而第 1 步两组的指标完全一样（中位数都是 1）。拿第 5、6 步的完成中位数去论证范围丢失没影响，在因果上是无效的。
5. **0036 的失败是键值校验死锁，不是 N=5 的记忆退化**：
   0036 自由决策 0 次，是因为 Spatial 把房间状态改为“疑似区域”后编号从已知列表消失，规划器连填三次旧 `room_key` 被校验器拒掉。这是模块间枚举列表不同步的程序 Bug，在每组只有 2 轮的样本下把它算进 N=5 的成功率（变成 1/2），会严重扭曲结论。
