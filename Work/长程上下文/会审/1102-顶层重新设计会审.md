## 一、Claude 的方案（发出之前写好）

**A. 底层：主线用乙，也就是 RPent 加冻结的 RLDX-1，把特权信号都藏起来。**
- **理由**：
  1. 用户的草稿要官方任务、要和主流比、要看到效果。走乙，现成的外部基线和官方指标都有：RLDX-1 单独跑 30.0；RPent 能看到特权信号时是 57–59。
  2. 不用训练。旋钮、水龙头、电器门这些操作 VLA 都会，甲要我们一个一个写。
  3. 身体还在：RPent 的底盘和手臂原语（move_base、navigate_to、move_to、rotate_pitch）由规划器来调。"把身体当工具用"对应到"调 VLA 之前，把身体摆在哪里"，可以量。
- **代价**：
  - 算力：VLA 约 7B，放在 A100 上，或者占满 5090；
  - 回合长，规划器花钱多；
  - 底层失败多：RLDX-1 在没见过的组合任务上只有 5.0；
  - RPent 的代码还在快速变化，要固定版本。
- **甲先放着**：代码留着，以后要分开"规划器的错"和"底层的错"时再用。丙不做。

**B. 判完成：特权信号全部藏起来。**
- success、terminated、task_progress、success_criteria 这四样，规划器都看不到。
- 规划器自己调 finish，或者用完预算；官方 `_check_success()` 在回合结束后离线算。
- 另外离线记两件事：每一步官方判定是真是假；规划器在哪一步停的。这样能分出"说早了""做到了还没停""没做到"。
- **基线**：RPent 藏掉信号以后的版本。RPent 公布的数字是看得到信号时的，只能当参考，不能直接比。
- **这样一来**："看不到特权信号时，怎么知道自己做到哪了"就成了核心难点，正好落在上下文的"任务进度"那一部分。

**C. 规划器**：
- **主结果用强模型**：主流的数字都是这样报的，基线也就一致。
- **"小模型也能规划好"放到第二条线**：比如 Qwen3-VL-8B 或 deepseek，看我们的上下文对小模型帮助是不是更大。
- **输出形式要注意**：Codex、Claude Code 这类编程智能体自己管上下文，会读文件、也有自己的对话历史，我们要研究的上下文变量会被它冲淡。所以实验用 RPent 的 `api` 接法，上下文由我们控制；编程智能体那几行只当参考基线。

**跑通的新定义**：
1. **先只跑 VLA**：用任务原文直接调 RLDX-1，跑几个原子任务，对一下公布的原子任务 60%，以此确认装对了。这一步不涉及规划器，也就没有特权输入的问题。
2. **再跑一小片**：比如 3 个原子任务、2 个见过的组合任务、1 个没见过的组合任务，各 2 个种子；信号全藏，用一个规划器。
3. **通过的标准**：从头跑到尾；官方判定只在离线记；规划器输入的审计里没有特权信息；记下每次的用时和 token。
4. 看了耗时和成本，再定完整基线跑多大。

**上下文**：
- RPent 自带的跨回合记忆，是用带成功标签的探索做出来的。主比较里先关掉，或者固定不动、照规则申报。
- 我们改的放在回合之内：世界、身体、任务进度。

**其他**：
- **BEHAVIOR**：以后再说。CaP-X 有 R1Pro 的接入，到时候再看。
- **THOR**：停。
- **`AGENTS.md`**：架构定了以后再改四库那一条。

**风险**：
1. VLA 的失败太多，上下文的作用被噪声淹没；
2. 时间和钱；
3. 藏掉信号以后，基线可能低到底，没法比；
4. 撞车：Harness VLA、PhyAgentOS 已经展示过"套一层框架"的收益，我们的新意必须落在"没有特权信号时，回合内的上下文"。

**更简单的退路**：用甲（自己的运动学工具），在官方组合任务里挑技能覆盖得了的一小部分来做。快，不用 VLA；代价是没有外部可比的基线。

## 二、GPT 第一轮（摘要，原文在附录）

- **底层**：选乙，冻结的 RLDX-1，只复用 RPent 的接入部分。上层发一个语言子目标，VLA 执行一段，再返回观测；先只开"执行、观察、结束"三个入口，不让写任意程序、不让查仿真。甲在执行器上要花的精力太多；丙暂缓。
- **身体信息**：上层根据夹爪状态、实际位移、视线遮挡、失败历史，决定换站位、重新看或换子目标。只能用策略本来就有的观测，不能用仿真算出的净空和抓住的是哪个物体。
- **判完成**：
  - 规划器在线维护"已确认、待确认"的任务条件。提出结束时，另做一次视觉判断来确认；确认不了就继续取证。
  - 官方判定只放在评分端，回合后汇总，也不影响动作段长短、重试和停止。
  - RPent 自带的配方和全局记忆不能直接用，里面可能有靠特权反馈得出的结论。
- **找到的泄漏**：除了核查里列的四样，`rldx_skill.py` 每执行一段就查一次官方判定、成功就停；返回结果里还有仿真识别出的被抓物体。Claude 核对属实，见第四节。
- **能比的数字**：57–59 只当特权条件的参考；30.0 要在相同的任务、种子、动作预算下重跑才能比。
- **规划器**：首版用 Sonnet 5.5 API，中等推理，每步一个工具调用，不写整段程序。"小模型、不开推理"留作后面的研究目标，用 Qwen3-VL-8B。
- **第一步**：
  - 三个官方任务：OpenDrawer、PickPlaceCounterToCabinet、PrepareCoffee。
  - 最小系统：官方环境、冻结 VLA、API 规划器、最近 4 次交互的窗口、结束确认、独立评分。
  - 每个任务先用 2 个种子调通，再用 10 个新种子，比较"VLA 直接执行完整指令"和"规划器加 VLA"，共 60 回合。
  - 通过：两个原子任务各至少 5/10，组合任务至少 2/10，误完成最多 1 次。
  - 估计开发 40–60 个工时，运行 10–30 小时；API 约 43 美元，预留 150–250 美元。
- **上下文**：不建四套记忆流水线，存带时间和来源的观测、动作记录；世界、身体、任务、经验作为读取视图，存储结构以后再定。跨回合记忆先关。
- **风险**：
  - 执行仍是瓶颈：公开的高分还用了运动原语，纯 VLA 加子目标能做到多少要实测；
  - 官方任务可能不需要记忆，所以先比完整历史和短窗口；
  - 资源和工程会膨胀。

## 八、Claude 的意见（看了用户的追问之后写）

**先认一个错**：三方一致选 VLA，核心理由是"能和主流比、能上榜"。这个框是 Claude 带进会审的：会审说明里把 agentic 榜和 Harness VLA 当成了对标。按用户说的目的，也就是研究规划和上下文、不局限在 RoboCasa、不刷榜，这个理由站不住，底层这一处的结论要改。

**逐条回答**：
1. **用了 VLA，规划还能做什么**：
   - 能做的：拆任务、排顺序、找东西、摆好身体再调 VLA、判断一步做成没有、失败了怎么重来、记住做到了哪、判断做完没有。Harness VLA 和 PhyAgentOS 的提升就来自这些。
   - 问题是，规划器的大部分功夫会花在"让这个 VLA 干好活"上：换说法、重试、重新摆位置。Harness VLA 的记忆本身就是"这个 VLA 在什么情况下好用"。研究内容会从"上下文怎么帮规划"滑到"怎么驾驭某一个 VLA"，换一个 VLA，结论可能就不成立。
   - 底层失败也太多：RLDX-1 单独跑没见过的组合任务只有 5.0。上下文的作用会被淹没，这是三方都承认的最大风险。
2. **VLA 的指令遵循**：确实有问题，有实测证据。
   - [LIBERO-Plus](https://arxiv.org/abs/2510.13626)：VLA 对指令的改写基本不敏感，倾向于完全不看指令。把指令整个去掉，OpenVLA-OFT 在物体那一组上的表现几乎不变；把目标换成没见过的物体，它们还是去做原来的目标。这些出自论文摘要和评述，细节没核对原文。
   - Harness VLA 自己也是这样设计的：只把 VLA 用在局部的接触操作上，定位、预备、搬运、导航、松手交给解析原语。理由是 VLA 遇到扰动会失败（论文摘要）。
   - 规划器给 VLA 下子目标，VLA 却不照着做，规划决策的好坏就量不出来。
3. **不局限在 RoboCasa**：
   - RLDX-1-FT-RC365 是在 RoboCasa365 上微调的，只能在 RoboCasa 上用。换到 BEHAVIOR 或真机，就要换一个 VLA，结论也跟着变。
   - 语义动作这一层，各平台都有：
     - THOR 自带开、关、拿、放；
     - BEHAVIOR 用的 OmniGibson 有现成的[语义动作原语](https://behavior.stanford.edu/omnigibson/reference/action_primitives/starter_semantic_action_primitives.html)：抓、放到上面、放进去、开、关、开关电器、导航、松手，另有一个只改状态的[快速版](https://behavior.stanford.edu/omnigibson/reference/action_primitives/symbolic_semantic_action_primitives.html)；[VisualAgentBench](https://arxiv.org/abs/2408.06327) 就是用这类动作，在 OmniGibson 上评测大模型智能体；
     - RoboCasa 的，我们自己写了 8 种。
     - 注意：OmniGibson 文档里写着这套原语只支持 Fetch 和 Tiago，R1Pro 能不能用要核实，版本不同也可能有变化。
   - 所以规划层应该通过一套稳定的技能接口说话，各平台各自实现，研究结论才能跨平台。
4. **不刷榜**：agentic 榜就不再是理由。"对标"应该是和别人的规划、上下文做法比，比如滑动窗口、滚动摘要、带反思的 ReAct、RPent 那种带记忆的框架逻辑，放在我们同一套技能接口上实现；而不是和别人的底层比分数。

**底层这一处，Claude 改成**：
- **接口**：规划层只通过一套语义技能接口和底层打交道。技能包括拿、放、开、关、拧、按、导航，也包括身体动作：底盘、躯干、手臂姿态。
- **实现**：
  - 研究主线在 RoboCasa 上，用我们自己的运动学实现，也就是甲；
  - BEHAVIOR 上用 OmniGibson 自带的语义原语，或者我们包一层，做更真实的验证；
  - VLA 以后可以作为技能的另一种实现接进来，看底层更不可靠时结论还成不成立，但不是现在。
- **甲的毛病要正视**：
  - 执行器用仿真信息（实例掩码），这是 THOR 和 OmniGibson 语义动作的通行做法；规矩管的是模型输入，不管执行器。但技能的反馈要像真机器人能感知到的：比如"夹爪合上了、手里有东西"可以，"东西已经在柜子里了"不行。
  - 技能怎么失败要按真实几何来：够不着、被挡、门会扫到身体。这正是身体信息有意义的地方。
  - 官方任务要的设施操作，比如旋钮、水龙头、按钮、抽屉，要补技能。先挑技能覆盖得了的一部分官方组合任务。
- **三方结论里仍然成立的**：特权的成功信号不进规划器；规划器自己判完成；官方判定只在离线算；每步一个工具调用。

  1. **对齐主流合规基线，避免工程无底洞**：Target50 有 50 个任务（含开水龙头、旋钮、微波炉、多步组合，见 02-RPent与RoboCasa榜核查.md）。若选甲，05-RoboCasa可行性移植-原始结果.md 仅做 1 个苹果任务就耗时 2.3 小时，扩到多布局多容器预估还需 24–40 工时，且用仿真实例掩码和运动学吸附（误差 0 微米）违反 RoboCasa agentic 榜“只能用策略自有观测”的规则，无法发榜对比。选丙则会重演 THOR“拿取失败淹没记忆作用”的覆辙。
  2. **RLDX-1 的短板正好留出了长程上下文的净收益空间**：RLDX-1 裸跑原子任务有 60.0%，说明底层短程操作够用；但组合任务暴跌到 21.3%（见过）和 5.0%（没见过），加上 RPent 框架后能升至 43.8%–61.0%。这高达 30–40 个百分点的差距，正是高层规划与上下文机制发挥作用的黄金区间。
* **风险**：去掉特权进度信号后，VLA 单次调用的局部失败（如差几厘米没放进、被柜门挡住）没有官方 `_check_success` 提示，规划器可能误判成功或死循环重试。

  1. **主动具身取证与可观测性调节**：通过 RPent 自带的底盘移动、躯干升降、移开遮挡手臂、查看腕部相机（`wrist_view`）来创造观测条件（直接支撑主线二）；
  2. **VLA 执行反馈的本体诊断**：利用底盘实际位移 $\Delta x$、末端受阻、夹爪闭合宽度等本体读数，在没有真值信号时辅助判断 `rldx_skill` 是“真抓到了”还是“抓空/被挡住”（直接支撑主线一）。

* **谁来判完成**：

**3. 规划器**

* **与用户 1031“让小模型也能规划好、不开推理”怎么协调**：
  - 把“小模型 + 不开推理”从**前期自我捆绑的脚镣**变成**第二阶段的消融自变量与论文卖点（Context as Amortized Reasoning）**！
  - 第一阶段（跑通闭环）必须先用强模型 + 简短推理把无特权组合任务成功率拉起来（证明机制有效）；第二阶段做 2×2 对照：`{强模型开推理, 小模型(如 Qwen2.5-VL-7B / deepseek-flash)不开推理} × {简单滑动窗口, 我们的结构化上下文}`。也可以采用**“后台轻量异步整理上下文 + 前台小模型不开推理直接决策”**的架构，证明好的上下文结构能替代昂贵的在线长推理。

**4. 第一步“闭环跑通”的具体方案**

* **最小可运行版本（MVP）**：
  1. 在**共享 A100** 上独立部署 `RLDX-1-FT-RC365` 服务（占 ~14 GB 显存），开发机 **5090** 只跑 RoboCasa 仿真（占 ~1.3 GB 显存，不动 17 GB 的 BEHAVIOR 常驻进程）。
  2. 克隆 `RLinf/RPent`，注释掉 `task_progress`、`dump_success_criteria` 和 `success` 字段，接入主图+腕部图+本体读数。
  3. 用**单次调用极简循环**替代旧 v2 的五模块：每步 1 次 API 调用，输出 `{step_verification, state_ledger_update, thought, action_call}`。
* **先量什么、跑多少次**：
  - 从 Target50 挑 **8 个官方任务**：**2 个原子任务** + **3 个见过组合** + **3 个没见过组合**（重点挑含开关门、跨容器转移、需多步确认的任务），每任务固定 **3 个种子（seed 1–3）** = **24 个 episode/组**。

    1. `No-Memory`（仅当前主图/腕图 + 上一步动作反馈）；
    2. `Sliding-Window`（最近 5 轮图像摘要与动作流，回应 Gemini 批评的简单基线）；
    3. `Structured-Ledger MVP`（结构化状态账本：子任务状态+证据来源+空间视点+本体受阻记录）。
  - **测量指标**：① 官方离线 `_check_success()` 成功率；② 过早结束率与已成未停率；③ 连续重复失败率；④ 平均轮数与耗时。
* **通过标准**：
  - 72 个 episode 零程序异常、输入审计确认 0 特权信号泄漏；
  - 原子任务成功率 ≥ 4/6；组合任务（18 次/组）上，`Structured-Ledger MVP` 成功率超过 RLDX-1 裸策略（>25%），且比 `No-Memory` 高出 **≥ 3 个成功回合（+16.7%）**，或过早结束率/卡死率降低 ≥ 30%。
* **时间和钱估算**（基于单轮 `rldx_skill` 2–5 秒 + API 3–5 秒 ≈ 10 秒/轮，平均 15 轮/episode）：
  - **时间**：工程改造 1–1.5 天；72 个 episode 实跑约 **3–3.5 小时**。**3 天内可拿齐完整数据**。
  - **API 成本**（单轮约 2500 输入 + 300 输出 tokens，85 个 episode 约 1300 次调用）：
    - 用 Qwen-VL-Max / DeepSeek：**约 15–30 元人民币（$2–$4）**；
    - 用 Claude Sonnet / GPT-4o 级别：**约 $15–$25 美元**。
    - 推算整个课题到第一篇论文投出（约 3000–4000 个 episode，含多轮消融与全量 Target50 评测），总 API 预算在 **$150–$350 美元（1000–2500 元人民币）** 量级（API 定价按当前主流公开价格估算，未联网逐家重核最新折扣）。

**5. 怎么给后面的研究留出余地**

不再用“四个独立模型盲写四个库”，而是改为**“单一证据状态账本（Evidence-Backed State Ledger）的四个逻辑切片”**：
* **Task & World & 主线一（可修订的决策充分上下文）**：
  - 去掉特权 `task_progress` 后，`rldx_skill` 经常出现“动作执行完但实际没抓稳/没放进/门弹回”的假完成。
  - 账本在 World 和 Task 切片中强制记录 `结论 + 支持证据(主图/腕图/仅技能回执) + 依赖该结论的后续子任务`。当后续观测推翻前序假设时，可直接测试“带证据结构的局部修订” vs “普通文本摘要”（完美落地 04-用户的几个想法.md 主线一）。
* **Body & 主线二（面向未来可观测性的记忆与行动协同）**：
  - Body 切片记录底盘/躯干位姿、手臂遮挡状态、视角可达性。在关门、放入深容器、或手臂遮挡视野前，规划器要在“直接调 `rldx_skill` 推进任务 ($a_t$)”与“先调身体/手腕相机确认并写入记忆 ($v_t, w_t$)”之间做权衡，将**身体信息**与**主线二**自然融为一体。
* **Experience（回合内与跨回合）**：
  - **回合内**记刚发生的失败-恢复对（如“直接抓取失败 → 升躯干 0.2m 后成功”）；**跨回合**直接复用 RPent 的 `seed 0` 探索机制，把提炼出的布局/操作先验存入 Experience，合规申报后既能测纯回合内记忆，也能测跨回合经验兑现。
* **平台分工**：**AI2-THOR 建议直接停用**（无真实本体且指物噪声大，已无增量价值）；等 RoboCasa 上主线一/二跑出干净结论后，抽 2–3 个任务到 **BEHAVIOR** 做全物理本体的上位验证。

**6. 最大的三个风险与更简单的做法**

* **最大的三个风险**：
  1. **去特权后 VLA 盲跑成功率坍塌**：没有 `task_progress` 兜底时，规划器看不出细微操作失败（如水龙头没拧开、物体差 2cm 入位）。*对策*：每次动作后强制同时给主相机+手腕相机前后对比图及夹爪宽度变化，允许连续失败 2 次时退回 RPent 底层移动/抓取原语微调。
  2. **部分官方组合任务“当前画面即马尔可夫”，无需长程记忆**：如果看一眼当前台面就知道下一步干什么，`No-Memory` 也会跑得很好。*对策*：选任务时专门挑含**容器闭合遮挡（关门后看不见内部）**或**历史过程状态（洗过/热过与否外观难辨，必须靠历史证据账本区分）**的组合任务。

**a. 技能接口的粒度与身体动作边界**

**b. 技能的反馈：真机感知边界**
