## 一、项目背景

- **人**：一名博士生，三年级末，两年内要出约 3 篇论文；一个人，加三个开发用的 Codex 会话，导师放手不管。
- **方向**（1102 和导师定）：长程具身任务里，模型怎样理解并利用"身体—空间—物体"之间的关系来做规划。
- **平台**：RoboCasa365。机器人是 PandaOmron：轮式底盘、升降躯干、七轴手臂。用两个官方任务：PrepareCoffee、SteamInMicrowave。
- **动作**：语义工具，有 pick、open、close、put、press、move_base、set_torso；不用 VLA。
- **模型**：
  - GPT-6-Astra 当强参照，用最低推理档，每月预算 200–400 美元；
  - Qwen3-VL-8B 在本地 RTX 5090 上跑；
  - deepseek-flash；
  - 全部冻结，不训练。用户认为"训练小模型本质上是在刷榜"。
  - 规划器不开推理。1031 定的最终目标是让小模型也能规划好。
- **规矩**：
  - 仿真真值和分数不进模型输入；
  - 识别用现成的 SAM 3.1，去掉落在机器人自己身上的块，再由用户只看原图人工核对可见标号。

## 三、要审的方案

方案 = GPT 的路线 + 用户 1105 的决定 + Claude 的调整。

**主线**：用户 1105 的原话是："核心肯定是动态更新的，我们的核心就是连续变化的规划"；"把故事讲好就是一篇不错的工作"。

一句话：机器人一边动，处境一边变（移动、调躯干、拿起东西、东西被挡住）。把身体、空间、物体的信息按机器人当前的身体整理好，并随动作及时更新，看冻结的小模型能不能连续几步都做对，最后把任务做完。

| 步 | 做什么 | 回答什么 |
|---|---|---|
| 0（正在做） | 差距测量第二版：4 对、8 个成对状态（远近两对、挡不挡、躯干高度）。输入两种：A 是编号图加身体参数；B 再在每个编号旁写前、左、高三个距离，身体参数里给出肩膀的位置。请求两种："直接选动作"和"先分析再选"。三个模型都跑 | 处境变了，模型的判断和动作跟不跟着变 |
| 1 | 成对诊断扩到约 24 对，覆盖距离、高度、通路、手里有东西。加一种"只问关系"的请求。加对照 D：直接给程序算好的"够不够得着"（PhysVLM 式） | 小模型错在关系还是错在动作；成对的两题都做对的比例 |
| 1b | 自然发生率：跑几回合闭环，数一数任务中段有多少次落进"够不着、被挡、躯干不对"的状态 | 这个问题在正常任务里有多常见 |
| 2 | 静态组织，当作地基。A→B 看多给信息的收益；B→C 看换种给法的收益。C 按当前身体当参照，同一个物体的信息打包在一起，并标明来源 | 换种给法有没有额外收益 |
| 3（核心） | 3–5 步的短闭环，三类片段：靠近后再抓；调完身体再操作；操作后目标被挡住。比较"普通的最近几步窗口"和"我们的方法"。两者用同一段历史；我们的方法按当前身体重新换算，并标明哪些是现在看到的、哪些是按里程计推算的 | 动了以后还能不能用对；用过期关系、重复失败的次数有没有减少 |
| 4 | 完整任务，分自然组和约束组。Qwen 跑三种：最近几步窗口、开发集上最强的简单方案、我们的方法。GPT-6 在固定的子集上跑两种 | 成功率提高多少，花多少钱 |
| 5 | 新厨房、新任务、检测器的原始输出、第二个小模型 | 能不能推广 |

**资源和节奏**：
- 一轮实验（写说明 → 开发用的 Codex 实现 → 写报告）通常要 1–2 天；
- GPT 原计划 1–2 周出 MVP，4–6 周出完整证据。
