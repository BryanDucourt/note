**1．核心论点：问题清楚，方法贡献尚未清楚。**

目前这句话——“机器人动了以后，及时更新身体、空间和物体的信息，让小模型连续做对”——清楚，也可以检验。但它覆盖了机器人系统中很常见的状态维护工作。“动态更新”本身还不足以构成新意。

我建议把核心主张收紧为：

> 在相同的观测、动作反馈和推理预算下，根据动作实际结果，更新物体相对身体的位置证据，并处理已经失效的历史记录，比近期窗口、常规对象状态表和在线可达性接口更可靠地支持连续决策。

这句话留下了明确的失败条件：常规状态表已经同样有效，或者直接给可达性更好且成本更低，都会削弱方法贡献。

与相关工作的具体关系是：

| 工作 | 已经覆盖的部分 | 你们还可能做出的贡献 |
|---|---|---|
| **PhysVLM** | §3.1 用运动学工作空间和深度生成 S-P Map；§4.4 已评估需要先靠近的任务规划。API 模型加图的结果在问答表中，规划表没有对应对照 | 同一份证据下，动作、遮挡和执行偏差之后怎样维护有效状态；以及这种维护对冻结小模型连续决策的作用 |

| **DovSG** | §III-D 已根据新 RGB-D 删除过期内容、更新受影响对象及关系；§IV 在动态环境中评估连续移动操作 | 身体相关证据的更新与失效处理，以及在严格同输入条件下对小模型决策的收益 |

**DovSG 是当前路线必须补上的比较对象。** 它与“动态更新”的核心主张比单纯问答工作更接近。不过，它的场景更新实验与这里的身体关系诊断仍有区别，研究空间还在。

**2．实验设计：四个关键问题需要这样处理。**

**A/B/C 目前分开了一部分信息收益，但 B→C 仍混合了多项变化。**

原文已经明确承认程序承担坐标计算，这点写得对。问题在于 C 同时改变了参照系、信息打包方式和来源表达，最终很难知道哪部分有效。

而且，[第二版输入说明](/Volumes/2T/note/Work/长程上下文/实验/1104-模型差距测量/1105-模型差距测量-成对状态说明.md:82)里的 B 已经提供底盘参照下的前、左、高和肩膀位置。C 如果改成相对肩膀坐标，新增计算可能只是几个减法。收益可以有，但贡献应据此衡量。

建议诊断阶段用以下设置：

| 条件 | 唯一主要变化 |
|---|---|
| A | 编号图及共同的身体、任务、工具信息 |
| B | 增加底盘参照下的物体测量 |
| B′ | 将同一测量换算到肩膀参照，保留普通列表 |
| C | 使用 B′ 的相同数值，改成按物体组织 |

来源、时间、对象身份等信息在 B/B′/C 中保持一致。这样 A→B 测增加测量的效果，B→B′ 测代做坐标计算的效果，B′→C 测组织方式的效果。无需强行补齐 token 数，但要避免某组因长度被截断。

动态部分还要单独做：**固定 C 的组织方式，比较不同更新方式。** “停止历史更新”可以作为消融；主竞争对手应包含正常工作的动态状态表。

另外，[原文短闭环设计](/Volumes/2T/note/Work/长程上下文/会审/1105-GPT论文路线设计/1105-GPT论文路线设计-原文.md:229)中的“同一段历史”需要分两种实验：

- 固定轨迹重放：各方法拿到完全相同的历史，分析更新机制。
- 自由闭环：各方法从相同存档开始，随后动作和历史自然分叉，比较任务后果。

自由闭环走出不同轨迹之后，双方历史就已经不同了。

**D 很可能打败我们，必须尽早测，而且要让它每步更新。**

这里首先要明确“够得着”的含义。PhysVLM 式工作空间判断回答的是目标是否落在运动学可达区域。碰撞、抓取姿态、手的占用、容器是否打开，还需要其他判断。不能把一个范围标记直接当成完整的 `pick` 成功判定。

公平的 D 应当：

- 使用与我们相同的观测和身体参数；
- 每步重算；
- 保留共同输入，再增加可达性结果；
- 对信息不足的情况允许返回未知；
- 计入其计算成本。

用隐藏物体位姿或离线执行答案生成 D，会违反你们现有输入规则；这些真值留在评分端。

D 胜出后的判断如下：

| 结果 | 论文是否成立 |
|---|---|
| D 在静态题更好，我们在历史依赖的连续执行中更好 | 动态更新主张可以成立 |
| D 与我们相当，我们有明确的成本或鲁棒性优势 | 可以成立，但需要相应证据 |
| D 加我们的更新优于 D | 可以转为“更新模块改善几何接口”的贡献，需要调整方法边界 |
| 在线 D 在主要任务上更好，成本也更低 | 当前方法主张基本失败；剩余诊断结果需要另行评估论文价值 |

把关系判断留给模型，是研究选择。审稿人仍会比较程序直接处理这部分工作的实际效果。

**“用了过期关系”不能直接从失败动作或模型解释中计数。**

建议分清三个对象：系统提供了过期记录、动作符合过期状态、更新干预减少了错误。这三件事分别统计。

一个可计数的“关系失效事件”至少满足：

1. 先前记录在当时有效。
2. 后续动作使相关状态发生了足以影响决策的变化。
3. 截至决策时，允许提供的观测或反馈已经足以支持修订。
4. 旧状态与当前状态对候选动作的要求存在可区分的差异。

例如，移动已经完成且实际位移可知，目标从范围外进入范围内；模型继续执行仅在旧距离下必要的靠近动作，可以记为“与过期状态相符的错误动作”。如果两种状态下这个动作都合理，就保留为无法归因。

建议主统计采用：

\[
\text{过期状态相容错误率}
=
\frac{\text{失效事件后，首次相关决策出现上述错误的事件数}}
{\text{满足定义的关系失效事件数}}
\]

一个事件引发连续四次失败，事件数计一次，后续重复失败另计三次，并报告错误持续了几步。分母和排除理由都公开。

要进一步支持原因归属，在固定存档和历史上，仅切换历史记录的更新处理，其余输入保持一致。更新内容必须由允许的证据推导。比较错误率是否下降。模型自行写出的理由可以辅助查案例，主标签应由状态、动作和预先定义的规则决定。

**“自然发生率”应前移做小样本摸底，最后再正式报告。**

放在基本工具可用之后、扩建大诊断集和投入完整方法之前合适。原来的 1b 位置基本合理，但“跑几回合”需要明确策略和分母。

要数两种事件：

- 任务中出现需要调整身体或解除阻挡的情况；
- 动作之后旧记录失效，后续决策需要正确修订的情况。

第二种更直接对应动态更新。

用固定基线跑官方采样起点，再用参考策略走同批起点，区分任务本身带来的约束与差策略造成的困境。报告每回合至少遇到一次的比例、每回合独立事件数，以及提前失败的回合数；连续重试不要制造多个“自然事件”。

正式实验再在自然任务组报告各方法的结果。约束组用于检验指定能力，单独呈现。

**3．最严重的五个问题。**

| 问题与依据 | 后果 | 改法与解决条件 |

| **① 动态更新还停留在功能描述。** 方案写了换算、来源和抓取反馈，但没定义记录何时传播、覆盖、保留或失效 | 最终容易成为常规坐标变换加对象表，方法新意偏弱 | 写出少量明确规则，并与普通动态状态表比较。若两者做法和效果相同，应接受贡献较薄的判断 |

第④点是明确的评分漏洞，见[第二版第六节](/Volumes/2T/note/Work/长程上下文/实验/1104-模型差距测量/1105-模型差距测量-成对状态说明.md:120)。优先修它，否则后续“成对两边都做对”的解释会出问题。

第③点还涉及一个信息边界：物体的三个坐标适合判断位置关系，手臂通路是否受阻还依赖障碍几何。需要写清这部分由图像判断、局部几何输入，还是执行反馈承担。

**4．资源条件下，最小可信的实验集合。**

我会让 Qwen 承担主要证据，GPT 做固定子集参照，避免把全部“模型 × 输入 × 请求方式”搬进完整任务。

| 实验包 | 建议规模 | 核心比较与目的 |
|---|---|---|
| 自然分布摸底 | 12 个官方起点，两个任务各 6；固定基线和参考策略各跑一次 | 估计问题是否经常出现，定位工具问题 |
| 静态诊断 | 开发集另设；正式约 24 对，四类各 6 对 | A/B/B′/C/D；主要直接选动作，关系题与先分析条件放小子集 |
| 动态机制实验 | 72 个短片段起点，三类各 24，覆盖多个留出厨房 | 当前观测、近期窗口、普通状态表、在线 D、我们；固定子集做更新消融 |

这些数量是**判断较大效果的起点**。如果完整任务仅多成功两三局，应该扩大独立实例，暂缓强结论。24 对也很难单独承担一篇顶会论文的证据量。

短闭环里必须包含：

- 当前观测足够的情况；
- 需要历史及动作反馈的情况；
- 身体发生变化、关键操作条件却保持不变的情况。

最后一类用于检查方法是否过度更新、制造多余动作。

GPT 可以控制为：24 个诊断状态的关键条件、12 个短闭环起点、12 个完整任务实例。先用实际调用成本估算总量，给一轮主要参照预留约 **80–120 美元**；预算紧时削减 GPT 重复和辅助条件，保留本地实验的强基线及独立实例数量。这是预算安排，未采用未经核实的单次价格。

确定性本地调用没有必要机械重复五次。随机模型在固定子集上重复，统计仍以任务实例为单位。第二个小模型可以顺序加载，无需同时占 GPU。

按每轮 1–2 天，主要证据大约需要 8–10 轮，另加工具修复、造起点和人工核验时间。原文的 4–6 周有实现可能，但前提是工具和数据生产很快稳定。

**5．我一定会要求的基线和指标。**

必需基线如下；细消融集中在诊断和短闭环即可。

| 基线 | 要排除的解释 |
|---|---|
| 当前观测＋相同的结构化测量，不保留历史 | 每步重新看一遍已经够用 |
| 最近几步窗口，包含相同反馈和测量 | 普通历史输入已经够用 |
| 常规对象状态表：新观测覆盖、正常运动学传播、必要的持物状态维护 | 标准状态维护已经实现主要收益 |
| 每步重算的 D | 直接提供几何判断更有效 |
| 相同表示下，去掉历史传播或失效处理 | 更新组件没有独立作用 |
| 简单距离规则、先判断关系再选动作 | 题目可被固定套路解决，或简单提示已经足够 |

常规状态表应认真实现。如果它与“我们的方法”几乎一样，就需要重新界定方法贡献。与 DovSG 等工作的适配比较，应清楚标注改动，避免把简化版写成完整复现。

我会要求的指标是：

- **主要结果：** 固定动作预算下的短片段完成率、完整任务成功率，自然组和约束组分别报告。
- **条件响应：** 配对两边正确率、关系变化后动作是否适当调整、无关变化后的多余动作率。
- **更新质量：** 过期状态相容错误率、错误持续步数、更新干预带来的错误率变化；需要时记录对象关联错误。
- **行为代价：** 重复失败、无进展动作、重新观察和恢复动作数量。
- **系统成本：** 所有模型调用与 token、更新计算时间、感知时间、总决策等待时间。
- **结果可信度：** 各方法在同一实例上的胜负、置信区间、逐厨房结果。重复调用和同一轨迹中的多步要保留其相关性。

动作效率还要覆盖失败回合，例如固定预算内的进展和达到子目标的步数分布。仅统计成功回合，容易让成功较少的方法显得更省动作。
