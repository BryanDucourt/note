### 先直接指出现有计划与背景中的 6 个核心问题

在回答八个问题前，必须先挑破你们当前方案里的结构性矛盾：

1. **把"单帧视觉感知缺陷"当成了"上下文问题"来修（方向跑偏的根源）**
   背景中 10-22 草案把 **M3（同一个模型在同一视角下犯同一种错）** 与现象 3（把吊柜部件认成刀、放大到 800×800 仍认错）、现象 9（顺视线方向 900 像素也认不出刀）列为核心问题，并花了一周做分块放大和复核。**依据**：如果给模型只看当前单张图、完全不给历史上下文，它依然认错，这100%是 DeepSeek Flash 视觉编码器的单帧感知盲区，跟上下文和记忆毫无关系。用记忆工程去补单帧视觉盲区，既发不了记忆论文，也发不了感知论文。
2. **`A → B（刀）→ A` 是伪长程任务，根本测不出上下文与压缩**
   **依据**：全流程只有两个物体，从 B 回到 A 只需要记住几步前的 1 个位置槽位。现象 10 已经证明"4–8 次决策就完成，几乎用不到记忆"。即便强行拼成 `A→B→A`，只要保留"最近几次执行的事实"，哪怕把 Object 和 Spatial 记忆库全删了也能完成【推断】，无法支撑导师关注的"上下文组织与压缩"。
3. **机器人全身防护（距障碍 >1.2m）与小目标（刀）物理冲突**
   **依据**：现象 9 表明刀小于 200 像素基本认不出，而全身防护限制机器人停在 1.2m 外，导致刀长期处于感知临界点以下。此时系统被大量单帧假阴性淹没，根本分不清是"上下文压制了识别"还是"物理距离太远看不清"。
4. **带着严重的工程与提示词脏数据做机制归因**
   **依据**：现象 6 中"提示词与代码校验冲突导致 6 轮里 3 轮一步没走"、"判断结论在规划器输入里重复出现 3 次"，这些属于明确的工程实现 bug。不先冻结并清理这些人为 bug，测出来的所谓"错误持续"全是代码噪声。
5. **全链路耦合单一轻量模型（DeepSeek Flash）**
   **依据**：规划、判断、两个记忆库全部使用同一个弱多模态模型，无法区分"多模块上下文架构的通病"与"DeepSeek Flash 的特定指令遵循/视觉偏见"。
6. **高估在线分叉（E2）的可行性，忽视仿真步进的时间成本**
   **依据**：单轮 30–40 分钟且 70% 是物理步进，OmniGibson 的 `dump_state/load_state` 尚未打通【推断：Isaac Sim 刚体与控制器状态热恢复极易出现非确定性抖动或报错】。在博士三年级末追求短迭代的条件下，重度依赖在线分叉会拖垮实验进度。

### 1. 研究问题

* **论文线（3 篇连贯主线）**：在受限上下文预算的长程具身任务中，多模态历史观测在**写入、跨模块传递与动态压缩**过程中会产生哪些结构性失真，这些失真如何通过闭环动作放大为规划与执行故障，以及如何围绕下游决策效用对具身上下文进行保真组织与压缩。
* **论文 1 的研究问题**：在多模块分库的具身闭环搜索中，**剥离掉单帧视觉盲区后**，历史上下文中的"无条件否定覆写、跨运动参考系失配、多跳同源回音"在何时以及如何覆盖当前有效观测并锁死规划/验证？如何通过**观测条件化与证据解耦的上下文协议**阻断错误持续？
* **为什么它是具身特有的（而非文本智能体已解决的）**：
  1. **证据受物理观测条件严格约束**：文本 RAG 中"段落 X 无答案"是静态事实；具身环境中"未见物体 B"只是**特定距离、视角、遮挡下的局部条件观测**。一旦上下文压缩丢掉观测条件（写成"台面无刀"），就会把"当前看不清（absence of evidence）"变成"物理不存在（evidence of absence）"（现象 4、9）。
  2. **参考系随本体运动实时失效**：文本实体指代不随推理步数改变；具身智能体每移动一步，旧帧上的 2D 像素框和相对方位在新帧中立即失配（现象 2、7）。
  3. **上下文污染直接改变未来数据采样（主动感知死锁）**：文本问答错了不影响下一轮检索静态语料库；具身规划器一旦被污染的上下文误导（如跳过某区域或停在错误位姿），机器人物理轨迹改变，**后续根本采集不到能纠错的新视野**，形成"上下文偏差 → 位姿偏差 → 观测缺失 → 错误固化"的闭环死锁。

### 2. 怎么判定"上下文问题"（离线可执行的严格分流规则）

记第 t 步当前原始图像为 O_t，输入给模块 M（Planner / Object / Verifier）的历史上下文为 C_t，模块输出为 Y(M, O_t, C_t)，离线评估端真值为 A5_t（真实像素数 px_t、可见比例 vis_t、真实 3D 框）。按以下三步流水线离线自动判定：

1. **第一步：排除工程实现与规则 Bug（Implementation Bug）**
   * 检查第 t 步落盘的提示词原文与代码校验器日志。若存在：（a）字段在序列化时被代码丢弃（现象 5）；（b）模型输出符合提示词要求但被硬编码规则拦截（现象 6a）；（c）同一结论在单次输入模板中被重复拼接（现象 6c）。直接归类为 **工程 Bug**，修复代码，不计入研究现象。
2. **第二步：剥离物理不可见与单帧感知错误（Perception Error）**
   * **物理不可见（Observability Limit）**：若 A5_t 显示目标 px_t < τ_px（如 200 像素）或 vis_t < 0.2，此时任何漏检均归为**物理视角受限**。
   * **单帧感知错误（Single-Frame Perception Failure）**：若 A5_t 显示目标清晰可见（px_t ≥ τ_px），且实际运行 Y(M, O_t, C_t) 出错。对该步执行**离线零上下文反事实探针（Zero-Context Probe）**，即构造 C_t = ∅（只给当前帧 O_t 和任务目标，清空历史记录与跨模块框）。若 Y(M, O_t, ∅) **依然出错**（如现象 3 把吊柜认成刀、现象 9 顺视线认不出），则严格判定为 **单帧感知错误**。
3. **第三步：确诊真正的上下文问题（True Context Problem）**
   只有满足以下三种可检验条件之一，才判定为**上下文问题**：
   * **类型 A（上下文压制当前感知）**：A5_t 判定当前帧可见，**零上下文探针 Y(M, O_t, ∅) 正确，但带完整上下文 Y(M, O_t, C_t) 错误**（如现象 4：旧记录"不在视野"压制当前帧中的可见目标）。
   * **类型 B（跨模块上下文污染）**：模块 M_2 在 C_t 包含上游模块 M_1 传递的附加条件（如 Planner 抄入的 Object 偏框、动作历史中的错误归因）时出错；离线将 C_t 中该上游附加字段置空或替换为中性语义后，Y(M_2, O_t, C'_t) 变正确（对应现象 2、7）。
   * **类型 C（长程证据遗失/覆写导致决策退化）**：当前帧 O_t 无目标，但 A5_{1..t-1} 证实目标曾在第 k 步清晰可见（px_k ≥ τ_px 且 Y(Object, O_k, ∅) 可认出），但在第 t 步的 C_t 中该证据被后续低质观测覆写或被封顶策略淘汰，导致 Planner 重复搜索已去过的区域。

| :--- | :--- | :--- | :--- |
| **1（最高）** | **无条件负向记忆覆写**<br>*(Unconditioned Negative Overwrite)* | 远距离/差视角下未检出 → Object 将"当前不可见"写成无条件否定（"台面没刀"） → ① 后续靠近后 Object 沿用旧结论压制新图（现象 4）；② Planner 排除该区域不再靠近，永久丧失获取高分辨率观测的机会。 | **已有明确迹象**（现象 4、9）。是最稳、最易用反事实探针量化的核心机制。 |
| **2（高）** | **跨运动参考系失配与代理坐标传递**<br>*(Motion-Induced Frame Misalignment)* | Object 在旧帧画出偏框或局部区域 → 机器人移动后参考系已变，或 Planner 将该 2D 框直接冻结传给 Verifier → Verifier 核查墙面/错位区域（现象 2）或导航动作对不准（现象 7） → 陷入原地观察或验证死循环。 | **已有明确迹象**（现象 2、7）。极具具身特色，直接解释为什么"判断独立了还会一起错"。 |
| **3（中）** | **跨步隐式回音室**<br>*(Multi-Hop Echo Chamber)* | 分库虽消除了单步写四库（现象 1），但单次猜测同时进入 Object 库 + Planner"最近执行事实" + Verifier 反馈（现象 6c） → 下一轮在 Planner 输入中形成跨槽位重复曝光 → 触发副本效应（Copies-as-Sources），使规划器过早锁死错误假设。 | **已有静态迹象**（现象 1、6c）；跨时间步的动态放大需在 >15 步任务中测出。 |

### 4. 实验方案

#### （1）任务设计：用"多目标顺序检索 + 偶遇复用"替代 `A→B(刀)→A`
* 在 `make_pizza` 场景中，先用 A5 + 零上下文探针筛选出 **4–5 个在 1.2–1.8m 距离下像素 >400 px、单帧识别率 >80% 的中大物体**（如特定碗、奶酪盒、烤盘、砧板等【推断：该场景包含多个此类厨房物体】）。
* 设计每轮含 **4 个连续子目标** 的任务 `T1 → T2 → T3 → T4`（上限 40 步）：
  * 其中 `T1、T2` 需要主动探索；
  * `T3` 布置在寻找 `T1` 时的必经视野内（测**偶遇记忆留存与复用**）；
  * `T4` 需要基于已找到的 `T1` 和 `T3` 的空间关系做二次确认或回到 `T1` 附近（测**长程保真与防覆写**）。
* **依据**：把单轮有效步数拉长到 20–35 步，强制让无记忆基线失败，同时彻底绕开"1.2m 外看不清小刀"的感知死胡同。

#### （2）对照条件
* **上下文机制对照（4 组，均在修好现象 5、6 的工程 bug 后运行）**：
  1. `Sliding-Window (No Memory DB)`：只保留当前帧、上一帧和最近 3 步动作（验证任务确实依赖长程记忆）。
  2. `Unconditioned Memory (Baseline)`：现行分库架构，允许写入无条件正/负结论，Planner 可传递参考框给 Verifier。
  3. `Observation-Conditioned & Decoupled Context (Ours)`：包含三项轻量机制：① **观测条件化写入**（每条 Object/Spatial 记录强制带 `(dist_bin, view_quality, frame_id)` 字段，远距离/边缘视野下的未检出只能记为 `unverified_at_far_view`，禁止覆写高置信度记录）；② **跨模块证据解耦**（Planner 向 Verifier 只传语义目标与粗粒度容器名，禁止传递 2D 像素框；去除同源重复字段）；③ **运动失效降级**（一旦发生平移/旋转动作，旧帧局部区域指代自动标记为 `stale_2d_frame`）。
  4. `Oracle-Filtered Context (Upper Bound)`：仅在离线分析中使用 A5 拦截错误写入，给出上下文修复的理论上限。
* **模型对照（2 组）**：在线跑 DeepSeek Flash；在离线单步回放（及少量在线验证）中加入 **1 个强多模态模型（如 Qwen2.5-VL-72B 或 GPT-4o）**，回应审稿人对单一弱模型的质疑。

#### （3）测量指标
1. **端到端闭环指标**：子目标完成率（Sub-goal SR）、平均每目标耗用步数（Steps-per-Target）、无效重访率（对已清晰观测区域的重复探索步数占比）。
2. **上下文机制诊断指标（由 A5 + 离线探针自动算出）**：
   * **上下文压制率（CSR）**：Pr(Y(O_t, C_t) 错 | A5_t 可见 ∧ Y(O_t, ∅) 对)；
   * **跨模块污染率（CMPR）**：剥离上游传递框/重复结论后下游判断从错变对的比例；
   * **偶遇命中率（Incidental Hit Rate）**：切换到子目标 T_3 后 ≤ 3 步内直接导航成功的比例。

#### （4）因果设计：离线单步反事实为主 + 受控记忆注入闭环为辅
* **依据**：在线跑一轮要 30–40 分钟（70% 物理步进），而离线改上下文重跑单步 API 只需 3–5 秒，**效率相差 500 倍**。
* **第一层（离线单步反事实矩阵，主力归因）**：从基线在线跑出的轨迹中抽取 200 个关键决策断面（固定当前图 O_t），做配对反事实干预（自然发生的错误清理 + 人为注入远距离否定/偏框/重复副本），直接测量模块下一步输出的**动作/判断翻转率（Flip Rate）**。
* **第二层（在线闭环后果）**：给 `dump_state/load_state` 最多 **2 天** 调试期。若跑通，挑 15 个分叉点续跑 10 步；若卡在物理引擎状态恢复 bug，**立即放弃状态恢复**，改用**固定起点 + 开局注入受控先验记忆（Seeding Contaminated vs Conditioned Memory）**跑在线闭环，同样能严格证明上下文错误对后续 20 步轨迹的因果影响。

#### （5）样本量与成本估算
* **离线反事实实验**：200 个断面 × 4 种上下文条件 × 2 个模型 = 1,600 次 API 调用（约 3,400 万 token），耗时 **< 3 小时**，零物理仿真成本。
* **在线闭环实验**：核实并构造 5 个不同物体摆放/起点实例 × 3 个在线对照条件 × 每实例 3 次独立任务组合 = **45 轮在线运行**（每轮限 35 步，约 25 分钟），总计约 **19 小时仿真时间**（2 天内跑完）。

#### （6）前 4 周执行顺序与决策点
* **第 1 周：清理工程 Bug + 筛选目标物体 + 跑通离线探针**
  * 修掉现象 6 的所有冲突与重复拼接；核实场景实例差异；用 A5 筛选出 5 个单帧识别率 >80% 的目标物体。
  * **决策点 1（第 7 天）**：在历史日志上跑零上下文探针。确认修掉工程 bug 后，CSR 和 CMPR 在自然轨迹中占比是否显著（>15%）。
* **第 2 周：采集多目标基线轨迹 + 跑完 1,600 次离线反事实矩阵**
  * 跑完 15 轮 `Baseline` 在线多目标轨迹；限时 2 天测试 `dump_state`。完成 Flash 与强模型的离线反事实实验。
  * **决策点 2（第 14 天）**：若 `dump_state` 未完全稳定，立即锁定"开局记忆注入"方案；根据离线翻转率确定 `Ours` 中哪两项子机制贡献最大。
* **第 3 周：实现 `Ours` 上下文协议 + 跑完 45 轮在线闭环对比**
  * 在线跑完 `Sliding-Window`、`Baseline`、`Ours` 三组多目标实验，导出全部 A5 诊断指标。
  * **决策点 3（第 21 天）**：若跨场景审稿风险高，花 3 天在 OmniGibson 第二个厨房/客厅场景补跑 15 轮轻量验证。
* **第 4 周：Token 预算消融（2.1w vs 1w vs 5k）+ 论文图表与初稿撰写**。

### 5. 取舍：保留什么、砍掉什么、刀还要不要？

* **坚决砍掉**：
  1. **所有针对"刀"的视觉增强补丁**（分块放大、放大复核、对比式提问调参）——全部停掉，不再花一分钟；
  2. **把 M3（同模型同视角重复视觉错误）作为上下文机制**——移出核心贡献，只在实验设置里作为通过 A5 过滤掉的感知背景噪声说明。
* **推后到后续论文**：
  1. **接入 π0.5 操作策略**（推后到论文 3）；
  2. **模型微调/训练**（不符合单人短迭代优势）。
* **保留并强化**：
  1. **A5 离线真值评估端**（这是你们最核心的实验武器，用来严格分离感知错误与上下文错误）；
  2. **Object / Spatial 分库与 2.1 万 token 预算封顶**；
  3. **M1（跨模块传递）与 M2（低分辨率否定压制）**，升级为包含运动参考系失配与多目标偶遇复用的完整设计。
* **刀还要不要当目标？**
  * **不能再作为主目标或唯一瓶颈目标**。在 4 目标序列任务中，要么全部使用单帧识别率 >80% 的中大厨具/容器，要么最多把"侧面摆放、A5 确认在 1.5m 处 >300 像素可认"的刀作为 4 个子目标里的普通一环。绝不能让视觉盲区再卡住实验。

### 6. 论文 1 的类型、投稿去向与拒稿防御

* **论文类型**：**"实证诊断 + 轻量机制修复（60% 诊断归因 + 40% 免训练上下文协议）"**。
  * **依据**：单人无训练经验，纯方法型论文会被要求在多个基准上刷 SOTA；纯诊断分析在机器人会议容易因"没有闭环改进"被拒。"用 A5 + 反事实探针严格剥离感知与上下文误差 + 提出观测条件化与解耦协议显著提升闭环成功率"攻守兼备。
* **投稿目标**：**CoRL / IROS / ICRA** 或 **NeurIPS / ICLR（Embodied AI 方向）**。
* **最可能的 3 个拒稿理由与提前防御**：
  1. *质疑 1："把 VLM 看不清物体当成了记忆问题。"* → **防御**：将第 2 节的"A5 + 零上下文反事实探针分流准则"写成论文的方法论亮点，所有上下文指标均在证明"单帧能认出"的前提下统计。
  2. *质疑 2："只在 DeepSeek Flash 上成立，换强模型就没这问题。"* → **防御**：在离线 200 个反事实断面上展示 GPT-4o / Qwen2.5-VL-72B 的同向翻转结果，证明无条件负向覆写与参考系失配是上下文结构问题而非特定模型 bug。
  3. *质疑 3："单场景（make_pizza）只找物不操作，实验太单薄。"* → **防御**：通过 4 目标序列任务拉长决策步数至 25+ 步，并在第 3 周末补充 OmniGibson 中第 2 个场景的找物验证【推断：同模拟器换场景仅需改配置，成本远低于接操作策略】。

### 7. 后续论文：如何自然引出论文 2、3？

三篇论文共享同一套 OmniGibson + A5 评估底座，层层递进：
1. **论文 1（保真与解耦）**：在固定预算（2.1w token）下，解决**"写什么、怎么传才不会让历史污染当前闭环决策"**（观测条件化记忆 + 跨模块证据解耦）。
2. **论文 2（面向决策效用的具身上下文压缩，直击导师核心关注）**：将任务扩展到跨房间 8–10 个子目标（80+ 步），将上下文预算从 2.1w 极限压缩到 2k–4k token。研究**如何基于空间拓扑锚点与未来任务依赖，对多模态历史进行非均匀压缩与按需重取证（Recall vs. Re-observe）**。
3. **论文 3（操作介入下的非平稳世界记忆更新，接入已部署的 π0.5）**：当 π0.5 真正移动物体、打开容器或抓取失败时，静态记忆假设被打破。研究**物理交互引发的记忆过时检测、动作执行状态幻觉（AGM 问题）的闭环校验与修正**。

### 8. 撞车风险与差异化边界

1. **与 MobiAgent (CoRL 2026) 撞车风险（最高）**：
   * *风险点*：MobiAgent 已经指出了"验证器结论同时用于进度和规划历史会导致连锁错误"。
   * *规避方式*：MobiAgent 没有量化错误传递，也未区分单帧感知错误与上下文错误。你们必须突出 **A5 像素级真值 + 反事实剥离量化**，并把重点放在**视角/距离条件丢失（M2）与本体运动引发的参考系失配**，而不是单纯复述"验证器判错会连锁"。
2. **与 CMA (Zhang et al., 2026) / Copies or Sources (Gao 2026) 撞车风险（中高）**：
   * *风险点*：CMA 用反事实替换历史审计具身策略；Gao 研究重复副本导致过早下结论。
   * *规避方式*：CMA 针对的是端到端学习策略（VLA）的黑盒隐状态，你们针对的是**VLM 多模块显式上下文的跨模块组装失真与主动感知死锁**；正面引用这两篇作为理论工具，将你们定位为显式多模块具身记忆的诊断与修复。
3. **与 3D 场景图记忆工作撞车风险（如 ConceptGraphs [ICRA 2024，确定存在]、3D-Mem 等）**：
   * *风险点*：如果把方法包装成"建一个更准的物体空间记忆库来找物"，审稿人会直接问为什么不用 3D 几何建图（ConceptGraphs）。
   * *规避方式*：**绝不宣称贡献在于 3D 空间建图精度**，始终紧扣"受限上下文预算下，多模态历史记录的观测条件保真、跨模块解耦与错误阻断"。
