# memlens
## 结论

一句话：MemLens 想解决“记忆太多，该留哪些”的问题，办法是给每条记忆算一个“有多大用”的分数，只留高分的。思路可以参考，但论文没有拿出可信的实验结果。

对我们有两点用：

- 可以借它的打分方法，事后分析“哪些历史记录真正影响了机器人的决定”。
- 它暴露了一个坑：给每条记忆单独打分、再按分数筛选，会选错。我们设计“保留什么”时要避开。

它不是我们的竞争对手。直接拿到机器人任务里用也不行，需要大改。

## 论文做了什么

**要解决的问题**：AI 助手和用户聊得越久，存下的对话记录越多。全都存着，有用的信息会被淹没，查找也变慢、变贵。光看“和问题相不相关”也不够：两条记录可能说的是同一件事，留一条就够；也有两条记录单独看没用，合在一起才有用。

**做法**分三步：

1. **拆**：把对话拆成一句一句的小记录，再汇总成几层摘要。
2. **打分**：想知道一条记录有多大用，就看“有它”和“没它”时，一个小模型回答问题的质量差多少。因为记录之间会互相影响，所以要在很多种组合里反复比较，取平均。这种算法叫 Shapley 值。
3. **筛选和使用**：分数高于某条线的才留下；回答问题时，先找相关的记录，再把分数高的排在前面。

**怎么验证的**：作者自己用 AI 生成了 2000 多段模拟的学生对话，和“全部保存”“只存摘要”两种做法比较。

**新意在哪**：打分方法是现成的，新意在于把它用到了 AI 的记忆管理上，并做成了一套能看能用的系统。还要注意，算出来的分数取决于用什么问题、什么模型来测，不是记忆本身固定的属性。

## 实验结果靠得住吗

目前靠不住。论文说的效果都没法验证，我们去看了作者公开的代码，还发现了两处问题。

|   |   |
|---|---|
|论文怎么说|实际情况|
|效果比“全部保存”“只存摘要”都好|论文里没有给数字。代码里展示效果的图表，数据是手写的示例数，准确率直接写成 0.75、0.65、0.88|
|用 AI 评判回答质量来打分|代码里不是这样做的：它比的是两段摘要有多像，而不是回答得对不对|
|能推广到其他公开数据集|只说了一句，没有结果|

需要说明的是：

- 公开代码不一定就是作者做实验用的版本，所以不能说论文造假，只能说它的结论目前没法核实。
- “两段摘要像不像”和“能不能帮助做对决定”是两回事。用前者打分，测出来的是“这些记录能不能复述全部内容”。

## 方法本身的问题

就算实验没问题，方法本身还有几个坑，第一个最重要。

1. **单独打分再按分数筛选，会选错。** 举个例子：三条记录说的是同一件事，留一条就够了。但按它的算法，三条得分一样，要么都留、要么都删，留不下“刚好一条”。它会合并意思几乎一样的记录，能解决一部分；但如果几条信息必须一起留才有用，还是会出问题。
2. **没说清用什么问题来打分。** 分数是针对某个问题算的，但存记忆时还不知道以后会被问什么。这些分数能不能用到以后，论文没交代。
3. **不处理过时的记录。** 它有合并和更新的功能，但只按“意思像不像”判断，没有办法处理“旧信息已经不对了”或者“之前记错了”。
4. **算起来很贵。** 每条记录都要在很多组合里反复测，记录一多，调用模型的次数就很多。

## 能不能用在机器人任务上

要看记的是什么。记“经验”可以借鉴；记“任务进行到哪了”需要大改。

|   |   |   |
|---|---|---|
|记的是什么|能不能用|要改什么|
|用户习惯、操作经验、常见失败原因|比较适合|用后续任务做得好不好来打分|
|当前任务的状态：东西在哪、做到哪了、放成功没有|需要大改|每条记录要写清是什么时候、怎么知道的、有多确定；还要能处理东西被挪动、动作失败|
|决定按什么顺序做、什么时候再看一眼|打分的思路能用|打分时要考虑：换个顺序以后还能不能看到、再看一眼要花多少功夫、出错的后果有多严重|

机器人任务里的记忆，有三点和聊天记录不一样：

- **“做了”不等于“做成了”。** “执行了放置动作”和“看到东西确实放进了篮子”要分开记。如果记录本身就混在一起，打分再准也没用。
- **记忆的用处不只是“省得再看一次”。** 还要看记错了会有多大后果。有些事过去了就再也看不到，比如某个东西曾经被人挪过。
- **执行顺序会改变哪些记忆有用。** 拿组装礼品篮来说：一种物品一种物品地放，就得记住每个篮子放了什么；一个篮子一个篮子地放、蝴蝶结最后放，篮子里的东西一直看得见，这项记忆就没那么重要了。不过“哪些篮子已经放齐”“有没有放成功”还是得记。

## 对我们的用处

**一、借它的打分方法，事后分析机器人的决定。** 把“回答质量”换成仿真里的真实结果，比如决定做对没有、后来多花了多少步、多看了几次，就能在某个决策时刻算出：哪些历史记录真正影响了这个决定。用的时候要注意三点：

- 从同一个时刻出发，只换记忆，别的都不变。
- 删掉一条记录时，摘要里提到它的地方也要一起删，不然信息还在。
- 仿真器知道的“标准答案”只用来打分，不能给机器人看。

代价也要考虑：在 BEHAVIOR 上，每试一种组合都要跑一段仿真，很慢，只适合在少数关键时刻做。在我们自己写的简化环境里，试一次几乎不花时间，可以试着用它批量生成训练数据，但结果稳不稳定要先验证。

**二、避开它的坑：决定“留什么”时，要看整体，不能逐条打分。** 我们的系统也要在有限的空间里决定保留哪些记录。正确的问法是：“已经留了这些，再加这一条还有多大用？”而不是给每条单独打分再筛。像“哪个东西 + 在哪 + 放成功没有”这种要一起才有用的信息，更要这样处理。

**三、写论文时别把换个写法当成新意。** 把“记忆的价值”写成“随执行顺序变化的价值”，只是换了个说法，原方法本来就支持。我们真正的新东西应该是：提前预测不同的执行顺序需要记住什么，再一起决定先做什么、记什么、什么时候再看一眼；并用实验证明这样做比“固定顺序 + 好好记录”效果更好。

## 对计划的影响

- **G1 实验**：可以加上这种归因分析，只在少数关键时刻做。
- **方法设计**：决定保留什么时，按“再加这一条还有多大用”来选。
- **对比方法**：“逐条打分 + 按分数筛选”可以和“全部保存”“只存摘要”一起，作为对比的几种做法。
- **历史记录格式**：明确区分“做了什么”和“看到了什么”，每条都写清楚是怎么知道的。
- **论文卡片系统**：核对证据时加一步“看公开代码”。这次的关键问题，只读论文是发现不了的。

# 长程具身任务中的记忆与执行顺序

## ·一句话问题

**机器人记不住所有东西时，它应该改变做事的顺序吗？改变的话，它能提前知道该怎么改吗？**

长程任务里，机器人早先看到的信息，后面往往还要用。但它的记忆（上下文）有限，而它自己的动作又会把信息藏起来：关上柜门、把东西放进容器、拿别的东西盖住。于是有三种应对办法：记下来、需要时再看一眼、换个顺序让信息一直看得见或者干脆不需要记。

现有工作大多只研究其中一种：要么把记忆做得更好，要么决定何时去看。我们关心的是三者之间的取舍——特别是“执行顺序”这一项，它把记忆问题和任务规划连在了一起。

**为什么重要**：家庭、仓储、装配里的长任务，很多失败不是“手不稳”，而是“忘了做到哪了、不知道东西在哪了”。如果一个智能体知道自己会忘什么，并提前安排好顺序，这类失败就能少很多。

## 问题的精确表述

**机器人每一步有三类选择：**

- **物理动作**：改变世界，也顺带改变以后能看到什么。执行计划记为 π。
- **观察动作**：去看一眼，要花时间或力气，代价记为 r。
- **记忆操作**：记下、压缩、丢弃，总量不能超过预算 B。记忆策略记为 μ。

**一条信息的命运**：某个事实在早先被看到，在后面某个时刻被用到。到那时只有三种可能：它还在记忆里；它还能看到，付出代价 r；两者都不行，只能犯错或付出更大代价恢复。

**π 和 μ 会互相影响。** 执行计划 π 决定了三件事：这条信息以后还要不要用、要用时还看不看得见、看不见时恢复要花多少。记忆策略 μ 决定它在不在记忆里。所以最优的 π 可能依赖 μ 能做到什么，反过来也一样。

**用一个量来衡量“联合选择值多少”**。记 C 为在预算 B 下完成任务的期望代价（步数、补看、返工、犯错的惩罚）。先按“记忆无限”选出执行计划 π∞，再为它配最好的记忆策略，和一开始就联合选择相比：

```latex
\Delta(B, r) = \min_{\mu} C(\pi_{\infty}, \mu) \;-\; \min_{\pi,\, \mu} C(\pi, \mu)
```

Δ 叫“联合选择的价值”，总是 ≥ 0。Δ = 0 说明最优顺序不受记忆条件影响，先定顺序、再管记忆就够了。**整个研究可以归结为三个问题：Δ 在什么条件下大于 0、现有智能体拿到了多少、我们能不能拿到。**

不在研究范围内的：底层控制、感知精度。这些固定下来，或者用理想版本替代。

## 核心假设

[embed: node/45c610a3-4606]

只有在右下角这一区，联合选择才有价值：记忆不够，再看一眼又很贵，最好的办法是换个顺序，让需要记的东西变少。如果这一区很小，或者只在不现实的参数下才存在，这个方向就不值得做。

## 研究问题

五个问题按顺序推进，每个都写了“什么结果会否定它”。前三个不需要提出新方法就能回答。

|   |   |   |   |
|---|---|---|---|
|问题|要回答什么|怎么回答|什么结果会否定它|
|**RQ0 现象常不常见**|自然的长程任务里，有多少决定依赖“看过但现在看不到”的信息？换个顺序能不能改变这种依赖？|分析 BEHAVIOR 等家庭任务的结构|这类决定很少，或者信息被遮挡后就不再需要|
|**RQ1 Δ 什么时候大于 0**|在什么条件下（记忆预算、补看代价、物品数量、放置失败率、从看到到用到隔了多久）最优顺序会反转？Δ 有多大？|简化的理论模型 + 离散仿真扫参数|在合理的参数范围内 Δ 都接近 0|
|**RQ2 现有智能体会不会这样调整**|LLM / VLM 规划器会不会根据自己的记忆限制改变做事顺序？它知不知道自己会忘什么？|文字版任务，控制上下文预算；对比告诉和不告诉它预算、给和不给完整历史|它们已经会自动调整；或者给了完整历史也做错（说明瓶颈不在记忆）|
|**RQ3 能不能提前预测并联合选择**|只用机器人能合法获得的信息，预测不同顺序下以后要用哪些信息、缺了要付多少代价，并据此选择|预测器 + 联合选择，对比强基线|比“固定顺序 + 完整记录 + 缺了就补看”好不了多少|
|**RQ4 学到的是什么**|学到的是一般的“证据依赖”，还是某个任务的规则？|换没见过的任务结构测试|换了任务就失效|

**RQ2 可能是最有意思的切入点。** 它问的是：LLM 智能体会不会围绕自己的记忆限制做规划。这是一个关于“自我认知”的问题，答案不管是是还是否都有信息量，而且实验成本很低。

## 导师可能提出的质疑

第一条最关键，它决定这个方向的动机是否成立。

1. **“现在模型的上下文已经很长了，全存下来不就行了？”**
    - 带图像的历史长得很快，几分钟的任务就可能超出预算。
    - 存了不等于用得上：历史越长，模型越容易漏看关键信息。
    - 全存解决不了过时信息，反而会堆积更多过时的记录。
    - 这一条本身可以检验：RQ2 里给完整历史，如果错误基本消失、成本也不高，说明问题不在记忆，我们就该收缩方向。
2. **“这不就是部分可观测规划或主动感知吗？”** 经典方法假设记忆完美且免费，只决定何时去看。我们把记忆当成有预算、会出错的资源。当记忆无限时，我们的问题就退化为主动感知，Δ = 0。
3. **“认知科学早就研究过人怎么在记和看之间取舍。”** 对。人在搭积木复制一类任务里宁可多看几眼也不多记，看的代价变大时才多记；“把记忆卸载到环境”也有专门研究（Ballard、Hayhoe 等人的工作，讨论前再核对具体文献）。这是支持，不是威胁：人会这样做，我们问机器人智能体会不会、该怎么做。区别在于，那些实验研究的是“看”和“记”的取舍，我们还加入了“改变执行顺序”这一项。
4. **“这是真实问题，还是你们构造出来的？”** RQ0 就是为了回答这个问题。礼品篮这类任务来自 BEHAVIOR 的官方任务；结果会分开报告自然出现的频率和人为加压后的情况。
5. **“是不是只是模型太弱，换个更强的就好了？”** RQ2 在不同模型上都做。如果强模型自己就会调整，结论就变成“这种能力随模型变强而出现”，也是有价值的发现。

## 需要和导师一起定的选择

|---|---|---|
|选择|可选项|当前倾向|
|**贡献类型**|A：现象与分析（理论模型 + 测评，回答 RQ0–RQ2）；B：方法（RQ3–RQ4）；C：两步走|先做 A。A 本身可以成文，结果好再做 B|

最后一项和之前的计划不同。之前打算先在 BEHAVIOR 上审计任务，现在建议先用理论和文字版环境回答 RQ1、RQ2，BEHAVIOR 留到方向确认之后。

## 建议的第一步研究

先做一个 3–4 周的小研究，只回答 RQ1 和 RQ2，不碰重工程。

1. **理论模型**：把组装礼品篮抽象成 K 个篮子、M 种物品，参数是记忆预算 B、补看代价 r、放置失败率 p。“按物品批量放”省路，但要同时记住 K×M 项进度；“逐篮完成”多走路，但只需记住当前篮子的 M 项和一个计数。推导出两者的分界线，得到 Δ 随 B 和 r 变化的图。
2. **文字版仿真**：同样的任务做成文字环境，看不见的东西不出现在描述里，上下文按预算截断。用它验证理论预测的分界线。
3. **测几个 LLM 规划器**，分三种条件：不告诉预算、告诉预算、给完整历史。看三件事：会不会换顺序、错误率、多走的步数。

**结果怎么用：**

- 理论和仿真都显示存在明显的反转区域，而且现有模型在这些区域里没有自动调整 → 方向成立，再投入 BEHAVIOR 和方法研究。
- 反转区域很小，或者只在不现实的参数下才出现 → 写成“什么时候简单规则就够了”的分析，调整方向。
- 模型给了完整历史也做错 → 瓶颈在推理而不在记忆，转向利用差距。
- 模型被告知预算后就会调整 → 问题变成“它自己不知道预算时怎么办”，研究重点转向让智能体认识自己的记忆限制。
