## 一、论文 1 要回答什么

**研究问题**：在具身闭环找物中，记忆已经分库，判断也是独立的，为什么错误还会持续？怎样打破？

**三个机制**：

| 机制 | 说的是什么 | 我们见过的例子 |
|---|---|---|
| M1 经过规划器的传递 | 一个库的偏差，被规划器写进检查条件和"下一步看哪里"，判断就在被带偏的区域里作答，机器人反复去查错误的地方 | Object 画偏的框，被抄进检查条件，判断看的是刀上方的墙面 |
| M2 不分条件的否定 | 远处、低分辨率下没认出来，被记成"这里没有"；之后走近、看得清了，旧记录却压住了正确的识别 | Object 沿用自己上一条"刀不在视野里"，可当前图里明明有刀 |
| M3 同视角下的同一种错 | 不换视角、不换尺度，同一个模型重问，或者让判断再核查一遍，都会犯同一种错 | 两次独立调用画出完全相同的偏框；把洗碗机把手、吊柜拉手认成刀 |

**三条主张，以及什么结果会推翻它**：
- **H1**：经过规划器的传递，会改变机器人的取证行为，并延长错误持续的时间。
  - 推翻：错误记忆有没有、规划器选的检查范围用不用，都不改变取证和后果。
- **H2**：低分辨率下记下的否定，会压住之后分辨率足够时的正确识别。
  - 推翻：同一张清晰的当前图，有没有旧的否定，识别结果都一样。
- **H3**：在同等预算下，"观测感知记忆，加上在歧义处换条件重看"，比"同视角重问"和"固定频率复查"更能缩短错误持续时间、提高完成率。
  - 推翻：收益完全来自多看了几次，或者正确的记忆也被频繁复查，把收益抵消了。

**和已有工作的边界**：
- Gao 2026 研究的是复述让模型过早下结论；
- Lin 2026 研究的是来源依赖，以及在预算内主动补取证据；
- CMA 2026 研究的是替换历史后，学习得到的策略动作会怎么变。

我们的贡献落在具身智能体特有的一点上：证据取决于机器人"去哪看、在什么分辨率下看"，而大模型智能体会把一次有适用范围的观察，写成过强的语义结论，再通过工具调用和检查条件把它维持下去。光是"把 CMA 的做法换到大模型上"，不算贡献。

## 二、任务：A（大物体）→ B（小物体）→ A

**三个阶段**：
1. 找到 A，让它出现在头部画面里，并能被认出；
2. 找到 B（刀）；
3. 回去再找到 A。

**规则**：
- 两个目标一开始就都告诉规划器和 Object，但规定按顺序找。Object 的查询改成两样东西，这样它在第 1 阶段才会顺带记下关于 B 的观察，M2 才有机会出现。
- 每个阶段是否完成，由程序判：当前目标的 G2（结束时的朝向），加上放大复核。确认以后，程序自动进入下一阶段；第 3 阶段确认后整轮结束。规划器不再调用 finish。
- 每个阶段最多 15 次决策。用完还没找到，就记为这一阶段失败，直接进入下一阶段，保证每轮都能走到第 3 阶段。整轮最多 45 次决策。

**物体**：
- A 的候选：烤盘、砧板、披萨面团、碗。它们都是几千像素，远处也认得出。
- B 就是刀，各个实例里它都平放在约 0.9 米高的台面上，但放在台面上的哪个位置因实例而异。

**选实例和起点的规则**（先写下来，再选）：
1. A 和 B 不能同时出现在一个画面里，这样中间必须走动。
2. 找 A 的路上，至少有一次远远看到 B 所在的那片台面，而这时 B 认不出来：小于约 150 像素，或者刀尖顺着视线。这是 M2 出现的机会。
3. 在机器人能站到的位置上，B 能被看清：200 像素以上，并且能从侧面看到整把刀。用 A5 和刀的姿态离线估算。
4. 第 2 阶段时，A 离开视野。
5. 避开可达性有问题的起点，比如 170、59。

先在仿真里查清候选实例中 A 和 B 各自放在哪里，补上补充七那张摆放表里的空白。

## 三、三种条件

三种条件只改 Object 这一侧，其余完全一样。

| 条件 | Object 怎么工作 |
|---|---|
| 基线 | 冻结版：大模型维护自己的记录；否定不带条件 |
| 强基线：无状态提取 | 每次只看当前帧和上一帧的图，不看自己的旧文字；由程序按观察事件归并。同一个物体在不同视角下怎么关联、同类物体有好几个时怎么区分、正负记录冲突时怎么办，都要写清楚 |
| 方法：观测感知记忆 | ① 每条记录带上观测条件：用的是整图、分块还是复核裁图，检查的是哪块区域，深度算出的表面距离；② 否定只对"那块区域、那种条件"成立，低分辨率下的否定标为"未核实"，不能压住当前的候选；③ 候选和确认分开记；④ "最近一次见到"指针，可以被新证据改正；⑤ 遇到没解决的候选，或者"未核实"的否定，而那块区域又在视野里时，程序给 Object 加上那块区域的放大裁图，也就是换条件重看 |

- 三种条件共用冻结版里的几项：成功口径、"上次见过"的修复、输入上限、判断的分块和放大复核。
- H3 的同预算对照，放在分叉状态上离线做：
  - 同视角重问：多问一次，但不放大；
  - 固定频率复查：每隔 k 步放大一次，不管有没有歧义。
- 方法组件可以分开开关：①②、③④、⑤，用来看收益各自来自哪一项。
- **补充八的教训（1022）**：放大裁图只对"太小、认不出来"有用；对"长得像"的误认，同一个模型放大了看，仍会犯同样的错。254 那帧吊柜上的浅色长条部件，放大以后照样被说成"有刀刃和刀柄的金属刀"。所以⑤里的"换条件重看"不能只换尺度，还要能换视角，必要时换一个模型来复核。这也是 M3 的一条直接证据。

## 四、实验

**E1 在线对照**：3 种条件 × 4 个实例 × 2 轮 = 24 轮，看闭环的总体后果。

**E2 分叉状态配对**：这是主要的因果证据。
- **选点规则**（事先定好）：
  - H2 类：B 现在就在附近、看得清，而 Object 里有一条旧的远处否定；
  - H1 类：规划器正要按一个错误的 Object 候选框，选检查区域或者下一步去哪；
  - H3 类：B 的位置上有一个没解决的候选。
- **干预**：
  - 原样；
  - 删掉那条否定；
  - 把否定换成带条件的"未核实"；
  - 在没有否定的地方，注入一条远处的否定。
- **H1 的交叉设计**：错误记忆有或没有 × 规划器选的检查范围用或不用（不用时改为看整图）。
- **两层结果**：
  - 下一步动作：离线做，便宜；
  - 其中一部分从同一状态在线续跑到这一阶段结束，看闭环后果。
- **分叉怎么实现**：仿真现在没有保存和恢复状态的功能。两种办法：
  - 接入 OmniGibson 自带的场景状态保存和恢复；
  - 从 reset 开始，按原来的决策序列重放到分叉点，再核对位姿误差。

  由 GPT 按可行性选。
- **样本**：试点 12–20 个分叉，正式 40–60 个，具体数量按试点的方差定。

**E3 换模型**（第 7–8 周）：在冻结的分叉请求上，把 Object 和判断换成 1–2 个其他视觉模型，离线跑；规划器换模型，做少量复现。

## 五、指标

下面凡是用到 A5 的，都只在离线计算，不进任何模型输入。

| 指标 | 定义 |
|---|---|
| 阶段完成 | 这一阶段的目标在结束朝向的头部图里被确认，并且离线核对属实 |
| 错误的阶段完成 | 程序判了完成，但 A5 显示目标并不在结束时的画面里 |
| 错误持续时间 | 从第一条错误记录（关于 B 的位置，或者"这里没有 B"），到它被正确记录取代，经过了多少次决策 |
| 被带偏的检查步数 | 检查区域或移动目标，来自一条按 A5 看是错误的记录，这样的步数 |
| 压制率 | B "认得出"时，Object 或判断却没认出的比例，分"有旧否定"和"没有旧否定"两组比较 |
| 分辨率提升 | 出现候选以后的 k 步之内，机器人有没有把 B 从"认不出"拍到"认得出" |
| 回访效率 | 第 3 阶段重新找到 A 用的决策数，和第 1 阶段相比 |
| 成本 | 每次决策的 token 和耗时，以及整轮的总量 |

**"认得出"的离线代理**：A5 的像素数、可见比例，再加上刀的长轴和视线的夹角；夹角小，说明刀尖顺着视线。必要时再加人工标注。
