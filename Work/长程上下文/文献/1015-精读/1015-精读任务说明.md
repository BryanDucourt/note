## 二、我们的方向（读之前先了解）

- **研究对象**：长程具身任务（BEHAVIOR 这一类）。系统里有多个使用历史信息的模块，下文统称“消费者”：VLM 规划器、VLA 或技能执行器、执行监控（判断这一步成没成）、任务评估（判断整个任务完成没有）。
- **方向**：完整的记忆／上下文统一存一份，再为不同消费者生成不同的表征或压缩。
- **目前的候选主线**：
  1. **面向验证的证据选择**：给监控和评估模块一份独立于规划器摘要的证据视图，围绕“这一步的完成条件”从原始记录里挑证据。
  2. **错误连带**：共享摘要出错后，错误会在多个消费者之间传播；独立视图能否切断这种传播。
  3. **来源追踪与失效**：每份派生摘要记下依据了哪些原始证据，证据变化时只让相关摘要失效、重算。
  4. **诊断**：“信息类型 × 消费者”矩阵，衡量不同消费者的信息需求重叠多少。

## 三、每篇要交付的内容

每篇控制在 1,500 字左右，表格不计。按下面的顺序写。

### 1. 基本信息
出处、版本、发表情况、主要团队、代码是否公开。

### 2. 一句话和要解决的问题
一句话说清楚这篇做了什么；再写它针对的具体问题，以及作者认为已有方法哪里不行。

### 3. 方法：按下表逐项回答

这一节是重点。每项都要写到具体机制，并标出处（章节、公式、表格或页码）。论文没写的项写“论文未说明”。

| 维度 | 要回答的问题 |
| --- | --- |
| 存储来源 | 存的是当前任务的历史，还是过去任务的轨迹或经验？存原始数据还是加工后的？ |
| 消费者 | 有几个？是同构的（同一模型扮演不同角色），还是异构的（模态、频率、接口不同）？ |
| 定制依据 | 按角色、任务阶段、当前决策状态，还是请求文本？在什么时候生成：任务开始时、每一步，还是按需？ |
| 压缩方式 | 是选择已有条目、改写成文本，还是生成 latent？预算多大、怎么定？ |
| 训练信号 | 有没有学习？用什么反馈？消费者模型是否冻结？ |
| 更新与一致性 | 证据变化后怎么更新？已经生成的摘要会不会失效？ |
| 验证 | 有没有专门负责检查的模块？它看到的证据是否独立于规划器？ |
| 共享 vs 分开 | 有没有在同一预算下，“所有消费者共用一份”和“按消费者分开”的对照？ |
| 错误传播 | 有没有测量过一个模块的错误怎样影响其他模块？ |
| 成本 | 总 token、延迟、调用次数分别是多少？按什么口径算？压缩本身的开销算进去了吗？ |

### 4. 实验
数据集与任务、基线（自己实现的还是官方的）、每组的试验次数或样本量、关键数字（附出处）、消融做了什么、没做什么。

### 5. 结论站不站得住
沿用 1013 的格式：

| 结论 | 证据强度 | 依据 |
| --- | --- | --- |

证据强度分三档：**支持**＝有直接的实验或证明；**弱**＝有证据，但样本少、缺对照或有混杂；**无**＝基本没有证据。

### 6. 论文与代码是否一致
只针对公开了代码的 LatentMem 和 HiMe。抽查方法里最关键的两三处实现，写明 commit 和文件位置。没看代码的就写“未核对”。

### 7. 对我们的影响
- **覆盖了什么**：对照第二部分的四条候选主线，逐条判断“已覆盖 / 部分覆盖 / 未覆盖”，并说明依据。
- **留下了什么**：有哪些空白是我们可以做的？
- **能借用什么**：方法组件、实验设计、评测指标、数据或代码。
- **如果当基线**：怎么接到我们的设定里？需要改什么？
- **导师可能会问的问题**：两三个。

## 五、规则

- **出处**：每个事实性说法都标出处（章节、公式、表格或页码）。数字必须来自原文，不要四舍五入后再转述。
- **事实和推断分开**：论文明确写了的直接陈述；属于你自己判断的，句首标“【推断】”。
- **不要只读摘要和引言**：方法、实验和附录都要看，特别是附录里的实验设置和补充实验。
- **判断“已覆盖”要逐项对照**：要按第三节第 3 部分的维度逐项对照我们的设定，不要因为用词相近就判定为已覆盖。
- **不确定就写“未核实”**，不要补全或猜测。
- **只读这四篇**：不扩展到其他论文；引用其他工作时只写论文里怎么说的。
- **格式**：中文 Markdown，标题层级和 1013 一致。
