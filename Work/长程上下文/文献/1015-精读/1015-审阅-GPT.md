## 二、推断分歧

### D1. “必须同族，VLA用不了”把实验边界写成了方法限制

Claude 的理由是 latent 要白盒注入，实验使用同一文本主干（第9、111、120行）。我同意**当前实现需要访问 embedding、维度兼容和相应训练**；但“同族”“VLA用不了”没有原文证明。

L 式5–6要求一个可接收连续记忆的消费者接口；代码还显式设置[`weaver2agent_proj`](https://github.com/KANABOON1/LatentMem/blob/48728068db63878b6205661556bfc5eb9294cc37/latentmem/mas_core/memory/latentmem.py#L65-L70)。当前投影按首个 agent 的 hidden size 构建，实验也未覆盖多类异构消费者，确实不足以直接复用到任意 VLA。

**【推断】我更支持的判断**：“对 VLA 的兼容性未验证；接入需确定注入位置、投影与训练信号。”我们可以研究这条接口，但不应以“latent天然不能服务VLA”为前提。

### D2. HiMe 对“验证证据选择”的覆盖应判部分覆盖

Claude 判“未覆盖”，理由是 Sentry 只截近期窗口（第379行）。我的独立稿判“部分覆盖”，理由是候选主线1还包含“给监控一份独立于规划摘要的证据视图”，H 已给 Sentry 近期原始图像，并按当前子任务判断完成（H 式2、附录 D；代码 `task_manager.py:358–381`）。

**【推断】“部分覆盖”更准确**：固定近期选择和独立感知入口已经存在；完成条件驱动的长历史检索、与整体任务评估的配合仍有空白。新贡献需要回答为何某个早期证据对完成判定不可替代。

### D3. 诊断矩阵的“风险最低”需要区分第一步工作与论文贡献

Claude 认为反事实矩阵适合作为第一步，所以风险低（第427–429行）；我认为仅做信息分布矩阵的新颖性风险高，因为 R **表23**已经按角色列出四类记忆占比。

**【推断】两种判断在不同层面可兼容**：作为低投入的诊断起点，可以赞同 Claude；作为独立贡献，应采用信息删除/替换等干预来估计需求与重叠。即使升级为反事实矩阵，研究价值仍取决于它揭示了什么会改变机制设计的规律。

另外，L 的 **2.30/6.45** 是特定框架去角色输入的变化，R 的 **1.3/1.9** 是特定QA/ALFWorld路由对比，任务、基线、训练和指标均不同。**【推断】将它们拼成“分开的收益只有1.3–6.45”不足以判断具身任务中分开的价值。**（L §5.6；R 表2；Claude 第429行）

### D5. “读到Planner计划”给出的是错误传播路径假设

Claude 多次说结构上“天然存在错误连带”（第24、380、421行）。这提出了有价值的研究切口，但需分清两件事：

- **错误完成判断**：子目标正确，监控因错误摘要而误判现场是否满足它。
- **错误子目标被正确执行**：Planner写错子目标，Sentry准确确认该子目标已完成，整体用户任务仍失败。

H 的 Sentry职责由当前计划定义（式2、附录D），所以第二种路径确实可能存在；它不必伴随 Sentry 局部判断错误。

**【推断】应分别干预“证据内容”和“验证问题/子目标”，并区分局部判定与整体目标。**否则所谓错误连带可能只是把错误规划执行完毕，独立视觉证据也未必能修复这个问题。两份原稿都应在后续方案中明确此区分。

### D6. “复现以代码为准”需要改成可追溯的实验配置

Claude 已发现 HiMe 默认FIFO为20、论文为8，也指出环境变量可覆盖（第372、391行）。这些是公开默认值与论文描述的差异；论文实际启动参数、提示词、运行日志仍未核实。

**【推断】更合理的做法是按论文目标设置锁定代码、参数和提示词，无法还原的部分明确列出。**代码默认值、论文公式、论文实验配置各自提供不同证据，不能任取其中一项作为所有结果的依据。我们把它改成新基线时，也要明确这是重实现或适配。

### O5. REFLECT 的通用摘要消融与多消费者共享对照尚有距离

Claude 第302行称 LLM summary“正好就是共享通用摘要基线”。F §5和图6确实提供“通用改写丢掉冰箱关闭信息”的例子，但实验未直接比较多个消费者共享同一摘要与各自取证，也未匹配token总开销。
