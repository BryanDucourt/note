### 总体判断与讨论问题

**【推断】空间最大的是候选主线 2“错误连带”，以主线 1“完成条件证据选择”为干预机制；最危险的是把主线 4 的分布矩阵单独当贡献。**主线 3 可作为机制支撑：记录原始证据依赖并定向失效，比一般的增删改更具体。（各篇覆盖表；R 表23；H §3.3、附录 D）

1. 【推断】我们要降低的是哪种错误：误判完成、漏检失败，还是修复动作错误？哪一种最依赖较早的证据？
2. 【推断】在同一原始证据池、相同总开销下，完成条件驱动的选择是否优于 RCR 式角色路由和 HiMe 式近期窗口？
3. 【推断】规划器给错子目标时，验证器怎样发现目标本身的问题？独立视觉输入仍可能继承错误的验证问题。
4. 【推断】收益来自保留更多信息、增加调用，还是减少共同错误？需要哪一项干预才能区分？
5. 【推断】证据依赖与失效最终改变了什么决策、节省了什么重算，并改善了什么执行结果？

### LatentMem: Customizing Latent Memory for Multi-Agent Systems

#### 1. 基本信息

预印本，arXiv v2 于 2026-03-09 更新。Muxin Fu 等，主要单位包括同济、上海 AI 实验室、香港中文大学、南京大学、上海交通大学；代码和模型链接在首页公开。指定版本未列正式会议出处。（L p.1；arXiv 版本页）

#### 2. 一句话和要解决的问题

把过去多智能体任务的原始交互轨迹，压成每个角色专用的连续记忆向量，并用任务奖励训练生成这些向量的 composer。作者针对共享记忆同质化、细粒度条目过多造成的上下文负担。（L §1、§4）

【推断】贡献最实在的部分是**角色条件化、固定长度连续接口、任务反馈训练**的组合；“记忆分工”值得承认，t-SNE 分群与单个自纠错案例对错误传播的证明力度较弱。（L 式5–13、图4、图7）

#### 3. 方法

| 维度 | 具体机制与出处 |
| --- | --- |
| 存储来源 | 过去任务的完整 MAS 轨迹，每步记录 agent、输入、输出；训练前建库，任务完成后追加。当前任务执行产生的历史仍进入 agent 自身输入，experience bank 的新增以任务结束为边界。（§4.1–4.2，式3–4，pp.4–5） |
| 消费者 | AutoGen 2 个、MacNet 5 个、CAMEL 4 个、DyLAN 5 个角色；实验每套系统使用同一指定文本 LLM 主干，角色与拓扑不同。没有 VLM/VLA/监控异构组合实验。（附录 B.3，pp.19–20；§5.1） |
| 定制依据 | 新 query 检索历史轨迹；式5在每个 reasoning step 根据当前 agent 的角色和检索轨迹生成 latent。公式未显式包含任务阶段、完成条件或当前观测；代码额外输入任务文本与检索轨迹中的该角色响应。（§4.2–4.3；L-C1） |
| 压缩方式 | 输出矩阵 $m_j\in\mathbb{R}^{L'\times D}$，拼到消费者输入 embedding。默认 $K=1,L'=8$，长度经敏感性实验选定；8 是连续 token 位置数。（式5–6；§5.1、§5.6） |
| 训练信号 | LMPO 采样一组 MAS 轨迹，用最终答案正确性形成组内相对 advantage，再优化 token 级 clipped 目标；冻结消费者，训练 composer 的 LoRA 等参数。记忆长度固定，奖励中未给显式压缩成本项。（§3，式2；§4.4，式9–13；附录 B.4、表3） |

| 共享 vs 分开 | **有直接消融**：without role 移除角色输入，各 agent 得到相同 latent；默认 latent 长度相同。端到端总计算预算、训练是否完全重做未充分交代。（§5.6，图6，pp.10–11） |
| 错误传播 | 图7与附录 C.4 展示循环、照搬历史和自纠错案例；未报告错误注入、跨 agent 条件错误率或传播概率。（§5.7、附录 C.4） |
| 成本 | §5.3、图3/8报告时间与 token；原文例子包括相对 OAgents **2.16×** 的推理时间差、AutoGen/KodCode 比无记忆少 **0.01M tokens**。未清楚分列 composer、检索重排、建库、训练及各类 token 成本，调用次数未说明。不能把 8 latent 直接用作系统总成本。（§5.3、附录 C.1；L-C2） |

### RCR-Router v4

#### 1. 基本信息

指定版本为 arXiv `2508.04903v4`，2026-10-12 更新，预印本。PDF 标题为 *Role-Conditioned Context Routing for Resource-Efficient Multi-Agent LLM Systems*，网页标题措辞不同；主要团队包括 CMU、Northeastern、Harvard、MIT 等。原文与 arXiv 页未给出可核对的官方实现链接，代码公开状态**未核实**。（R p.1；arXiv 版本页）

#### 2. 一句话和要解决的问题

在固定的多智能体系统前加一个路由层，每次调用前决定该角色应看到哪些共享记录以及多少 token。针对的问题是同一记忆反复广播带来的冗余与角色无关信息干扰。（R §1、§3.1）

【推断】这是四篇中最直接覆盖“当前任务内、按消费者给不同历史”的论文；具体增量是学习相关性与预算、按条目长度选择。其方法先例很明确，实验中的若干内部矛盾需要单独处理。（R §3；下表）

#### 3. 方法

| 维度 | 具体机制与出处 |
| --- | --- |
| 存储来源 | 当前任务的交互、推理、外部知识、工具结果、实体和子计划；经 Memory Update Agent 转为带角色、阶段、时间戳、内容的原子条目。不是完整原始传感记录。（§3.1、§3.3；附录 E） |

### REFLECT: Summarizing Robot Experiences for Failure Explanation and Correction

#### 1. 基本信息

CoRL 2023；arXiv v4 为 2023-10-16。作者 Zeyi Liu、Arpit Bahety、Shuran Song，论文署名 Columbia。作者项目页提供代码与 RoboFail 数据链接；本次遵守任务范围，不审计其代码。（F p.1；作者项目页）

#### 2. 一句话和要解决的问题

把一次失败执行的多感官历史整理为“逐帧状态—关键事件—子目标终态”，逐个检查子目标，再解释失败并生成修复计划。核心难题是让文本 LLM 获得机器人失败推理所需的物体状态、空间关系和事件时序。（F §3.1–3.3）

【推断】这是“围绕完成条件挑证据”的明确前身，尤其是先定位异常子目标、再取细粒度事件历史的检索顺序；最重要的适用边界是事后失败分析和感知假设。（F §2–5）

#### 3. 方法

### HiMe: Hierarchical Embodied Memory for Long-Horizon VLA Control

#### 1. 基本信息

arXiv `2607.03449v1`，2026-07-03；PMLR确认收录 ICML 2026。任务说明标注 poster，本次未从可访问的会议页面独立核实展示类型。主要团队为复旦、上海创智学院、华东师范大学，代码公开。（H p.1；arXiv；PMLR）

#### 2. 一句话和要解决的问题

让 VLA 专注即时控制，小 VLM 用近期视频判断子任务是否结束，大 VLM 在触发时查询和增删改长期图文记忆、生成下一子目标，以协调快控制与慢推理。（H §3.1–3.4）

【推断】它对我们最强的挑战是：**异构消费者已经拿到不同上下文，而且监控直接看图像**。剩余空间须具体到历史证据如何选择、错误目标如何纠正，以及多个派生视图如何保持一致。（H 式1–4；附录 D）

#### 3. 方法

| 维度 | 具体机制与出处 |
| --- | --- |
| 存储来源 | 当前任务/连续交互的即时观察、近期窗口、图文 contextual memory、带 done/current/pending 的 procedural plan；长期条目保存状态、空间约束、偏好等。没有 LatentMem 式过去任务训练轨迹检索库。（§3.2，pp.6–7） |
| 消费者 | 异构三层：π0.5 Executor；Qwen3-VL-8B Sentry；GPT-4o Planner，附录用 Qwen3-VL-30B替换。Executor看当前双目视角、本体状态、子目标；Sentry看近期图像与计划；Planner看阶段图像、指令、计划和检索图文。（§3.3–3.4；附录 B、D） |
| 定制依据 | 根据功能与时间尺度预设接口；Sentry完成/失效触发Planner，低召回另用固定间隔fallback。Planner两轮：先Query，再CRUD+计划。（式2–4；§5.4；附录 D） |
| 压缩方式 | Sentry近期窗口8帧；Planner使用子任务阶段均匀采样图像和图文条目，生成语言子目标。长期主设置不限制条目数；未规定统一token预算。代码检索为tag优先、文本Top-5回退，tag命中可返回全部匹配项。（§3.4、§4.3、表2；H-C1/C2） |

#### 4. 实验

真实 WidowX平台上 Object Search、Counting、Rearrangement，**每任务每方法20次**。固定Executor与Planner主干，作者实现 transient、transient+Sentry、flat FIFO、HiMe w/o Sentry；Human High-level由人给正确子目标，作为固定低层策略下的参考上界。相关论文只用于设计类比，基线并非其完整官方复现。（H §4.1–4.2、图3；附录 A）

## 四、对方向的总体影响

| 候选主线 | 判断与取舍 |
| --- | --- |
| 1. 面向验证的证据选择 | 【推断】**有空间，但必须推进到“历史证据为何足以判定完成”。**REFLECT已按子目标看证据，HiMe有独立图像监控，RCR有Verifier路由；单加验证器或分离输入很容易落入已有工作。（F §3；H 式2；R F.3） |

【推断】下一步讨论应围绕一个具体失效例子展开：早期观察包含完成条件所需证据，规划摘要遗漏或写错；规划器据此选错动作，监控又重复信任该摘要。我们从原始记录重新取出目标相关证据，是否能让监控改变判断，并推动真正有用的修复？这个链条比抽象主张“不同消费者需要不同记忆”更有区分度。

【推断】比较时至少需要共享视图、RCR式角色路由、HiMe式近期监控、REFLECT式子目标/事件回溯，以及我们的完成条件选择；共同使用合法原始证据、相同消费者和可比总开销。若只提高摘要质量却不改变错误决策，主张应停留在表征改进。

【推断】架构上可继续让 Task、Object、Spatial、Experience 各自维护派生状态，共享原始证据及其引用；本稿没有提出把它们并成一个共享语义仓库。仿真真值和任务分数用于离线评估，消费者侧通过合法观测获得证据。
