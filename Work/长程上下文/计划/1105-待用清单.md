**现在的主线**（用户把 GPT 收窄后的回应贴来作答复，见 [[1105-论文路线会审-收窄后的回应]]）：

## 先放着的做法

| 做法 | 回答什么问题 | 什么时候拿出来 |
|---|---|---|
| 直接把算好的"够不够得着"给模型（对照 D） | 关系已经给对了，模型用不用得上。这正是第二个小问题最干净的测法 | 8 个状态的结果出来以后，下一轮的头号候选 |
| 只问关系的请求 | 不受动作请求影响时，关系本身答对多少 | 需要单独量关系判断时 |
| B、B′、C 拆开（以底盘为原点 → 以肩为原点 → 按物体打包） | 换参照系、换打包方式，各帮了多少 | B（编号旁写距离）明显好过 A 时 |
| 常规状态表 S、我们的更新 U，以及 S、S+D、U、U+D 四格对照 | 动了以后，更新规则有没有额外作用 | 进入连续几步的时候 |
| 任务中段的"事件和损失表" | 这类问题在正常任务里多常见、每次损失多大 | 进入连续几步、完整任务之前 |
| 跨帧认出同一个物体（自动关联） | 闭环里更新的是不是同一个物体 | 开始做自由闭环之前 |
| 短思考对照 | 只开一点推理是不是就够了 | 开始比较上下文方法的时候 |
| 加任务（扩到 6–8 个） | 两个任务里这类问题够不够多 | 事件表显示两个任务里这类事件太少时 |
| 自带全身调整的 pick | 底层自动调身体以后，规划器还要不要管身体 | 做系统级比较时 |

## 相关工作怎么看（按 10/16 定的规矩：讲清重合和差异）

- PhysVLM：一遇到要先靠近的任务，GPT-4o 就从 75.9 掉到 35.8；它的解法是训练一个模型。
- WorldSketch：GPT-6 82/90，因为动作交给了几何规划器；9B 小模型只有 2%，多步任务 3/30 到 5/30。
- RMMBench：GPT-6 40 分，其余模型都不超过 21 分。
- 它们说明问题是真的，而且没解决。"不训练的小模型在处境不断变化时，看得懂却做不对"，还是我们的。
- 建议用户读 WorldSketch 和 DovSG。
