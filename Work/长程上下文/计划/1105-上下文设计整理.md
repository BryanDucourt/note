## 一、一句话

上下文设计回答的是：规划器每做一个决定之前，该看到什么；这些东西由谁写、怎么挑、按什么顺序给。

## 三、v2 的样子（冻结版，到 1102 为止的实验都用它）

### 1. 每一步谁在干活

每步大约调用 5 次模型，都是 deepseek-flash，温度 0，不开思考，输出 JSON。

| 角色 | 做什么 | 谁来写 |
|---|---|---|
| 规划器 | 每步选一个工具调用。只读记忆、不写记忆，也不能自己结束任务 | 模型 |
| 判断模块 | 判断目标在不在画面里。G1：目标出现在当前任意一张图里；G2：出现在正对方向那张图里，G2 满足才算找到 | 模型 |
| Object | 关于物体的记录：在哪见过、是看到的还是推断的 | 模型，看图写 |
| Spatial | 布局、区域、地标，带相机位姿 | 模型，看图写；程序记下走过的视点，也并进这一块 |
| Spatial 重排 | 按当前目标给 Spatial 的条目排序 | 模型 |
| Task | 目标、阶段、每阶段的决策预算、完成情况 | 程序 |
| Experience | "什么情况、怎么做、效果如何"的案例 | v2 里关着 |

### 2. 规划器每一步收到什么（按顺序）

1. **任务块**：目标、当前阶段、剩余决策数、G1 和 G2 的状态，以及对应的是哪张图；
2. **当前观测**：图片，每张配一行说明（编号、是不是最终朝向、怎么转过去的），再加底盘的位置和朝向；
3. **上一步的图**，标明"动作前"；
4. **最近 3 步的执行**：工具、参数、实际转了多少度或走了多远、为什么停；外加上一步写的意图；
5. **记忆**：按库分块给，每库最多 4 条。
   - Object 里写到当前目标的排在前面；Spatial 按重排的结果给。
   - 每条记忆写明：内容、证据图、多久以前、是观察还是推断、可信度、有没有冲突；
6. **一张历史图**：按当前目标检索出来；
7. **工具表**：由程序维护，开关工具不用改提示。

系统提示是一份分块的固定英文文本，写了这几块：
- 分工；
- 任务怎么算完成；
- 证据原则：分清现在看到的、记忆里的、推断的、预期的；
- 五条做法，都在讲怎么找东西；
- 身体说明：按平台从配置生成，写到相机装在哪、视野多宽、里程计会漂；
- 输入和输出的说明。

### 3. 规划器交回什么

- 字段：reason、subgoal、tool、arguments、expected_outcome。reason 的第一句先报 G1、G2 的状态。
- 程序只检查 tool 和 arguments 两项。
- 转向有两种写法：直接选一张环视图的编号，角度由程序来算；或者写"左"或"右"加一个角度。

### 4. 冻结的规矩

- 冻结以后，只修会让数据作废的错误。
- 扩展要满足两条：
  - 没开扩展的现有任务，规划器的输入必须逐字节不变；
  - 扩展要单独做一次在线检查。

## 五、暴露出的问题

1. **围着"找东西"设计**：
   - 提示开头就是"在室内找目标物体"；
   - 只有 G2 满足才算完成；
   - 五条做法都在讲搜索。
   - 搬东西是后来硬接上的，用户 1031 的原话是："老围绕看没看到这个事情本身就是错的"。
2. **写对了、送到了，不开推理就用不上**：这是这条线最稳定的一个发现。
3. **系统很重，却没和简单做法比过**：每步约 5 次模型调用，输入很长，从来没和"最近几步的滑动窗口"或"滚动摘要"这类简单做法比过（Gemini 指出）。
4. **"同一个 v2"在三个平台上并不一样**：走向某点、环视、指物，三个平台各有各的语义。
5. **噪声大，样本小**：温度 0，同样的输入在两批之间也会变；场景少，一张餐桌反复用。

## 六、和现在主线的关系

- **差距测量不用 v2**：每个点只调一次模型，输入是一张带编号的图、一段固定模板的文字，输出是一段短 JSON。冻结的 v2 文件一个字节都没动。
- **能带过去的东西**：
  - 证据分层：看到的、记得的、推断的、预期的；
  - 身体说明。用户 1030 定过："按关节写"和"按效果写"两种都要测；
  - v3 的两个想法：先核对上一步；预期写成下一步能核对的变化；
  - 角色分开；仿真真值不进模型输入。
- **最直接的教训是"说得出，不等于用得上"**。差距测量里"关系说对了、动作却不对"那个数，量的就是这件事。
- **还没定的**：
  - 四个库要不要保留。用户 1102 的原话："具体的架构倒不一定非得是四个库"。
  - 1102 提到的"维护物体之间的关系，方便检索更新"，等于一份各角色共用的关系记录。按 `AGENTS.md` 的规矩，引入之前要先讨论。
