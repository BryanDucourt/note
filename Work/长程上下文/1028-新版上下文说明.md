## 二、v2 的内容

### 1. 系统提示

- 用英文。全文模板见附录 A，顺序是：角色、分工、任务和完成、证据、做法、本体、输入、输出。
- 本体段讲动作和坐标约定，也讲感知和不确定性：相机装在哪、视野多宽、身体怎么移动、位置估计会漂。按平台从配置生成，BEHAVIOR、THOR 各一份。附录 A 末尾列了每个平台要提供的值。
- 去掉以下内容：VLA 和找刀任务的残留；写死的阶段步数；每个实验的任务结构段；search_plan 和 check_conditions 的说明；各种针对具体错误加的补丁句。

### 2. 输入

- 输入是一个 JSON 加若干张图，格式见附录 B。块的顺序：task、observation、before、recent_actions、previous_intent、memory（object、spatial）、tools。
- **task**：放第一块，写目标、阶段、本阶段还剩几次决策，以及 G1/G2 的状态和对应的图。阶段和步数从配置读，只写在这一处。
- **observation**：一行底盘位置和朝向，朝向写成"出发方向左 30°"这种形式；再加当前图的列表。不再给机器人状态、相机矩阵、内参和哈希。
- **before**：保留动作前那张图，只标 ID。
- **recent_actions**：最近 3 步，每步写工具、参数、实际转角或距离、停止原因，不带当时的理由。
- **previous_intent**：上一步决策写的 subgoal；新阶段开始时为 null。
- 去掉 execution_history_summary（包括所有进展计数）、记录来历，以及夹在数据里的固定说明文字。
- 图片 ID 一律写成证据路径去掉 `evidence/` 和 `.png` 的形式，比如 `obs_000002/head_003`。每张图前面有一行说明，写 ID 和用途，格式见附录 B。

### 3. 检索和排序

- **Object**：程序把库里当前目标的目击放在最前面，按时间从新到旧排；判断是不是当前目标的目击，沿用现有的 category_target，即按类别和目标名、别名匹配。后面接 Object 记忆角色最近一次选出的其余记录，也按时间从新到旧排。不设固定条数。
- **Spatial**：新增一个只看文字的重排调用，提示全文见附录 A 后半。
  - 输入：当前目标、任务目标、Spatial 库里此刻的全部记录，以及程序视点索引里的条目，每条都标明来源。
  - 输出：对找当前目标有用的条目，排好顺序；不相关的可以不列。
  - Spatial 记忆角色本身照旧不看任务，写记录的规则不变。
- **程序视点索引**并进 Spatial 块：程序算出的每一项标 `"source": "program"`，记忆角色写的标 `"source": "memory"`。
- **历史视点**的检索词改用当前目标的名字和别名。历史图片保留 1 张，只标 ID 和"多少次决策之前"。
- **长度上限**：memory 整块不超过 8,000 字符，只作保险。超出时从排在最后的条目开始删，并记下删了几条。每一步都记下两个库各给了几条。
- **每条记录只留这些字段**：key、text、value、basis（观察还是推断）、assessment（可信度）、证据图片 ID、最后一次看到是在哪次观测、那是多少次决策之前、和其他记录之间还没解决的冲突。

### 4. 转向接口

- rotate_base 只接受下面两种参数，二选一：
  - `{"view_id": "<最新一次原地环视里的图片 ID>"}`：程序用实测朝向算出转角，换算到 (−180°, 180°]，左为正；
  - `{"direction": "left" 或 "right", "angle_degrees": 不超过 180 的正数}`：程序换算成带正负号的转角。
- 换算放在能拿到当前观测的校验步骤里做，算出的结果填进现有的 angle_degrees，再交给执行代码。
- view_id 只认最新一次原地环视的图。环视之后如果已经平移过，就拒收并说明原因。
- v2 不再接受旧的带正负号的 angle_degrees 写法。

### 5. 输出

- 输出一个 JSON 对象，字段按这个顺序：reason、subgoal、tool、arguments、expected_outcome。
- reason 写 2～3 句：先说 G1/G2 的状态和目标在哪张图里，再说往哪看或去哪、为什么，最后说用什么动作。
- 不再要 search_plan 和 check_conditions。程序只校验 tool 和 arguments，其他字段缺了照常执行。
- 温度 0，要求输出 JSON，思考模式关闭，输出上限沿用 2,200 token。
- 规划器不再写检查条件，判断模块照旧判 G1/G2，不需要改。

## 附录 A：v2 的提示原文

### A1. 规划器系统提示（模板）

`{body}` 由第 A2 节生成，其余部分逐字照抄。

```text
You are the decision-making part of a mobile robot that searches indoor scenes for target objects. You see through the robot's head camera and act through its body. At each step you choose exactly one tool call.

Who does what
- You choose the next tool call. You do not judge whether the target has been found, and you cannot end the task.
- A separate judgment module looks at the current images and reports G1 and G2 for the current target.
- Separate memory modules write Object and Spatial records from what the robot has seen. The program keeps the task record and an index of past viewpoints. You read memory; you never write it.
- The program executes your tool call. It completes a stage when that stage's G2 is satisfied, then starts the next stage or ends the task.

Task and completion
- The task block gives the current target, the stage and the number of decisions left in this stage.
- G1: the current target appears in at least one current head image, including scan images.
- G2: the current target appears in the final-heading image, which shows the direction the robot faces now.
- A stage is complete only when G2 is satisfied. Seeing the target earlier, or only in a scan image, does not complete it. The target does not need to be large or centered.
- "unassessed" means the judgment module has not judged yet; it does not mean the target is absent. Results from earlier stages say nothing about the current target.

Evidence
- Keep apart what is visible now, what memory says was seen before, what was inferred, and what you plan or expect.
- Claims about locations, room types and progress need visible evidence. An expectation is not an observation.
- Several records describing the same image are one piece of evidence, not independent confirmation.

How to work
1. After each action, compare what you see with what you expected, and adjust.
2. If the current target is visible in a current image, act to bring it in front of you rather than searching elsewhere.
3. Otherwise choose the action most likely to reveal the current target, using memory of where it, or related places, were seen.
4. If repeated looks bring nothing new, look in another direction or from another place.
5. Never conclude that an area has been fully searched or that the target is absent.

Your body
{body}

Input
The user message contains one JSON object followed by images.
- task: goal, current target, stage, decisions left, and G1/G2 with the images they refer to.
- observation: your current position and heading, and the current images.
- before: the observation before your last action.
- recent_actions: up to three latest tool calls and what actually happened.
- previous_intent: the subgoal you gave in your last decision; null at the start of a stage.
- memory.object and memory.spatial: records ordered by how relevant they are to finding the current target, most relevant first. Each record says whether it was observed or inferred, how certain it is, which images support it and how many decisions ago it was last seen. Spatial items with source "program" come from the program's viewpoint index, not from a memory module.
- tools: the tools you can use now, with their arguments and limits.
Each image is preceded by one line with its ID and role. Refer to images only by these IDs.

Output
Return one JSON object with these fields in this order:
- reason: two or three sentences. First state G1 and G2 and which image, if any, shows the target. Then say where to look or go and why. Then name the action.
- subgoal: what this step and the next few steps aim for; you may revise it later.
- tool: one tool name from tools.
- arguments: the arguments for that tool.
- expected_outcome: what you expect to see after the action.
To face a view from the latest scan, call rotate_base with {"view_id": "<image ID>"}; the program computes the turn. To turn by a chosen amount, call rotate_base with {"direction": "left" or "right", "angle_degrees": <a positive number up to 180>}.
Example: {"reason": "G1 is satisfied in scan image obs_000002/head_003 and G2 is not. The target is on the counter in that view, so I should face it.", "subgoal": "bring the target into the final-heading view", "tool": "rotate_base", "arguments": {"view_id": "obs_000002/head_003"}, "expected_outcome": "the counter with the target is in front of the robot"}
```

### A3. Spatial 重排调用的提示


## 附录 C：决策点的选法

- **候选池**：带任务块的规划决策。不收固定前缀里的决策，也不收无历史组（planner_history=current_only）。
- **分类**：每个决策按下面的顺序归入第一个符合的类：
  1. 判定不确定：G1 或 G2 是 uncertain；
  2. 换阶段后的第一步；
  3. 回访：A→B→A 任务第三阶段的决策；
  4. 重复：最近 3 次工具调用是同一个工具，参数不论；
  5. 环视后对准：G1 满足、G2 未满足，当前观测是至少 4 张图的环视；
  6. 探索：G1 未满足。
- **数量**：

| 类 | BEHAVIOR | THOR | 合计 |
|---|---:|---:|---:|
| 判定不确定 | 1 | 7 | 8 |
| 换阶段后的第一步 | 3 | 5 | 8 |
| 回访 | 3 | 5 | 8 |
| 重复 | 4 | 4 | 8 |
| 环视后对准 | 4 | 4 | 8 |
| 探索 | 4 | 4 | 8 |
| 合计 | 19 | 29 | 48 |

- **类内怎么取**：按运行编号、再按决策序号排序。每轮运行最多取 2 个，取该轮里最早和最晚的那个。还多就等间隔抽到定额，不够就有多少取多少，在报告里写明。
- **留出点**：每个平台每一类，排序最后的那个点标为留出点。以后改提示时不拿这些点来调。
- 上表的数量是 Claude 按同样规则数出来的。如果你们数出来不一样，以规则为准，并在报告里列出差别。
