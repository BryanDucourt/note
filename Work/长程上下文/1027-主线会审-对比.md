## 一、三方一致的地方

1. **换掉原问法是对的，但新问法太宽，要收窄。**
   - Claude：容易做成测了一堆数、说不出规律的测量文章。
   - GPT：适合阶段诊断，撑不起论文主问题；"任何零结果都能容纳"。
   - Gemini：像工程体检，不像科学问题；"值多少"不绑定任务结构，测出来的是任务难度。
2. **量法的骨架都是三档对比**：无记忆、我们生成的记忆、一份参考记忆。三方的参考记忆造法不同，见第三节。
3. **现在的任务太容易**，要造出记忆必要的任务。主跑 THOR，BEHAVIOR 只做小样本复核，或者复用已有的误报场景。
4. **推广**：结论落在写、送、用这几个环节上，或者对应到通用的功能通道；四个库的名字不承担贡献。再加一个常见设计作对照（滚动摘要，或同样长度的近期原文摘录）。

## 二、两位指出、Claude 漏掉或说错的地方

1. **"无历史"同时拿掉了当前的 G1/G2 判定。**（GPT 第 6 点，Gemini 第 6.2 点）
   - W3 的规划器看不到 Task，也就看不到判断模块最新的判定。所以"有历史 3/6、无历史 2/2"混着两样东西：历史，以及当前的完成信号。
   - 不能把这个差距当成历史的效果。
2. **停下来的是程序，不是规划器。**（GPT）
   - 规划器只是选了 observe，是程序按"G2 满足就结束"收的尾。
   - 正常运行时，第一张图上判定满足就会直接结束，THOR 厨房 7 就是这样，规划器根本没机会看到这个判定。BEHAVIOR 第二周为了做受控任务，才让前缀里的判定不结束任务。
   - 所以条件变化那 3 次误报完成，很大一部分是受控协议造出来的局面。Claude 之前说的"过早停下是上下文缺陷"站不住，至少要打折。
3. **1,145 像素那张近图来自布置筛选，不是在线运行。**（GPT）第二周报告写的是：6 轮在线都没有满足 ≥500 像素的普通近头图。问题里"走近后能拍到 1,145 像素的清楚图"，说的是选点时的核查。
4. **W2 其实没测到 Object 记忆。**（Gemini，GPT 也提到）6 轮延迟回访交接时，规划器看到的 Object 摘录里都没有砧板。下一步应该把库里已有的那条砧板记录补回去，在这 6 个决策点上做探针。
5. **THOR T1 的干预 1–2 步就被覆盖。**（两位都提到）此后两组已经没有区别，用整轮的完成步数说明不了范围丢失有没有影响。
6. **0036 是两个库之间编号没对上。**（Gemini）它被算进了 N=5 的成功率；Claude 认为它是参照过时，Gemini 认为是程序缺陷，两种说法都指向 Spatial 的条目改了、规划器手里的编号没跟着改。损失账已经把它算进去。

## 四、文献核查

- **EMem-Bench**（arXiv 2609.28236，2026-09-23）：已核实存在。附录 D.1 比较"Correct history / Current only / Cue removed / Minimal oracle"四种条件，任务在 AI2-THOR 扩展的多房间住宅和 ProcTHOR 上，指标是成功率。结论是去掉历史或关键线索，成功率大幅下降；只给最小的结构化命题，两个模型分别到 58.2 和 69.1。
  - 含义：三档对比本身已经有人做过，而且就在 THOR 上，是整轮层面的。
- **SafeVantage**（arXiv 2609.36906，2026-09-29）：已核实存在。每条结论连同支持它的视角、位姿、估计位置一起存；用可见性预测决定去哪取证，权衡路程；最后回答"是、否或弃权"。固定 8 或 12 步预算，环境是 ProcTHOR、HM3D、ScanNet。
  - 含义：和 1022 提过的"带观测条件的记忆"、Claude 方案里的参考记忆很接近。这一方向已经有强的竞争者。
- **LongMemEval**：把记忆拆成索引、检索、读取三步，GPT 的说法对。
- **Gemini 列的文献**（凭记忆核对，没有逐篇打开）：
  - MultiON 是 NeurIPS 2020，不是 CVPR 2020；
  - "已证明单房间短视距搜索里记忆差距极小"，这个说法没法确认，像是概括过头；
  - KnowNo 讲的是规划器拿不准时去问人，和"感知错误写进记忆"关系不大。

## 五、Claude 的判断

1. **收窄**：三方都认为要收窄。新意不能再放在"三档对比"上（EMem-Bench 已做），也不能放在"结论带条件"上（SafeVantage 已做）。我们能多做的，是在决策点上把价值拆到写、送、用三步，看它丢在哪一步，而且是在有实际走路代价的模块化系统里。
2. **参考记忆**：改用 GPT 的造法：原样抽出当时已有的证据，不纠错、不加条件，和我们的记忆同样长度上限。理由有两条：
   - 它不混进感知：Gemini 的人工重写会带进人的眼力；
   - 它不是一个提前做好的方法：Claude 原来的造法加了条件，等于把 1022 的方法、也就是 SafeVantage 那类做法，偷偷放进了尺子里。
3. **任务**：GPT 的配对回访最干净：交接时画面相同，只有历史能告诉机器人去哪。再用 Gemini 的硬标准验收：无历史时中位要 ≥5 步才找到。重看代价可以以后作为第二个变量，用两处位置之间的距离来调。
4. **误报完成**：降级成副问题，问的是"完成信号该不该、怎样传给规划器"。正在跑的探针里有"去掉判定"一项，正好检验它。如果规划器选 observe 完全跟着判定字段走，它就是完成信号的问题，不是长程记忆的问题。
5. **第二个模型**：按用户的决定维持结束。Gemini 的结构化解码约束放进暂缓清单，等主线需要第二个规划器时再拿出来。
6. **下一步**：等损失账和离线探针的结果出来，再做第二轮：把综合方案连同结果发给两位挑刺，这一轮算作 Gemini 的那次追问。下一轮可以先做三件事：
   - 把砧板记录补回 W2 的 6 个决策点做探针；
   - 在 THOR 上做配对回访的原型；
   - 写好按原样抽取证据的工具。
