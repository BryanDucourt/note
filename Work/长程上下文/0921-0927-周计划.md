# 周计划：历史证据对决策与执行的作用

**周期：2026 年 9 月 21 日（周一）—9 月 27 日（周日）**

## 一、本周目标与工作边界

**核心目标：围绕一个恢复节点，形成清楚、可复验的配对实验结论，明确历史证据在哪一步改变决策，以及真实执行是否受益。**

本周围绕以下证据链展开：

> 缺少什么历史 → 产生什么错误决策 → 补入证据后如何改变 → 真实执行是否受益。

### 两条工作线并行推进

| 工作线 | 本周重点 | 主要产出 |
| --- | --- | --- |
| 研究主线 | 在恢复节点上比较无历史、精简真实证据和当前系统上下文，定位历史的作用环节 | 一条“历史证据—决策变化—执行结果”证据链 |
| 工程支撑线 | 用最少修改处理运动反馈、目标确认、交互交接和提前停止 | 可重复恢复、可执行、可解释的短程实验入口 |

### 优先级与范围

- **核心交付**：一份清楚的配对实验结论及其可回查材料。
- **启动原则**：周一即准备历史节点，不等待初态搜索稳定。
- **后续验证**：条件成熟时，做少量初态取刀闭环验证。
- **暂缓事项**：完整披萨长跑、完整三维地图接入、四类记忆同时重构。
- **结论要求**：保留正收益、无明显变化和负收益结果；稳定定位“历史有效但自动系统未选出”或“决策正确但执行受阻”，同样作为本周有效产出。

## 三、两批核心实验

### 3.1 实验规模

| 批次 | 实验目的 | 配置 | 短运行上限 |
| --- | --- | --- | --- |
| 第一批：交接诊断 | 区分执行能力、自动交接损失与历史干扰 | 2 个节点 × 3 组 × 5 次配对重复 | 30 次 |
| 第二批：历史必要性探针 | 观察历史证据引起的决策变化及执行收益 | 1 类节点中的选定恢复状态 × 3 组 × 5 次配对样本 | 15 次 |
| **合计** | **形成一个清楚的配对实验结论** | **两批核心实验** | **最多 45 次** |

重复运行采用可控制的种子和交错顺序，并保存实际初态；完全相同的确定性重放单独标记。

### 3.2 第一批：交接诊断

#### 实验节点

- **N0：示范恢复节点。** 此前成功抓刀的示范节点。
- **N1：自主探索近景节点。** 自主探索后接近刀具的位置。

#### 对照条件

| 条件 | 输入与执行方式 |
| --- | --- |
| **A：明确指令参考** | 人工核对当前画面，提供明确目标和短操作指令 |
| **B：当前观测自动交接** | 上层根据当前观测确认目标、选择工具 |
| **C：真实历史自动交接** | 在 B 的基础上加入该节点之前的真实历史 |

#### 执行顺序与降级安排

1. 先跑 A 组，检查节点可用性，再进入 B/C 组。
2. 若参考组频繁失败，优先修复执行条件，暂缓该节点的完整矩阵。
3. 若 N1 缺少可靠恢复快照，先完成 N0 的完整对照，同时建立能够保存和重放的 N1。
4. 旧视频继续用于离线判断实验。

#### 统一记录阶段

> 候选出现 → 有效近景 → 交互目标 → VLA 调用 → 抓取达成 → 视觉确认。

- 每轮标明到达阶段、停止阶段及原因，保留对应输入、判断、证据和工具反馈。
- 执行诊断期间，视觉完成判断仅作旁路记录；所有组采用一致的动作预算和安全停止规则。
- 仿真物理状态只进入独立评估侧。

**本批交付：** 交接对照表及阶段化故障记录，回答明确操作指令能否完成抓取、自动交接在哪一步损失表现，以及加入历史是否引入干扰。

### 3.3 第二批：历史必要性探针

#### 节点选择

**本周优先只选一类：刀曾经出现，目前离开视野。**

这一类节点对应当前的重复扫描和重访问题，重点检查历史位置证据是否影响工作区选择和后续交互。

#### 对照条件

| 条件 | 输入 |
| --- | --- |
| **H0：无历史** | 目标、当前观测和各组共同的当前工具状态 |
| **H\*：精简真实证据** | H0 加上人工核对的少量真实历史事实 |
| **Hcurrent：当前系统上下文** | 当前系统实际组装的历史上下文；目标、当前观测和共同工具状态与其他组一致 |

H\* 可提供“此前在哪看到刀、何时看到、对应哪张图”，保持为可回查的历史事实，避免包含下一步动作答案。

#### 运行与记录

- 每组先做 5 次配对样本，共 15 次短后缀运行。
- 先记录决策，再执行受影响的短后缀。
- 统一记录：
  - 决策是否改变，以及改变了哪个行动分支；
  - 是否返回正确工作区；
  - 获取有效近景的动作数；
  - 是否推进到交互；
  - 所用历史证据及其来源。

**本批交付：** 一条能够回查实际输入、决策和执行结果的历史作用证据链。

## 四、工程支撑与实验固定项

### 4.1 工程修改控制在四项

| 项目 | 最小修改范围 | 保留的信息 |
| --- | --- | --- |
| **可重复恢复** | 保存节点状态、来源前缀、配置和种子；恢复时清空旧动作缓存 | 实际初态、恢复配置、历史前缀 |
| **阶段化记录** | 每轮明确停在哪个阶段 | 当时的输入、判断、证据和停止原因 |
| **运动反馈分离** | 分开记录请求运动量、实际估计、超时与部分完成；记忆根据执行反馈更新 | 请求、反馈及记忆更新依据 |
| **完成判断旁路** | 执行诊断阶段保留视觉判断，统一控制其对停止的影响 | 视觉判断记录、实际停止原因 |

### 4.2 正式对照固定项

- Comet 权重、动作变换、VLA 指令模板及预算保持固定。
- Experience 继续关闭规划输入。
- 开发修改结束后冻结版本，正式对照期间不随样本修改提示词。
- 抓取标准、成功与失败判据、动作预算、安全停止规则在周一固定。
- 周五若进行针对性改进，只调整一个因素，并保留改进前后的版本与配对结果。

### 4.3 暂缓与候选方向

- 本周暂缓完整三维地图接入、四类记忆同时重构和完整披萨长跑。
- Spatial 如需改进，优先处理观测锚点与相关旧图回取。
- 3D-Mem、ConceptGraphs 留作明确瓶颈后的实现候选。

## 五、周五工作由周四结果决定

| 周四观察结果 | 周五优先工作 |
| --- | --- |
| **H\* 改善，Hcurrent 没有改善** | 沿“写入—关联—检索—组装”定位精简证据在哪一步丢失，只修最直接的一处 |
| **H\*、Hcurrent 都改善** | 在另一个恢复状态复验，检查效果能否保持 |
| **H\* 与 H0 接近** | 检查节点是否确实需要历史、模型是否读懂证据、工具是否能执行对应动作 |
| **决策改善，执行仍失败** | 保留决策层结果，定位后续运动或操作瓶颈 |
| **历史组更差** | 定位错误事实、过期状态、无关内容或提前完成判断 |

## 六、周末交付与完成清单

### 6.1 周报回答四个问题

| 问题 | 报告内容 |
| --- | --- |
| **执行能力** | N0、N1 上的明确操作指令能否完成抓取？ |
| **交接损失** | 自动确认与工具选择在哪一步降低了表现？ |
| **历史作用** | 补入哪条历史证据后，哪个行动分支发生变化？ |
| **自动化差距** | 当前系统能否提供并利用这条证据，代价是多少？ |

### 6.2 交付清单

- [ ] 固定节点卡片：节点状态、来源前缀、当前观测、恢复方式、配置和种子。
- [ ] 实验协议：抓取标准、成功与失败判据、预算、停止规则和冻结版本。
- [ ] 第一批交接对照表：各组实际输入、到达阶段、工具反馈、独立评分和故障分类。
- [ ] 第二批历史必要性对照表：历史证据、决策变化、工作区返回、近景动作数及交互推进情况。
- [ ] 周五针对性改进或复验记录：单一调整因素、配对结果、成本和失败分析。
- [ ] 完整实验台账：实际初态、条件、种子、运行顺序、异常及确定性重放标记。
- [ ] 覆盖成功与失败的观测片段，以及几段直接展示组间差异的对照录像。
- [ ] 周报结论：汇总完整证据链，并确定下一阶段优先投入方向。

### 6.3 核心结论记录格式

| 环节 | 需要写清的内容 |
| --- | --- |
| 当前信息缺口 | 当前画面与工具状态缺少哪条关键信息？ |
| 历史证据 | 补入了什么事实，来自哪个时刻、哪张图？ |
| 决策变化 | 无历史时如何选择，加入证据后哪个行动分支改变？ |
| 执行结果 | 是否返回正确工作区、获得有效近景并推进交互？ |
| 自动化差距 | 当前系统在哪一步提供、遗漏或误用了这条证据？ |
| 成本与失败 | 为获取和利用证据付出多少代价，失败发生在哪个阶段？ |
| 下一步 | 优先投入空间关联、检索、生命周期管理，还是继续修复执行接口？ |

**本周完成标准：形成一条有来源、有配对输入、有决策记录、有真实执行反馈的证据链，并据此确定下一阶段的工作重点。**
