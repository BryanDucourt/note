## 一、怎么算跑通

**跑通**：正式的 8 轮里，三条同时满足：
1. 程序错误、工具出错、输入里的特权信息，都是 0；
2. 每个任务至少有 1 轮按离线核对算完成；
3. 每次没成功的操作，都记下原始的失败码，再标一个原因：工具或接口、身体几何、规划器的选择、感知或判断、还不知道。

**读法线**：8 轮里离线完成 4 轮以上，说明这个基线可以直接拿来做实验；不到 4 轮，下一轮先查失败原因。读法线只用来决定下一步，不算过不过。

**防止为了过线去调**：
- 第 2 步（开发）和第 3 步（正式）的数据分开记；
- 正式开跑前冻结代码和配置，记下提交号和配置的哈希，跑的过程中不改；
- 没达到就照实报告。改了以后算新版本，另跑一批，原来那批保留。

## 二、要改的

| 项 | 现在 | 改成 |
|---|---|---|
| 指物 | 只认点到的那个像素 | "点 + 名字"：open、close、pick_up、put 多一个参数，写要操作的东西。程序在点周围约 0.05 图宽（720 图约 36 像素）内，找画面里看得见、名字对得上、离点最近的；找不到就返回失败。物体 ID 不进规划器输入 |
| 开局手臂 | 很多主图大半是自己的手臂 | 单独定义一个收起姿态，开局用它；开局主图里手臂不超过 15%。home 和其他 wrist_view 姿态不动 |
| 拿起以后 | 物体贴着台面；除了升躯干，别的动作一开始就会被判成碰撞 | pick_up 成功后，工具把物体竖直抬离 2 cm，沿途查碰撞；抬不起来就照实返回"拿住了，没抬起"。不换手的朝向，不升躯干，不收手臂 |
| 放下以后 | 手停在物体旁边，官方判定要求手离开 | put 放稳后，手沿原来的接近路线退回，沿途查碰撞 |
| 放置位置 | 在点到的整个设施里找，最多试 12 处 | 只在点到的那块放置区域里找 |
| move_to_point | 不转向、不留距离、没有上限；走到柜子跟前也报"被挡" | 保留现在的平移；加 1.5 m 上限；加一个可选的身前留距参数，由规划器给，默认 0；停在点到的那个表面跟前时，反馈和"被别的东西挡住"分开写 |
| 身体说明 | 写着"升躯干或动手腕都能把东西抬起来"，手腕那一半和代码不符 | 按上面几项改，和代码一致 |
| 规划器输入 | 冻结版设了 `history.recent_tools` = 5 和 6 种上下文类型，RoboCasa 都没设 | 补上；`input_limits.recent_tools` 保持 3，和冻结版一样。用实际发出的请求和冻结版逐项对比，剩下的不同逐条写理由 |
| 模型返回 null | 重试接不住 AttributeError，直接崩 | 所有角色都当成一次格式错误，走修复和重试。改在 RoboCasa 这边，冻结文件不动，报告里写明这处不同 |
| 阶段推进和计分 | 只有"找苹果" | 一个搬东西的阶段，见下 |

**搬东西阶段的推进和计分**：
- **在线**：只看公开的工具反馈。四件事都有了才算完成：至少开成功一次、拿成功、放成功、开过的都关成功。
- **离线**：官方 `_check_success()` 不改；另外核对目标柜门关上了、手空。
- **两边对不上**：在线说完成、离线不对的，记成误完成。
- **规矩**：离线结果只在计分时用，不回流到在线推进，也不进模型输入。

## 三、任务

- **两个官方环境**，布局 1、风格 1、seed 0、苹果：
  - **柜内→台面**（PickPlaceCabinetToCounter）；
  - **台面→柜内**（PickPlaceCounterToCabinet）。
- **开局**：
  - 用官方的机器人起点，不后退、不转身；
  - 手臂在收起姿态；
  - 官方开局会把目标柜门打开，开局准备时把它关上。
- **任务文字**：官方指令，加上目标柜子的说明和"用完关上柜门"。
  - 柜子的说明按开局图写，用看得见的位置和外观，比如在什么东西上面或旁边、几扇门；不用物体 ID。
  - 第 1 步写好，报告里给出原文，之后不改。
- **预算**：每轮最多 32 次决策、600 秒。
- **规划器**：冻结 v2，不开思考。
  - 工具反馈照现在的写法保留，包括被挡的方向和净空；
  - 不加身体信息的实验字段，也就是连续被挡次数、卡住经过。

## 四、做法：三步

**第 1 步：脚本验证，不调规划器**
- 做好第二节的各项。改了行为的地方，做针对性检查。
- 3 个布局 × 两个任务，按完整的合法序列（开、拿、放、关）自动跑。要点的位置由程序按相机投影算出来，只在测试里用，不进模型输入。
  - 事先判定合法的操作，成功率不低于 95%；不穿模，放下的东西不弹飞；每个布局都通过官方 `_check_success()`；
  - 计分要对：完整序列算完成；故意漏关门、放错地方，都要判成没完成。
- 报告里给出开局主图里的手臂面积、柜子说明的原文和输入对比表。
- **停**：解决不了穿模或吸附不稳；或者要改官方判定才能过。

**第 2 步：开发冒烟（布局 1）**
- 规划器跑两个任务。只修工具和接口的问题；冻结 v2 的提示不改，平台的工具说明和身体说明只能改成和代码一致。每一次修改都记下来。
- 两个任务都至少完成过一次，才进第 3 步。工时用完还没做到，就停下报告卡在哪里。

**第 3 步：正式 8 轮（布局 1）**
- 冻结代码和配置，记下提交号和哈希。
- 两个任务各 4 轮，失败的不重跑替换。
- 按第一节判断，跑完停下报告。

**时间**：三步一共不超过 16 个工时。超了就停下，报告做到哪里、卡在哪里。

**报告**：写一页，放进 `docs/`，不下结论。包括：
- 每一步过没过，以及证据；
- 正式 8 轮的原始表：每轮四个操作的结果、失败码和原因；
- 3–5 个原始案例；
- 计时和成本。
