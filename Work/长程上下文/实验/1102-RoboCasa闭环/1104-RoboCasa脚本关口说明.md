## 二、第 2 步：补技能，跑脚本关口

### 要改的

| 项 | 现在 | 改成 |
|---|---|---|
| 指物 | 一个像素点 | open、close、pick、put、press 接受一块区域（掩码），点留作退路。执行器在同一视角的仿真分割里，找区域里像素最多的实体：要占区域一半以上，第二多的要少于它的一半，类型要对得上（拿的是可移动物体；开关的是有门的设施；放的是有放置区域的设施或容器；按的是有按钮的设施）。对不上就返回失败，"目标不明确"单独一个码。不看名字；实体的名字和 ID 不出现在返回给规划器的字段里 |
| 按（新增） | 没有 | press(目标, button)：button 取这台设施自己有的按钮（咖啡机 start；微波炉 start、stop）。手指沿直线碰到按钮，再退到离按钮 0.15 m 以外。沿途查碰撞，只许碰这个按钮；够不着、会撞，就照实返回 |
| 设施状态 | 不更新 | 每个工具做完，调用一次 RoboCasa 自己的状态更新（`Kitchen.update_state`）；按的时候，手指碰着按钮时再调用一次。不许直接改 `_turned_on` 这类状态 |
| 放进容器 | 只能放到设施的放置区域 | 也能放进可移动的容器，比如碗；放下后照样跑物理、看稳不稳 |
| 放置点 | 在点到的整个设施里，离点最近的地方 | 设施或容器自己有固定放置位置的，用它：咖啡机出水口下面、微波炉里面、碗里。台面这类大面，用区域里落在这个实体上的像素的三维中心附近 |
| 端着容器 | 只附着拿起的那一个 | 拿起容器时，把当时在容器里的物体一起附着，放下时一起松开，再跑物理。这是近似，报告里写明 |
| 拿起以后 | 物体贴着支撑面 | 拿起后竖直抬 2 cm，沿途查碰撞；抬不起来就照实返回"拿住了，没抬起"。不换手的朝向，不升躯干，不收手臂 |
| 放下以后 | 手停在物体旁边 | 放稳后，手沿原来的接近路线退回，沿途查碰撞 |
| 开关门 | 只查门和机器人 | 门扫过的地方也查所有物体；碰到就停在碰到之前，照实返回 |

不改的：操作时锁住底盘和躯干，现有的检查保留；move_base、move_to_point、set_torso、wrist_view 不动。

改了行为的地方，各做针对性的检查。

### 脚本关口

- **回合**：测试组的 3 个厨房 × 两个任务 × 2 个种子，共 12 回合。按官方开局，不改官方的摆放。
- **先冒烟**：先用 1 个回合把每种操作都走一遍，没问题再跑完 12 回合。单个回合没通过不停，照实记下。
- **序列**：
  - PrepareCoffee：拿杯子 → 放到咖啡机下 → 按开始；
  - SteamInMicrowave：从水槽拿菜 → 放进碗 → 拿碗 → 走到微波炉前 → 放进微波炉 → 关门 → 按开始。
  - 站位和躯干高度由测试程序算，可以用仿真信息，可以试几个；再用 move_base、set_torso 走过去。
  - 目标区域由测试程序从仿真分割取（理想编号），只在测试里用。
- **要做到**：
  - 12 回合里至少 10 回合通过官方 `_check_success()`，每个厨房的每个任务至少 1 回合通过；
  - 不穿模，放下的东西不弹飞；
  - 没通过的回合，每次失败的操作记下原始失败码，再标一个原因：工具或接口、身体几何、官方判定触发不了、还不知道；
  - 计分要对：漏一步（不按开始、不关微波炉门、碗放在台面上），官方判定都要判成没完成；
  - 绑定要稳：每个操作再用两种不准的区域各绑定一次，只绑定、不执行：理想区域的外接框，以及往外扩 5 像素。结果只能是同一个实体或"目标不明确"，不能绑到别的实体上。报告各种结果的次数。
- **顺带存图**：每个成功的操作之后存一张头部主相机图，格式同第 1 步，放进 `outputs/robocasa-frames-20261104-1/gate/`。
- **停**：解决不了穿模或附着不稳；或者要改官方判定才能过。
