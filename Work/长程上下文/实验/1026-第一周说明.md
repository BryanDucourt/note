## 二、要做的事

### T1 挑物体

- **抽图**：从 1020 以来的已有运行（包括三轮 A→B→A 试点）里抽头部图。
  - 每种候选物体约 20 张，按 A5 像素数分几档；
  - 另外加一些没有该物体的图；
  - 抽图只用评估端的信息，属于实验设计。
- **候选物体**：烤盘、砧板，以及场景里其他中大物体，比如碗、面团。具体有哪些，看能找到多少帧。
- **问法**：每张图用冻结的判断提示词问"图里有没有能认出的 X"，只给单张图、不给历史，每张问 3 次，算判对的比例。按物体和像素档分别列表。
- **选择**：选出 3 种，要求在机器人常见的观看距离下判对的比例高，参考线是 80% 以上。
  - 范围测试先用其中一种；
  - T1 出结果之前，可以先用砧板或烤盘搭 T2。
- **记下图片编号**：以后估计"压制率"时不再用这组图片（实验说明第二节：取样分开）。

### T2 范围测试：搭建并试跑

设计见实验说明 4.1 节。任务用多目标任务的配置，只设一个目标、一个阶段。

要实现四样东西，都用新配置启用：

1. **reset 时摆放目标**：
   - 配置里写明物体、台面（例如 `bar_egwapq_0`）、放在哪一段、什么姿态；
   - 摆放以后静置若干步，核对物体是否稳定（位移小于 1 厘米）；
   - 位置只写进评估端的记录。
2. **脚本前缀**：
   - 配置列出前几步的动作，代替规划器的决策；Object、Spatial 和判断照常运行；
   - 记下前缀走完时的底盘位姿和头部图哈希，用来核对几次重放是否一致。
3. **前缀结束时替换记录**：把 Object 库里关于目标的那条记录换成下面一种版本。Object 没写这条，就新加一条。其余各库和 Task 完全不动。

   | 版本 | 写法 |
   |---|---|
   | 保留范围 | 写明是哪张图、图里看到的是台面的哪一部分、没有看到目标，并说明台面的其余部分还没看过 |
   | 丢掉范围 | 用同一张图作证据，但写成整个台面上都没有目标 |
   | 等长无关改写 | 改一处和目标无关的内容 |
   | 原样 | Object 自己写的那条 |

   要求：
   - 两种改写的字数相差不超过一成；其余字段（评估、证据引用）相同；
   - 替换前后的记录都写进运行清单；
   - 改写只用机器人当时看到的内容来描述范围，比如"画面左侧那一段"，不用仿真真值，不写坐标和实例名。
4. **评估端要量的东西**：
   - 前缀之后的每张头部图里，目标是否入画（A5 像素数）、是否认得出（像素数和可见比例）；
   - 目标第一次入画是第几次决策；
   - 完成用了几次决策；
   - 结束原因：找到、误完成、预算用完、卡住；
   - Object 关于目标的记录有没有被改，在哪一步改的。

**怎么选布置**：先把选择规则写进文档并提交，再按规则选。
- 用 S1 的静态工具（`analysis/paper1_static.py`）看虚拟头部图；
- 起点的视野里能看到台面的一段，另一段完全不在视野里；目标放在不在视野的那一段；
- 之后要能走到看全那一段的位置；
- 选 1–2 种布置。

**试跑**：
- 两种主要版本（保留范围、丢掉范围），每种 3 次，1–2 种布置，共 6–12 轮；
- 前缀之后最多 15 次决策；
- 预算允许的话，"原样"和"等长无关改写"各跑 1–2 轮，作为参照。

### T3 在已有日志里找例子

- **找什么**：在 1020 以来的运行里，找三类上下文错误的真实例子：
  - 观测范围丢失；
  - 该记的没记住：没写进记录，或者写了但没送到规划器；
  - 参照过时：机器人移动以后，旧图上的位置还被拿来用。
- **每个例子写什么**：每类最多 10 个，每个写清哪一轮、第几步、记录原文、当时的证据（图和 A5）、规划器下一步做了什么。
- **标注规则**：用这些例子把标注规则写成一页。每个错误分别标两项：
  - 从哪一段开始：看到的机会、感知、写入、保留和选取、使用；
  - 什么让它持续。
- 这些例子只用来定规则，不算发生率。
