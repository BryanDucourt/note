# 新仿真适配说明（1026）

**状态**：草稿，先给用户看。

**读者**：实验机上的第二个 GPT 会话。代码路径都相对仓库根目录。

**这件事要回答的**：
- 我们的系统能不能在第二个仿真器里跑通？
- 跑得多快？
- 要正式用起来，还要多少工作量？

只做可行性适配，不做研究实验。

**为什么要做**：
- BEHAVIOR 慢：每次决策约 43 秒，大半花在物理步进上；
- 现有的 10 个实例，目标都在同一个厨房台面上，场景几乎没有变化。

第二个仿真器如果快、场景多，可以用来补场景的多样性；以后也能做"机器人自己改变世界"的实验。

## 一、选哪个

先试 **AI2-THOR**，用 ProcTHOR 程序生成的房子；跑不起来，再试 **Habitat**，用 HSSD 场景。

| | AI2-THOR（ProcTHOR） | Habitat（HSSD） |
|---|---|---|
| 场景 | 上万个程序生成的房子，另有 30 个手工做的厨房 | 约 200 个合成的房子 |
| 摆放物体 | 有现成的接口 | 可以，要多写一些代码 |
| 每张图的真值 | 实例分割、深度、物体元数据 | 语义传感器、深度 |
| 速度 | 快 | 更快 |
| 以后让机器人改变世界 | 有简化的拿起、放下、开关 | 要用 Habitat 3.0 的重排任务 |
| 画面 | 偏游戏风格 | 更接近真实 |
| 要先试的风险 | 在 RTX 5090 上能不能无头渲染 | 预编译包支不支持新显卡 |

先选 AI2-THOR 的理由：
- 场景多，能直接补上"只有一个台面"的问题；
- 摆放物体和每张图的真值都是现成的；
- 以后可以直接用它的拿起、放下；
- 用大模型做具身智能体的工作很多都在它上面做，审稿人熟悉。

它的小物体做得比较粗，但刀已经不是主要目标，影响不大。

接口和名称以实际安装的版本为准。

## 二、隔离

实验机是共享环境，下面几条必须遵守：
- **单独的目录和分支**：用户会先建好单独的工作目录 `../lhc-sim2`，分支 `codex/sim2-feasibility`。只在这里工作，提交并推送这个分支，不要合并进共享分支。
- **单独的 Python 环境**：新建一个环境，不改 BEHAVIOR 的环境。
- **不碰 BEHAVIOR**：不碰常驻的 BEHAVIOR 会话、它的进程和已有的运行记录。
- **显存**：开跑前看显存，常驻会话约占 14 GB；分辨率用和头部图相同的中等分辨率。另一个 GPT 在跑 BEHAVIOR 试跑时，不做大批量渲染。
- **下载的资源**：放在 Git 外，版本写进运行清单。

## 三、步骤

### S0 兼容性（不超过半天）

- 在新环境里装 AI2-THOR，无头渲染一个厨房，拿到 RGB、深度和实例分割三种图，分辨率和我们的头部图一样。
- 测每一步的耗时。
- 跑不起来，就换 Habitat 试半天；两个都不行，就停下来报告卡在哪。

### S1 适配层（不超过 2 天）

**写法**：
- 照现有适配层的接口（`lhc_demo/adapters/behavior.py`）写一个新的适配层；
- 不改 BEHAVIOR 的代码路径；
- 共用代码如果要改，用配置开关隔开，再跑相关的已有检查。

**要实现的内容**：

| 部分 | 要做到什么 |
|---|---|
| reset | 加载场景，摆放目标物体 |
| 观测 | 头部 RGB、深度、位姿。没有腕部相机，用"只看头部图"的设置 |
| 工具 | 环视（5 个朝向）；走向图上一点（用深度算出那一点，再走到离它最近的可达位置）；小步平移或转身；原地观察。碰撞就停下，作为防护 |
| 判断 | 沿用分块。位置检查依赖台面高度的先验和相机参数：能按同样规则实现就实现，算不了就关掉，并写明 |
| 评估端 | 用实例分割算每张图里各物体的像素数、框和可见比例，相当于 A5；不进模型输入 |

### S2 冒烟运行（不超过 1 天）

- 用冻结的系统跑：提示词、DeepSeek、分库和判断都和 BEHAVIOR 上的一样。
- 选 2–3 个房子，每个房子跑 2 轮"找一个物体"，每轮最多 15 次决策。
- 看四件事：
  - 整个闭环能不能走完；
  - 信息边界审计能不能通过；
  - 每次决策的墙钟时间和 token；
  - 目标够大的时候，判断能不能认出来。
