## 一、损失账

**范围**：
- BEHAVIOR：第一周 T2 的 8 轮（见 `docs/week1-20261026-report.md`），第二周 W2 的 12 轮、W3 的 4 轮；
- AI2-THOR：第二周 T1 的 32 轮、T2 的 10 轮；
- 不算只做选点、静置的诊断轮次。
- 有注入的轮次照样记，注明版本；和注入记录有关的损失单独标出。

**每一轮记**：
- 结果：正确完成、误报完成、预算耗尽、暂停或失败（写明原因）；
- 自由决策数；
- 每个损失事件。

**什么算损失事件**：
- 失败轮：导致失败的那一步。整轮算作损失，标出决定性的那一步。
- 成功轮：对照评估端的真值，按当时已有的观测看明显多余的决策，包括：
  - 已经看到目标却没完成，反而走开或继续搜索；
  - 重看一处当时已经看清的地方，没有得到新信息；
  - 走向一条错误记录所指的地方；
  - 被校验拒绝，或导致暂停的规划。

**每个损失事件标三项**：
1. **起因**：判断认错、Object 写入、Object 选取、Spatial、Task、规划器推理、工具或校验、布置或仿真。
2. **上下文有没有参与**：做这个决策时，是否有某条记录或某段历史影响了它。参与的话，引用原文和记录 ID；拿不准的列为候选，不算确认。
3. **代价**：多用了几次决策，或者整轮失败。

**汇总**：一张表。
- 行是起因；
- 列是失败轮数和多余决策数，各自分成"上下文参与"和"未参与"；
- 分母是全部轮次和全部自由决策。

## 二、离线探针（gpt 做）

**材料**：BEHAVIOR 条件变化 0040–0045，各轮首次自由规划（D000001）的冻结请求。图片和其余文字一律不变。

**改法**：

| 改法 | 用在哪几轮 | 做什么 |
|---|---|---|
| 原样 | 0040–0045 | 不改，量重复问的一致性 |
| 加板状物记录 | 0041、0043、0045 | 把 0040 那条标为"不确定"的板状物 Object 记录加进去 |
| 加无关记录 | 0041、0043、0045 | 加一条长度相近、描述另一件可见物体的 Object 记录 |
| 删板状物记录 | 0040、0042 | 去掉那条板状物记录 |
| 换成无关记录 | 0040、0042 | 那条记录的文字换成长度相近的、另一件可见物体的描述 |
| 去掉判定 | 0040–0043、0045 | Task 里只删 G1、G2 的判定结果，其余不动 |
| 判定附像素大小 | 0040–0043、0045 | 在 G1、G2 的判定后面附上引用框的像素大小 |

**规则**：
- 每种改法、每一轮问 5 次。模型、参数、提示词、解析代码都和在线一致。
- 只改表里列出的字段，其余字节不变。每个改后的请求都存档，记哈希。
- 加进去的只能是在线就有的信息，不放评估端真值。

**量**：
- 每种改法下，规划器选 observe、走近、scan 和其他工具各几次；
- 理由里有没有引用 G1/G2 的判定，或者那条板状物记录。

**要回答**：
1. 规划器去不去核实，是跟着 Task 里的判定走，还是跟着 Object 里的记录走？
2. 判定后面附上像素大小，规划器会不会去核实？

**规模**：约 130 次调用，约 200 万 token。
