## 二、v3 改了什么

只改下面这些，其余（图像、观测、最近 3 个动作、记忆记录、工具、身体信息字段、BEHAVIOR 的身体说明、THOR 的语义工具说明）一律照原请求不动。英文原文见附录。

1. **任务块**：不再有 G1/G2，改成"当前阶段"，信息量和 v2 一样，只是写法不同：
   - 类型：find（找）或 carry（搬），和 v2 的阶段一一对应；
   - 涉及的物体：照任务原文；
   - `done_when`：照任务原文写这个阶段怎么算完成。find 写明"目标出现在你现在正对方向的那张图里"，保留 G2 的意思；
   - find 阶段给 `seen_in`：只列**这一次观测**里判断模块认定看到了目标的图像编号（原来 G1 的信息），不列历史；
   - carry 阶段列出各小条件现在的状态（手里拿着没有、放下成功没有、开过的容器关了没有）。这些来自 v2 输入里已有的工具反馈和 holding 状态；
   - find 阶段不写 met、not_met，因为规划器被叫来时它总是没满足。
2. **系统提示的"任务和完成"一节**：说明阶段和完成条件；由程序和判断模块判完成，规划器不判。
3. **系统提示的"怎么做"一节**：
   - 先核对上一步；
   - 上一步没达到预期，就换做法；看不清对没对上，就写 unknown，不强行换；
   - 选最能推进当前阶段完成条件的动作，并引用证据。
   - 去掉"选最可能让目标露出来的动作"。
4. **输出顺序**：`last_step_check → evidence → why → tool → arguments → expected_change`。
   - `evidence` 是 0–3 个图像编号或记忆的 key；
   - 去掉 subgoal，因为它在"为什么"前面等于先定意图、再找理由，和 expected_change 也重复。
5. **带回上一步**：输入加 `previous_expected_change`，照原来那一步回答的 `expected_outcome` 原文转录，不改写、不补成 v3 的写法。`previous_intent` 照旧保留。
6. **不改的**：挑记忆这一步不重跑，记忆照原请求；这一版不加多步计划。

## 附录：v3 的英文原文（替换 v2 的对应段落）

**Task and completion**
```text
- The task is a sequence of stages. The task block describes the current stage: its type (find or carry), the objects it involves, and the condition that completes it (done_when).
- The program and the judgment module decide when a stage is complete; you do not.
- For a find stage, seen_in lists the images from the current observation in which the judgment module has seen the target. A find stage is complete when the target appears in the image of the direction you face now.
- For a carry stage, the task block lists the current status of each part of done_when, from tool feedback.
```

**How to work**
```text
1. First check the last step: compare previous_expected_change with what actually happened, using recent_actions and the current images.
2. If the last action did not produce its expected change, do not repeat it unchanged; change the approach. If you cannot tell, say so.
3. Choose the action that best advances the current stage's done_when condition, using the current images and memory. Cite the evidence you rely on.
4. Keep apart what is visible now, what memory says was seen before, and what you infer or expect.
```

**Output**
```text
Return one JSON object with these fields in this order:
- last_step_check: one sentence: what you expected from the last action, what actually happened, and whether they match (yes, no, partly or unknown). At the start of a stage, write "stage start".
- evidence: up to three image IDs or memory keys that this decision relies on.
- why: one or two sentences on how this action advances the current stage, based on that evidence.
- tool: one tool name from tools.
- arguments: the arguments for that tool.
- expected_change: the observable change this action should produce, such as the base moving about 1 m toward a place, holding becoming an object, or a container opening or closing.
```

**Example**（中性的找东西例子，不涉及受阻和操作）
```text
{"last_step_check": "I expected the sink area to come into view after turning right; it did, so they match.", "evidence": ["obs_000004/head_002", "object:mug_1"], "why": "Scan image obs_000004/head_002 shows the counter beside the sink, where memory record object:mug_1 says the target was seen.", "tool": "rotate_base", "arguments": {"view_id": "obs_000004/head_002"}, "expected_change": "the counter beside the sink is centered in the facing image"}
```
