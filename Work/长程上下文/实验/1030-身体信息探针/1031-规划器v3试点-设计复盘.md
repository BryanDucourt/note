# 规划器 v3 两次离线试点：设计复盘（1031）

起因：重跑以后（[[1031-规划器v3离线试点重跑-原始结果]]），用户说"我觉得是不是再分析一下实验设计和输入输出，感觉还是有问题"。Claude 查了两次试点的输入原文、每类点的回答和计分标签。

## 一、先说结论

这两批的分数基本说明不了 v3 好不好：大部分点本身就比不出差别，或者比出来的是别的东西（点偏、看不清小目标）。问题有四层。

## 二、点和"正确动作"的标签有问题（规则是 Claude 定的）

| 类 | 实际情况 | 结果 |
|---|---|---|
| a 打开容器 | 6 个点里，3 个是"冰箱里的生菜"，冰箱就在眼前，任务也点名了冰箱，两版都选打开，全对；另外 3 个是"柜子里的水壶"，任务没说是哪个柜子，规划器不可能知道开哪个，两版都在环视或走近柜子，全算错 | 两版都是 9/18，比不出差别 |
| b 拿起目标 | v2 没过的 13 次里，11 次是选对了拿起，但点在 (352, 460)，就是试点里点到冰箱铁丝架上的老问题；v3 没过的 11 次里，9 次是先走近 | 比的是点偏和先走近，不是格式 |
| c 放下目标 | 台面在画面里只有 49 个像素；两版都说"台面之前在左边看到过"，先转过去。这一步合理，但标签不认转身 | 两版都是 0 |
| d 关上容器 | 只有 4 个点，其中 1 个点画面里根本没有要关的冰箱 | 点太少 |
| 受阻 | 格式本来就不针对被挡这件事 | 两批都是 0 |

真正能比出东西的，只剩 e 和 f（共 10 个点），f 两版一样。

## 三、v3 在 THOR 上改得比设想的少，有一处还改坏了

- **搬东西的阶段**：v2 的输入里本来就有"操作进度"：`stage_kind`、`stage_instruction`、`operation_progress`（开过、拿过、还没放、还没关）。v3 的条件状态只是换了个写法，真正的差别只剩系统提示和输出顺序。
- **v2 自身的矛盾**：c 类那个点，生菜拿在手里，v2 的输入写着 G1、G2 都满足，可阶段并没有完成。
- **找东西的阶段**：v3 把"判断模块看到了"写弱了。
  - v2 写的是 `G1: satisfied, images: [obs_000001/head_003]`，18 次都转了过去；
  - v3 写成 `seen_in: [obs_000001/head_003]`，回答却说 "No toaster is visible in any scan view"，然后朝那张图的台面走过去"凑近看"。
  - 烤面包机在那张图里很小。判断模块是把原图切块放大看的，规划器看的是整张缩小的图，看不清就不信这个字段。

## 四、离线单步比不出 v3 想要的效果

- v3 的核心是每一步核对"上一步的预期"，这要在连续几步里才起作用。
- 冻结的点，上一步是 v2 做的，带回来的预期也是 v2 那种"会看到什么"，比如 "Five views around the robot revealing more counter surfaces and possibly the toaster"。
- 离线只看下一步，测不到"预期没达到 → 换做法"这个循环。唯一能测到的是受阻的点，可那里卡在"不会绕路"，换格式也没用。

## 五、噪声大

- 同样的输入，两批之间能差 5/18：b 类里没改过的 v2，上一批 10/18，这一批 5/18。
- 每类只有 4–6 个点，每点 3 次，几次的差别都在波动范围里。

## 六、这两批还是说明了几件事

- 修掉问题以后，v3 没有把东西弄坏：a、b、d、f 大致持平。
- v3 的输出更容易出 JSON 错误（第一次回答 8–12/117，v2 是 1–3/117）。在线有自动修复，但这是成本。
- 找东西时，"判断模块看到了"必须写得明确；换个字段名，它就不信。
- 只改格式，解决不了起点 108 的绕路，和之前几批一致。

## 七、下一步的几种走法（等用户定）

1. **在 THOR 上做在线小试点**：比 v2 和 v3 走完整任务时完成了几个阶段、用了几步、重复失败了几次。这样才测得到"核对上一步"的作用。要先定"柜子的写法"（任务里说清是哪个柜子），这是 1030 试点读法里还没定的一条。
2. **继续离线，但重做点集**：只挑"有唯一合理动作，而且 v2 在那里犯过可以纠正的错误"的点；标签允许几种合理做法；同时把 v3 里"判断模块看到了"写明确。
3. **先回到主线**（上下文值多少）：格式先用修好的 v3，放到在线实验里一起测。
