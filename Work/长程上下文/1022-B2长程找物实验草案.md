# B2 长程找物实验（草案，1022）

**状态**：草案，供讨论。B1 跑完后再定稿；定稿前不发给 GPT。

**一句话**：机器人不动手，只靠"走"和"看"，在厨房里按顺序找到并认出几个物体，最后再回去找第一个。目的是造出 B1 里没有的情况：要用的东西已经离开视野很久，记忆越积越多，以前顺带看到的东西后面用得上。

## 一、为什么要做

B1 是短程基线：每轮 4 到 20 次决策，找到刀就结束。它能暴露的是短程里的问题：
- 认不出眼前的东西；
- 一开始就看错，错误往下传；
- 旧记录压过新证据。

它暴露不了三类长程问题：
- **离开以后再回来**：要用的东西已经很久没出现在画面里，只能靠记忆；
- **记忆越积越多**：记录变旧、互相矛盾，错误累积；
- **跨子任务复用**：找 A 时顺带看到的 B，轮到找 B 时有没有用上。

## 二、要回答的问题

1. **回访**：机器人离开一个见过的物体、过了很多步之后，记忆能不能把它带回去？比第一次找要快多少？
2. **顺带看到**：找前面目标时看到的后面目标，有没有被记下来，轮到它时有没有用上？
3. **长程里的记忆质量**：记录变旧、互相矛盾、身份认错的比例，会不会随步数上升？对动作的影响有多大？
4. **成本**（附带测量）：上下文和 token 怎样随步数增长。

## 三、任务

**场景和起点**：沿用 make_pizza，从 B1 里能走到厨房的起点中选。170、59 是已知的难点起点，B1 里如果到不了厨房，就不放进 B2。

**目标**：在头部相机里按顺序找到并认出 4 个物体，最后回到第 1 个，一共 5 个阶段。

下表的候选物体来自 A5 已有的记录，全部在厨房、放在开放的表面上，不用开门开柜就能看到。像素数是到目前为止各次试跑里头部图的最大值。

| 候选 | 最大像素数 | 备注 |
|---|---:|---|
| 披萨面团 | 6,456 | 中等大小 |
| 烤盘 | 9,246 | 中等大小 |
| 砧板 | 3,633 | 中等大小，上面放着洋葱 |
| 碗 | 4,694 | 中等大小 |
| 冰箱、烤箱 | 4.5 万以上 | 很大，太好认，只适合当容易的一档 |
| 刀 | 410 | 很小；现在 200–300 像素的那一档基本认不出 |
| 洋葱 | 495 | 很小 |

**选目标的规则**（先写下来再选，不看结果改）：
- 相邻的两个目标，从同一个位置不能同时看到，保证中间必须走动。用 A5 检查。
- 第 1 个目标要选最好认的，否则后面的回访阶段就没法测。
- 至多放一个小目标（刀），不放在第 1 个。
- 顺序事先定好，所有轮次都一样。

**例子**（只是示意）：披萨面团 → 冰箱 → 砧板 → 烤盘 → 回到披萨面团。

**每个阶段怎么算完成**：
- 程序为当前目标生成一条目标条件，和 B1 的 G1 一样，只看当前的头部图；
- 当前目标确认后，Task 切到下一个目标；
- 每个目标最多给 20 次决策。用完还没找到，就记为失败，进入下一个目标，保证每轮都能走到最后的回访阶段。

**规划器和 Object 知道什么**：建议一开始就把全部目标告诉它们，但规定按顺序找。这样 Object 才会把顺带看到的后续目标记下来，问题 2 才测得出。另一种做法是一个一个告诉，要求更高，留到以后再说。

**预算**：每轮最多 100 次决策（5 个阶段，每个 20 次），约 18,000 步，墙钟上限 1.5 到 2 小时。

## 四、前提（缺一不可）

1. **B1 跑完，系统定版。** B2 在定好的版本上只加第 5 条的任务功能。
2. **识别过关。** 用 A5 已有的帧，逐个检查候选目标在常见大小下能不能被认出来。刀如果仍认不出，要么先做识别辅助，要么不把它放进目标。
3. **修好 Object 的"上次见过"**，就是补充五里的那一项。否则回访阶段测出的"记忆没用"，可能只是因为该记的没记住。
4. **给记忆调用的输入设上限。** 现在每一路记忆每一步都收全部旧记录和相关的原图，每次决策的 token 随步数线性增长，总量按平方增长。上限要事先定好，比如每路最多若干条记录、若干张图，并记进 manifest。这个上限本身也是研究变量。
5. **任务功能**：
   - Task 能管理目标序列，并为每个阶段生成目标条件；
   - Object 的查询改成目标列表；
   - 评估端为每个阶段自动出表。

## 五、测什么

| 指标 | 怎么得到 |
|---|---|
| 每个阶段找到没有，用了多少次决策、多少步 | 程序记录 |
| 回访效率：回到第 1 个目标用的决策数，和第一次找它比较 | 程序记录 |
| 回访开始那一刻，Object 里有没有第 1 个目标的正确"上次见过"；规划器有没有朝那个位置走 | 记忆库加 A5，人工抽查 |
| 顺带看到：后续目标在前面阶段出现在画面里多少次，Object 记下了几次，轮到它时有没有用上 | A5 加记忆库 |
| 记忆质量随步数的变化：每个库的记录数；可见性和 A5 不符的记录占多少；抽样人工核对错误 | 记忆库加 A5 |
| 成本：每次决策的 token 和耗时，随步数怎么变 | 审计记录 |

**之后的对照，不在第一次试点里做**：
- 在回访开始那一刻做单事实对照：把"上次见过"删掉，或者换成错的，看规划器的下一步变不变；
- 可选：在线跑"没有记忆"的对照。

## 六、成本估算

依据：0010–0012 三轮的实测。
- 每次决策平均约 7.7 万 token，耗时约 37 秒；
- token 会随步数增长：第 2 次约 6.3 万，第 19 次约 9.6 万，大约每多一次决策多 1.8 千。

| 情况 | 每轮 | 20 轮 |
|---|---|---|
| B1（参照） | 30 万到 170 万 token，4 到 12 分钟 | 约 2,000 万 token，2 到 4 小时 |
| B2，不限制记忆输入，80 到 100 次决策 | 1,100 万到 1,500 万 token | 2.2 亿到 3 亿 token |
| B2，限制后每次决策保持约 8 万 token | 650 万到 800 万 token | 1.3 亿到 1.6 亿 token |
| B2 的时间 | 每轮约 50 到 60 分钟，不含冷启动 | 约 17 到 20 小时 |

**建议先跑试点**：5 个起点各跑 1 轮，大约 3,500 万到 7,500 万 token、5 个小时，先看各阶段的成功率和回访阶段的样子，再决定要不要跑满 20 轮。

## 七、风险

- **认不出目标，整轮卡住。** 每个目标设上限，到了就跳到下一个。第 1 个目标一定要选最好认的。
- **目标离得太近，空窗不够长。** 所有候选都在厨房里，按第三节的规则，用 A5 检查相邻目标不能同框。
- **输入一长，规划器表现变差。** 这本身就是要测的现象。每次都记下规划输入的长度。
- **防护在厨房角落频繁拦停。** 照实记录，不为 B2 放宽余量。
- **成本超出预期。** 先跑试点。

## 八、需要用户定的事

1. 目标列表和顺序。
2. 全部目标一开始就告诉，还是一个一个告诉。
3. 当前目标确认后，由程序自动进入下一个，还是由规划器自己声明。自动进入更简单，能去掉"规划器和判断标准不一致"这个干扰；代价是测不到规划器自己决定什么时候停。
4. 记忆输入的上限怎么定。
5. 试点的规模。

## 九、顺序

B1 跑完 → 第四节的前提逐项满足 → B2 试点 → 用户决定是否跑满。
