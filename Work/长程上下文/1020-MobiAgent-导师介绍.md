# MobiAgent 介绍（给导师）

**论文**：*MobiAgent: Dual-Loop Recursive Policy Self-Improvement for Long-Horizon Mobile Manipulation*
- 作者单位：香港大学、Astribot、南方科技大学
- 发表：[arXiv 2610.03476](https://arxiv.org/abs/2610.03476)，2026 年 10 月
- 代码：已在 GitHub 开源（kaiknower/MobiAgent）

本文依据论文正文和公开代码，代码看的是最新提交 `ffce244`。

## 一句话

用大模型做规划和核查，用一组共享主干的技能策略做执行，在 BEHAVIOR-1K 上完成长程移动操作；再把成功的执行录像自动切分，用来继续训练技能。

## 动机

- **长程任务里错误会累积。** 移动和手臂操作交替进行，前面的小偏差会传到后面。端到端的 VLA 通常一个任务训一个模型，缺少多阶段推理、失败后重规划和持续学习的能力。
- **分层智能体扩充技能成本高。** 它们能拆解任务，但技能库靠人工标注来扩充。
- **他们想同时做到两件事：**
  1. 执行中能发现失败，并决定重试还是重规划；
  2. 离线不靠人工标注，把成功的经验变成新的训练数据。

## 怎么做的

**内环：执行任务**

| 部件 | 做法 |
|---|---|
| 规划器（GPT-5.4） | 看任务目标、当前头部图像，以及已结束子任务的文字记录（每条附核查理由）；每次只输出下一个子任务：技能类型、指令、目标物体 |
| 技能执行 | 6 个动作专家：移动到、拿起、放入、放上、打开、关闭。它们共用一个由 π0.5 初始化的视觉语言主干，按技能类型路由 |
| 反思核查员（GPT-5.4） | 每执行几秒动作检查一次。看当前子任务最近几次尝试结束时的三路相机画面和夹爪状态，判定"完成/未完成/出错"，并给出理由和证据 |
| 推进规则（代码写死） | 完成 → 进入下一个子任务；未完成 → 重试；出错或重试次数用完 → 把失败理由交给规划器重新规划 |

**外环：自我改进**

Gemini 把成功的录像切成技能片段；GPT-5.4 核对切分描述，并归入已有技能；最后微调对应的技能专家。切分 800 个片段约需 0.8 小时，人工约需 29 小时。

## 结果

- **主结果**：BEHAVIOR-1K 上 4 个任务，每个任务 10 次。平均成功率 65.0%，而 2025 年 BEHAVIOR 挑战赛的冠军方案 π0.5-TA（每个任务单独训练一个模型）是 42.5%。
- **消融**：
  - 去掉核查员：10.0%，降幅最大；
  - 用固定子任务代替规划器：20.0%；
  - 去掉全局重规划：40.0%。
- **外环迭代**：
  - RoboCasa 上，从 π0.5 的 7.5% 提升到 27.5%；
  - Astribot S1 真机上，π0.5 为 10.0%；MobiAgent 自举后为 32.5%，迭代后为 57.5%。

## 存在的问题

1. **系统最依赖的核查环节，本身没有被评估。** 去掉核查员后成功率从 65% 掉到 10%，可见系统高度依赖它；但论文没有报告核查本身的准确率，只在失败分析里定性描述了误判。
2. **一个判断在多处被使用，判错就会连锁。** 核查员的判定同时用在三处：
   - 决定进度：进入下一步还是重试；
   - 以文字理由写进规划器读的历史；
   - 代码再从历史里推出"手里拿着什么"，作为核查员下一次判断的输入。

   论文自己的例子：机器人离垃圾桶还差一点，核查员就判了"已到达"；规划器随即安排抓取，抓取一直失败，直到重试用完。同一个错误事实，同时带偏了进度判断和下一步动作，但论文没有量化这类连锁错误。
3. **判断能用的证据很窄。**
   - 核查员只看当前子任务最近几次尝试的末帧，新子任务的第一次尝试只有当前帧；
   - 规划器只看当前头部图像和文字历史。

   需要更早历史的判断，比如"这罐汽水是不是已经扔过""眼前这个是不是同一个物体"，就没有对应的证据。论文还承认，核查员只按子任务自己的目标来判断：抓起来了但姿态不对，要到下一步放置时才会失败。
4. **评测回避了两个难点。**
   - 任务何时结束由仿真的目标谓词直接判定，智能体不需要自己判断整个任务是否完成；
   - 任务都在已知站点之间移动，不涉及搜索。代码里有一个原地转圈扫描的功能，默认关闭。

   另外，评测规模较小（4 个任务 × 10 次），BEHAVIOR 上的技能权重也没有公开。
5. **核查依赖大量定制提示词。** 代码里 RoboCasa 的规划和核查提示词按任务类别分别编写，每份约 300–1000 行。"通用核查员"的说法要打折扣。

## 我们的出发点

MobiAgent 证明了"判断这一步做完没有"是长程系统的关键环节，但它把这个判断当作可靠的黑盒。我们把它当作研究对象，问三个问题：
- 当规划、进度判断和记忆共享同一份历史时，判断错误是怎样产生的？
- 错误又是怎样传到后续动作和判断的？
- 在有限的上下文预算下，怎样给判断补上对的历史证据？

我们在 BEHAVIOR-1K 上做的找刀实验（LHC 系统）有同样的结构，而且耦合更紧：一次模型调用同时描述画面变化、判断进度、写入记忆，还看得到规划器自己的理由和预期。在线试验里已经自然出现了和 MobiAgent 同类的错误：
- 记忆写下"入口更大更清楚"，实际变大的是沙发；
- 进度被记成"正在接近入口"；
- 规划器接着继续前进。

## 我们能做的改进

下面几项都能用已有的试验记录离线完成，只需要 API 调用，不需要训练，也不需要开仿真。

1. **把连锁错误量化。** 标注已有试验的决策点，统计判断错误里有多少同时带偏了下一步动作。这正是 MobiAgent 只做了定性描述的现象。
2. **检验"判断者该看什么"。** 固定图像和执行结果，只改变判断者能否看到规划器的理由和预期。MobiAgent 的做法（不给理由）正好是其中一组，这个对照可以首次为这类设计选择提供证据。
3. **确认因果。** 只把记忆里的一条错误事实改对，看下一步动作和进度判断是否同时恢复。
4. **按要判断的事补证据。** 在相同的图像额度下，按"当前要判断什么"取回旧证据，比如"上次确认这扇门时的画面""这一罐放进去之前的画面"，再和 MobiAgent 式的"只看最近几次尝试"对比。这一项直接针对它的第 3 个问题。
5. **守住评测边界。** 所有判断都由智能体自己完成，仿真真值只用于离线评分。

**预期贡献**：MobiAgent 说明了核查器很重要；我们要进一步回答，核查器的错误从哪里来、传到哪里，以及怎样用合适的历史证据减少它。同时给出可以复现的测量和干预方法。

如果需要证明结论不依赖我们自己的系统，可以借用 MobiAgent 的 RoboCasa 版本：它的权重已经公开（需申请），规划和核查走 OpenAI 兼容接口，可以换成我们用的模型，在上面复现部分测量。
