# 具身长程任务中的上下文与记忆压缩调研

检索截至 **2026-10-16**。本轮围绕机器人操作、导航和具身决策重新检索，定向核对方法与实验章节，整理 **13 篇具身执行或决策方法、3 篇具身感知与视频记忆参考**。论文版本列在文中，实验数字均为作者报告；本轮没有运行论文代码或复现实验。

**主要判断：具身历史压缩已经有相当直接的研究，任务条件化、动作监督、强化学习摘要、多尺度表示和动态刷新均有具体方法。** 下一轮讨论应重点对照 MeMento、MEM、Memo、NativeMEM、AstraNav-Memory 和 COMPACT-VA。它们比文本多智能体中的角色记忆，更直接约束我们对“具身任务导向压缩”的新颖性判断。

【判断】目前更值得追问的是：**在相同历史访问权与总预算下，压缩对不同下游判断造成什么损失，哪些信息必须保留，什么时候需要重新读取证据。** “规划和完成判断的共同错误”仍可作为候选问题，但需要与已有的决策条件压缩、事实问答保真和停止动作评估具体区分。

## 一 纳入范围

沿用当前讨论中的压缩含义：将历史图像、观测特征、交互记录或任务状态转成更小的表示，供后续决策使用。主要追踪三个环节：**压缩什么 → 压成什么 → 哪项能力依靠它保留下来**。

模型权重量化、动作输出编码、训练数据压缩放在本轮范围之外。单帧视觉剪枝只有在处理历史或有相关具身执行证据时才纳入。

“长程”分别记录为三种：单次任务执行链较长；当前决策依赖早期信息；同一环境中跨任务积累记忆。几秒的驾驶历史、十五分钟的厨房任务和跨天视频检索，使用的压缩机制可以比较，任务规模需要分别理解。

## 三 最影响方向判断的结果

### 按需求压缩已有直接实现

**MeMento 是本轮最需要补入近邻比较的工作。** 它的完整题名是 *Long-Horizon Embodied Decision-Making via Multimodal Memory Compression*。压缩受偏好条件控制，训练包含历史证据相关性与事实问答；评估也包含压缩后问答。因此，“让历史保留决策需要的事实”已经有相当直接的实现。

作者报告决策准确率 52.78%、记忆约 3.8K tokens；事实问答 macro-F1 为 0.719，文字摘要为 0.556。**其 v1 多处引用缺失的 Appendix，训练规模和细节披露不足；主对照也未统一 token 预算。**【判断】方法构成明确的新颖性约束，效果强度仍需谨慎采用。参见 [§5.4–6.2、图5](https://arxiv.org/html/2608.01456v1#S5)。

COMPACT-VA 则把压缩和下游意图预测连接起来。训练时未来轨迹供后验网络学习，部署时先验网络仅用已观测历史预测意图。【判断】“通过任务目标决定压缩保留什么”已经覆盖到具体物理决策，后续需要提出更具体的需求冲突或信息损失问题。参见 [§III-C](https://arxiv.org/html/2606.07464v3)。

### 真实长程操作已经采用语义压缩

MEM 的长期摘要保留仍与后续任务有关的事件，允许把逐件物体描述合并为数量与位置；训练标签由子任务标注及成功失败信息辅助生成。它还有语言记忆与短期视觉记忆的消融，并完成真实长程操作。

【判断】“短期保细节、长期保语义”和“按剩余任务压缩进度”应作为已有设计。它留下的具体问题是：何时合并对象仍保留后续决策所需的身份与关系，以及生成的摘要能否支持额外核验。相关证据见 [MEM §III-B、§IV-A、图5](https://arxiv.org/html/2603.03596v2)。

### 压缩训练目标有实际影响

NativeMEM 的消融中，跳过第一阶段、用平均池化视觉特征作记忆，仿真均分为 **58.0**；完整方法为 **84.0**。这支持动作监督下学习压缩表示的价值。主要对照还涉及任务微调与作者重实现的基线，采用其跨方法大幅领先数字时要保留这个条件。参见 [表1、表3及§4.1、§4.4](https://arxiv.org/html/2607.06678v1)。

Memo 将每 **256 步**压为 **32 个摘要 token**，直接用 RL 任务奖励训练；与全上下文 Transformer 对照并研究摘要累积、梯度传播和流式截断。【判断】“压缩只需优化下游任务表现”也已有端到端路线。默认摘要随段数累积，固定容量运行另有流式设置。参见 [Memo §3.2、§4.3–4.6](https://arxiv.org/html/2510.19732v2)。

### 压缩率和任务质量存在可见的折中

下列数字更适合用于判断机制，几篇的指标与任务各不相同。

| 工作与具体对照 | 作者结果 | 应据此关注什么 |
| --- | --- | --- |
| AstraNav，GOAT-Bench 未见场景子集，100 图历史 | 4× 压缩 **63.2**；16× **57.5**；64× **49.1**。50 图不压缩为 **60.2** | 多看历史与保留单图细节之间有折中；压缩倍率需要与历史长度一起比较。v1 表4 |

另外，AstraNav 保留压缩前的 DINO 特征所需显存仍限制可处理图像数。**输入 token 降低、缓存变小、整系统显存降低和端到端加速，应分别报告。** ContextVLA、HAMLET 的效率表也分别涉及缓存复用和特定显存统计口径，横向比较时需要对齐。参见 [AstraNav 表3–4](https://arxiv.org/html/2512.21627v1)、[ContextVLA 表5](https://arxiv.org/html/2510.04246v1)、[HAMLET 表4](https://arxiv.org/html/2510.00695v3)。

### 行动与停止会受到不同影响

History-Conditioned Pruning 在 R2R 的结果尤其值得注意：

| 设置 | 途中到达过目标区域 OS | 在目标处正确停止 SR |
| --- | --- | --- |
| 不剪枝 | 63.60% | 55.74% |
| 剪除 90% 视觉 token | 68.46% | 47.63% |

作者在 §IV-B 讨论了这一区别。**【判断】这给“压缩需要同时保住行动与完成判断”提供了具体切入点。** 当前结果涉及同一个导航策略的到达与停止，规划器和独立验证器的共同误判机制仍需单独研究。压缩也改变了执行路径，因此后续应对齐判定点再分析究竟丢了什么信息。参见 [v3 表I、§IV-B](https://arxiv.org/html/2603.06480v3)。

## 四 三篇相邻但证据类型不同的研究

### StreamMeCo

完整题名为 *StreamMeCo: Long-Term Agent Memory Compression for Efficient Streaming Video Understanding*，ACL 2026 Findings。它压缩多模态记忆图中的文本节点：孤立节点做聚类和多样性采样，连接节点结合实体重要性剪枝，再增加时间衰减检索。

M3-Bench-robot 使用机器人视角视频，评估结果是视频记忆问答。表1中，三数据集均分由原系统 **44.7**，经删除70%文本节点降至 **41.2**，加 TMR 检索后升至 **45.7**。**【判断】收益依赖压缩与检索的组合；若用于我们的基线，应分别消融两部分。** 该实验的具身证据范围是观察与问答。参见 [§4–5、表1](https://aclanthology.org/2026.findings-acl.647.pdf)。

### LTE

*Linguistic Trajectory Encoding for Efficient Long-Horizon Spatial Memory in Embodied Agents*，[arXiv 2609.04802v3](https://arxiv.org/html/2609.04802v3)。把物体运动历史压成文字描述、稀疏三维位置和视觉锚点，以 Ego4D、EgoLife 的查询与检索任务评估。

**8.7×–26.1× 是 LTE 轨迹表示相对逐帧轨迹存储的压缩率**，系统还包含其他视图与索引。失去追踪时记录最后观察位置，身份错误会影响后续查询。【判断】适合研究对象级事实和证据锚点的压缩，行动收益还需接入执行任务。参见 §3.3–3.5、表4。

### Chimera

*Compressing History into Memory: Distilling Transformers into Recurrent Transformers*，[arXiv 2606.21562v2](https://arxiv.org/html/2606.21562v2)。教师先把已观察历史压成显式瓶颈，再用中间表示监督固定容量循环记忆；压缩时不读取后续查询。

主要验证是 Mem-RPE 相对位姿估计，另有流式视频问答。**【判断】它提供“用全历史教师教会在线压缩”的训练路线；适用证据集中在记忆读取与感知任务。** 对我们有价值的问题是：压缩时未知未来问题，如何保留可被不同查询使用的事实。参见 §3–5、表1。

## 五 对当前研究问题的影响

以下为基于本轮文献的研究判断。

**第一，主要近邻文献需要更新。** MeMento 已有需求条件压缩与事实问答保真，MEM 已有真实长程任务中的语义压缩，Memo 已有奖励驱动摘要，NativeMEM 已有动作监督压缩，COMPACT-VA 已有决策对齐。这些应进入问题定义和方法对照。LatentMem、RCR 继续用于多角色记忆比较。

**第二，“同时保住多种能力”比“按角色做压缩”更值得展开。** 可以具体比较：同一历史中的哪些事实影响下一步行动，哪些影响最终验收；信息需求一致时共享表示是否足够，冲突时怎样分配预算。MeMento 的问答探针和导航论文的 OS/SR 分离已经覆盖部分评估思路，我们需要进一步建立同一证据、同一判定点上的错误联系。

**第三，压缩后的更新和恢复仍可作为另一条主线。** SD-VLA 已实现缓存刷新，MEM 已实现摘要更新。更具体的研究问题可以是：新观察到来后，哪些旧结论必须撤销；压缩丢掉的身份或时序关系，是否值得付出重读、重新观察或返工代价来恢复。这需要再补专门的更新与恢复文献检索，本轮不据此宣称空白。

**第四，实验选择应对应研究层级。** 面向高层规划与核验，先考虑 MeMento、MEM 的摘要机制和简单状态表加检索；面向 VLA 内部表示，再考虑 NativeMEM、HAMLET、ReMem-VLA；面向导航历史效率，则已有 Uni-NaVid、StreamVLN、AstraNav 和剪枝方法作为直接对照。迁移时需分别对齐可见证据、训练监督、输入接口和总开销。

## 六 优先阅读顺序

1. **MeMento**：确认与“按当前需求压缩，并保留判定事实”的重叠，尤其读 §5.4 和 §6.2；同时看 v1 缺失的实验细节。
2. **MEM**：看真实长程操作中具体保留什么、如何删除和合并语义信息，重点 §III-B、§IV-A。
3. **Memo**：看任务奖励怎样训练摘要、摘要累积怎样影响长期信息利用，重点 §3.2、§4.4–4.6。
4. **NativeMEM**：看动作监督和简单视觉池化的差别，重点 §3.2、表3。
5. **AstraNav-Memory**：看压缩率与历史长度的二维折中，重点表3–4。
6. **COMPACT-VA**：看决策意图如何进入压缩训练，以及同预算对照和闭环证据的范围，重点 §III-C、表I–III。
