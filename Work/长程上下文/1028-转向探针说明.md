## 一、决策点

**选点规则**：选环视之后的第一个规划决策，并且同时满足三条：
- 当前图是环视图：至少 4 张，带 scan_heading_degrees；
- Task 里 G1 已满足，并引用了其中的环视图；
- G2 尚未满足。

**判对规则**：
- rotate_base：转后的朝向和 G1 引用的任一环视朝向相差不超过 36°，即环视间隔 72° 的一半，算转对；
- move_to_point：evidence_ref 指向 G1 引用的环视图，算转对；
- 其他工具单列。

## 二、四种改法

|  | 原朝向 | 原朝向 + 相对转角 |
|---|---|---|
| **全量输入** | A：原样 | C |
| **删减输入** | B | D |

**删减**（B、D）：输入 JSON 只留这一步需要的部分。
- 保留：
  - schema_version、goal、task_context、task_sequence、current_subgoal；
  - memory.task，G1、G2 原样；
  - available_tools；
  - current 里只留 observation_id，以及每张环视图的 ref、camera、scan_heading_degrees；
  - 环视图本身和它们的说明文字。
- 删掉：
  - 其余顶层字段：before 及其图片、recent_tools、execution_history_summary、spatial_memory、memory.object、memory.spatial、last_search_plan、evidence_groups 等；
  - 环视图条目里的位姿、内参、哈希等。
- 按 0015、0034 和 THOR 的两个点估算，删完约剩原来的 13～17%。
- 四组的系统提示都不变。

**相对转角**（C、D）：在每张环视图的说明文字末尾加一句。
- 例如："relative to the current heading: −72.5° (72.5° to the right; left positive)"。
- 数值是这张图的实测朝向减去 head_000 的实测朝向（环视结束后机器人回到这个朝向），换算到 (−180°, 180°]，正为向左。
- JSON 不改，只加这一句，不加其他提示。

**规则**：
- 每个点、每种改法问 3 次。以前的原样请求重复问时都一致，所以 3 次够用。模型、参数、提示词、解析代码都和在线一致。
- 只改上面列出的部分，其余字节不变。每个改后的请求都存档，记哈希。
- 加进去的只能是在线就有的信息。相对转角来自机器人自己的实测朝向，不用评估端真值。
- 校验照常跑。被拒的回答也记下工具和角度，另列。
