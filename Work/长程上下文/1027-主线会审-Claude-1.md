# 1027 会审：Claude 的方案

**用途**：按"先独立、后对比"，第一轮不发给 GPT 和 Gemini；拿到它们的独立答案以后再一起比较。

**背景和数据**：见 `1027-主线会审-问题.md`。1027 改版：问题改为"上下文对决策值多少、价值从哪来、我们生成的记忆兑现了多少"。原先关于"选哪个主机制"的方案作废，其中误报完成的分析留作数据。

## 一、问法

**适合作为现阶段的问题。**
- 它包住了原来的缺陷问题：缺陷就是价值丢在哪一步。
- 它直接回应用户的两个疑问：任务需要什么上下文；生成的记忆值多少。
- 它和长期问题的三问一一对应：该留下什么（写），怎样送给当前决策（送），什么时候该重看、不该信记忆（用）。

**最大的弱点**："值多少"取决于任务，很容易做成一篇测了一堆数、却说不出规律的测量文章。必须量出一个说得清的规律，例如：
- 重看越贵，记忆的净值越高，过了某个代价才转正；
- 价值主要丢在送和用，不在写。

**已有工作**：检索增强的研究里常比"直接给标准答案段落"和"给检索到的段落"；具身工作里常有"给真值地图"的上限和逐个模块的消融。但它们大多只看整轮成功率，不看单个决策，也不控制重看的代价。具体要查文献。

## 二、怎么量

**同一个决策点，换三种上下文**：

| 上下文 | 怎么来 |
|---|---|
| 无记忆 | 只给当前观测和任务目标 |
| 我们生成的记忆 | 现在的系统 |
| 参考记忆 | 只用我们的感知已经给出的东西：判断模块的结果和 Object 原本的观察。每条结论带上来自哪张图、目标多大、离多远、确认没有；该送的都送到 |

- 参考记忆比无记忆好多少：这个任务需要多少上下文。
- 我们的记忆比无记忆好多少：我们生成的记忆实际值多少。
- 参考记忆比我们的好多少：粗糙的生成丢了多少，再拆成写、送、用三步。
- 在参考记忆里逐条去掉记录，看去掉哪条决策就变：哪些记忆有价值。

**单位和指标**：
- 先在决策点上离线量，几秒一次。指标是决策变没变、变得好不好；"好不好"用评估端的几何估计，比如离目标的远近、下一张图里目标会不会入画，只用来打分。
- 只对差距最大的情形做闭环：reset 加脚本前缀分叉，看整轮成功率和所用决策数。

**感知固定**：参考记忆不重新认图，不用更强的模型看图；仿真真值只用于打分。

## 三、用什么任务

**把"重看的代价"做成变量。** 脚本前缀让机器人看清 X，再把它带到不同的位置，再看见 X 要花的代价分三档：
- 转身就能看到；
- 要走几米或绕过遮挡；
- 要换房间。

**平台**：
- THOR 更合适：导航按可达网格，ProcTHOR 有多房间户型。穿门要先验证。
- 每档几个场景，同一前缀重复几次。
- BEHAVIOR 只做"代价小"那一端，作复现。

## 四、怎样推广

1. 结论写在写、送、用三个环节上，四个库只是一种实现。
2. 参考记忆本身和设计无关，可以当共同的尺子。
3. 加一个常见设计做对照："一条历史记录"或"滚动摘要"。离线按同样的观测序列重写，在同样的决策点比较。
4. 关掉部分库，近似只用一两个库的工作。

按项目规矩，加"一条历史记录"要先讨论。我认为把它当对照、不替换四个库，可以。

## 五、第一步（约一周）

1. 损失账和离线探针做完（已在跑）。
2. 在现有决策点上试做三档比较：条件变化和延迟回访的首次自由规划。预计"参考记忆比无记忆好多少"接近 0，因为现在的任务不需要记忆；这一步主要验证量法能不能做。
3. THOR 上搭重看代价的任务原型：2–3 个户型、三档代价，只跑脚本前缀和少量冒烟，不跑正式轮次。

**放弃条件**：
- 在重看很贵的任务里，参考记忆也不比无记忆强。说明对这个规划器来说上下文本来就不值钱，问法要改成"为什么规划器用不上好的记忆"。
- 参考记忆不靠更强的感知就造不出来，和"感知固定"冲突。

## 六、最该先核实的

- **条件变化的分界**：5 轮里"有板状物记录就走近、没有就 observe"，可能是巧合。每次 reset 后判断模块的远图判定和 Object 的记录都有微小变化，规划器的选择也可能受别的字段影响。离线探针会直接检验。
- **"无历史 4/4 对"**：样本小，而且只拿掉了规划器能看到的部分。它可能只说明任务太容易，不能推广成"记忆没用"。

## 七、风险

参考记忆的造法，接近 1022 提过的"带观测条件的记忆"。要守住它只当尺子，不提前变成方法。
