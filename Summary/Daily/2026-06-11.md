# FeatSched motivation

- 推进 M2 PTS contention 实验和分析闭环。
  - 当前 `results/m2_contention_plan/` 下已经有 Apache、Nginx、C-Ray 三组 foreground workload 的 bg_cpu10 contention runs。
  - 每组都覆盖 6 个 policy：
    `baseline`、`batch_manual`、`affinity_compact_manual`、`affinity_spread_manual`、`fifo_manual_later`、`rr_manual_later`。
  - 补齐并检查了 Nginx FIFO 的 background summary，后续 tradeoff 表已经能覆盖 18 个 run。
  - C-Ray 单轮执行时间明显长于 Apache/Nginx，确认 background timeout 需要按 workload 校准，不能简单依赖 stress-ng 默认 10 分钟。

- 统一 M2 policy 命名和 policy family。
  - 在 `configs/policies.yaml` 中增加 `display_name` 和 `policy_family`。
  - 将 `baseline` 标为 `default` family。
  - 将 `batch_manual`、`affinity_compact_manual`、`affinity_spread_manual` 标为 `non_rt` family。
  - 将 `fifo_manual_later`、`rr_manual_later` 标为 `rt` family。
  - 在 `configs/pts_contention_matrix.yaml` 和 `docs/pts_runbook.md` 中明确 FIFO/RR 是 aggressive RT-style policies，需要在图表和论文叙述中单独解释。

- 改进 M2 run-level dataset 和 policy matrix。
  - `analysis/build_run_level_dataset.py` 现在保留 `background` 字段，支持 foreground/background 组合分析。
  - `analysis/m2_policy_matrix.py` 改成读取 run-level paired dataset。
  - 支持选择 metric，默认优先 `pts_score`。
  - normalized score 和 regret 都尊重 `higher_is_better`。
  - 对 C-Ray 这类 lower-is-better 的 PTS score 做了正确处理。
  - 输出：
    - `tables/m2/objective_table.csv`
    - `tables/m2/normalized_scores.csv`
    - `tables/m2/oracle_policy.csv`
    - `tables/m2/policy_regret.csv`
    - `figures/m2/policy_heatmap.{pdf,png,svg}`
    - `figures/m2/policy_regret.{pdf,png,svg}`

- 新增 PTS raw sample 抽取。
  - 新增 `analysis/extract_pts_raw_values.py`。
  - 从每个 paired run 的 `benchmark/pts_result.json` 和 `benchmark/run_meta.json` 中抽取 raw values 与 test run times。
  - 输出 `tables/m2/pts_raw_samples.csv`。
  - 如果 PTS JSON 中没有 raw values，会 warning 并跳过，不改原始结果。
  - 增加 Apache/Nginx 风格 fixture 测试。

- 新增 foreground-background tradeoff 分析。
  - 新增 `analysis/build_m2_tradeoff_table.py`。
  - 新增 `analysis/plot_m2_tradeoff.py`。
  - 读取每个 run 的 foreground `run_summary.csv`、background `background_summary.csv` 和 collector `run_feature_summary.csv`。
  - 输出：
    - `tables/m2/foreground_background_tradeoff.csv`
    - `figures/m2/foreground_background_tradeoff.pdf`
    - `figures/m2/foreground_background_tradeoff.png`
  - 图中 x 轴表示 foreground normalized score，y 轴表示 background progress per foreground active second。
  - 对 background runtime 明显长于 foreground active time 的点加 warning marker。
  - 该图用于观察 foreground 提升是否伴随 background progress 下降。

  - 表中额外保留 `metric_value` 和 `normalized_score`。
  - 输出：
    - `tables/m2/feature_explanation_table.csv`
    - `figures/m2/feature_explanation_heatmap.pdf`

- 当前初步观察。
  - 在 bg_cpu10 contention 下，不同 policy 在 Apache、Nginx、C-Ray 上确实表现出 workload-dependent 差异。
  - FIFO/RR 这类 RT-style policy 可能给 foreground 带来提升，但需要结合 background progress 一起解释，不能只看 foreground score。
  - affinity compact/spread 的效果依赖本机 CPU 拓扑和 background 干扰方式，需要在论文中作为 static policy mismatch 的例子，而不是默认最优策略。
  - feature heatmap 只能说明 active-window feature 与 policy outcome 的关联，不能作为因果证明。
